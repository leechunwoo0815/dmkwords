# error_list — 错误记忆库（防复发机制）

## 这是什么

从 librio 项目全部审查/复审/修复报告中提取的**所有大模型（含历任开发模型、审查模型、
交接者）犯过的错误**，按根因模式聚类，固化为一套"动手前自查 + 动手后验证"的防错机制。
不是错误清单归档，而是**下次不再犯同样错误的操作手册**。

## 目录内容

| 文件 | 说明 |
|---|---|
| `错误记忆库-全项目-YYYYMMDD.md` | 主记忆库（根因模式库 + 防复发动作 + 正反案例 + 引用锚点） |
| 后续版本 | 按周期追加：`错误记忆库-全项目-YYYYMMDD.md`（新版本独立成文，不覆盖旧版） |

## 周期性重做流程（建议每轮大审查后执行）

1. **收集**：把本轮新增的审查报告/复审记录/修复报告加入待分析清单。
2. **提取**：逐份标注"开发方错误"条目（五要素：事实 / 被抓方式 / 根因 / 修复 / 是否复发）。
3. **聚类**：对照主记忆库根因模式库——命中既有模式的标"复发"（重点！），新模式的扩类。
4. **更新**：新版本主记忆库（或增量补录），只增不改历史（保留完整演进史）。
5. **自测**：随机抽 3 条新错误，验证"读 §三 检查清单 → 定位根因类 → 对应防复发动作
   能否拦住当时的自己"。
6. **广播**：更新 K3 交接文档 §五 指针，确保恢复口令路径能摸到最新版。

## 使用要求（强制）

- **新任务开工前**：读主记忆库 §三（一页检查清单），对照当前任务命中哪些防复发项。
- **修复进行中**：凡修"一类 bug"，先 `rg` 全库枚举同类调用点/入口，逐个核对。
- **声称完成前**：门禁命令全量复制不缩范围；MySQL-only 检查不标"没法跑"跳过；
  报告必须附五项回归原始输出 + 自检闭环验证表。
- **发现新错误**：当场按第 2 步五要素记录，下个周期并入记忆库（或立即追加补录）。

## 与交接文档的关系

K3 交接文档 §五"陷阱清单"是记忆库的**速查摘要**；记忆库是**完整版（含根因与案例）**。
两者指针互链，恢复口令路径必须同时摸到。
