## 一、本轮新增错误

### E-20260829-01 select().scalar_one_or_none() 单列返回标量而非 Row
- 事实：`_on_quiz_passed` 事件订阅器对 `row[0]` 取父 ID，抛 `TypeError: 'int' object is not subscriptable`，
  导致既有 wm7 测验测试 500。
- 被抓方式：全量回归 7 个既有测试失败；traceback 指向 notifications.py:237。
- 根因：SQLAlchemy 2.0 单列 `select(Child.parent_id).scalar_one_or_none()` 返回标量（int），
  多列才返回 Row——`row[0]` 想当然照搬多列写法。
- 修复：`parent_id = row`（None 已被前置保护）。
- **复发风险：中**（SQLAlchemy 1.x→2.0 心智残留）。
- 防复发：**单列 select 用 scalar_one_or_none 直接取值，不要 [0]；多列才用 row[i]；
  写事件 handler 后必跑一条真实链路测试**。

### E-20260829-02 Session 工厂 vs 会话实例混淆（get_session() 不可再 call）
- 事实：`run_task` 里 `get_session()()` 报 `'Session' object is not callable`，
  全部 12 项任务执行失败。
- 被抓方式：新测试 14 失败，首错即 TypeError。
- 根因：`backend.database.get_session()` 已返回 SessionLocal() 实例（不是 sessionmaker），
  误当工厂再调用一次。旧代码（events.py 独立 session 分支）用 `get_session()()` 是因当时 API 不同。
- 修复：`session = get_session()`。
- **复发风险：低**（调用点少，但 API 易混）。
- 防复发：**用前先读 backend/database.py 的 get_session 签名（返回实例）；不再 call 一次**。

### E-20260829-03 任务方法与测试共用"过去时间"却忘了域校验
- 事实：activity_auto_finish 测试用过去 start_at 创建活动，但 ActivityService.create 校验
  "开始时间必须在未来"（422），测试用 `act2 = client.post(...).json()` 拿到 detail 而非 id，
  后续断言静默 0。
- 被抓方式：测试断言 `processed == 0`；定位到活动根本没建成。
- 根因：造"历史活动"走了业务创建 API（禁过去时间），未走直改库。
- 修复：改为直改库 add Activity（start_at=过去）。
- **复发风险：中**（"造过期/历史数据"场景）。
- 防复发：**造"过去/未来边界"数据优先直改库；业务 API 有域校验时看状态码，别吞 422**。

### E-20260829-04 alembic check 报 remove_table / modify_comment（模型↔迁移双失配）
- 事实：门禁 step5 alembic check 报"remove 三张新表"（env.py 未 import 新模型）；
  补 import 后又报整表 modify_comment（迁移列无 comment，模型列有）。
- 被抓方式：门禁 step5 FAIL。
- 根因：①新域/横切模型必须追加进 alembic/env.py 的模型 import 列表，否则 metadata 不知道
  新表 → alembic 认为"多余"建议删；②迁移列定义与模型列 comment 不一致 → check 报差异。
- 修复：env.py 追加 import；迁移列全部补 comment。
- **复发风险：高**（每加一张表都要同步两处）。
- 防复发：**新建模型后：①env.py 追加 import ②迁移列与模型列完全一致（含 comment）；
  跑 `alembic check` 到"No new upgrade operations detected"再进门禁**。

### E-20260829-05 common 层函数内 import 业务域也被架构关拦截
- 事实：架构关报"common 依赖了业务域"——common/notifications.py 的 handler 在函数内
  import Child/Parent/Book。
- 被抓方式：门禁 step3 架构关 FAIL。
- 根因：verify_architecture 递归扫描 common 下所有 py 的 import（含函数内），
  不只看模块级。
- 修复：handler 移到 backend/tasks/notify_handlers.py（编排层，允许依赖域）。
- **复发风险：高**（图省事在 common 写查询的诱惑）。
- 防复发：**common 任何 py 禁止出现业务域 import（含函数内）；需要查业务域的逻辑
  放 tasks/ 或对应域**。

### E-20260829-06 flush 撞唯一索引后 rollback() 连坐主事务；savepoint 也救不回
- 事实（外部审查 P0）：notifications.send 撞唯一索引后 `self.db.rollback()`——
  EventBus 同步共享事务下撤销了主业务未 commit 的写入（订单 paid 等）。
- 被抓方式：外部审查读代码发现；自测永远测不到（串行 count 先命中查重）。
- 根因：①`db.rollback()` 是全事务回滚，共享 session 下连坐发布方写入；
  ②尝试 `begin_nested()` savepoint 隔离，但 SQLAlchemy **flush 抛异常后 session
  强制 PendingRollback**（"first issue Session.rollback()"），savepoint 回滚无法
  恢复 session——方案不可行。
- 修复：改用 **MySQL `INSERT IGNORE`**（`mysql_insert(...).prefix_with("IGNORE")`，
  宪法 MySQL-only）——撞唯一约束静默忽略 rowcount=0，零异常、零 ORM flush、
  不污染事务，主事务无感；微信状态回写用 Core `update()` 不碰 ORM 对象。
- **复发风险：高**（"并发幂等写"是高频需求）。
- 防复发：**在共享事务里做"撞唯一约束也要优雅"的写入 → 用 INSERT IGNORE /
  ON DUPLICATE KEY，不用 flush+except IntegrityError+rollback；涉及"主事务不可
  回滚"的写入一律先想清楚事务边界**。

## 一B、手动验收期新坑（2026-08-29 追加，E-07~E-12）

### E-20260829-07 WXML 不支持字符串下标，分包编译失败连坐整包导航
- 事实：quiz.wxml 写 `{{index < 6 ? 'ABCD'[index] : ''}}` → reading-pkg 分包编译失败 →
  **整个分包所有页面导航挂死**（测验入口点击无任何反应）。
- 被抓方式：用户实测"点测验没反应"；pytest 全绿、纯静态检查发现不了——
  只有微信开发者工具 GUI Console / 官方 wechatide mcp compile_wxml 报错可见。
- 根因：WXML 表达式引擎不支持字符串下标运算（`'ABCD'[i]`），支持数组字面量下标。
- 修复：改 `{{['A', 'B', 'C', 'D'][index] || ''}}`。
- **复发风险：高**（JS 习惯直接搬进 WXML）。
- 防复发：**WXML 内禁止字符串运算/方法调用这类 JS 语义；"小程序整包导航挂死"先查
  分包编译（scripts/wechat_ide_mcp.py compile_wxml 或工具 GUI Console）再查业务代码**。

### E-20260829-08 唯一索引不含 is_deleted，软删行挡住重新 INSERT
- 事实：生词删除后再查同一词 → lookup 500；`uq_vocab_child_word` 唯一索引不含
  is_deleted，软删行（is_deleted=1）仍占用索引，重新 INSERT 撞冲突。
- 被抓方式：用户实测"查词 500，查别的词又好"。
- 根因：索引设计与 orders.uq_order_no 的"软删可重建"先例不一致（漏 is_deleted 列）。
- 修复：**复活语义**——查询不过滤 is_deleted，命中软删行置 0 复活（book_id 顺手回填）；
  加"删除→复活"回归测试。
- **复发风险：高**（软删 + 唯一索引组合高频）。
- 防复发：**新表唯一索引一律含 is_deleted；既有"软删+唯一索引"组合的重插路径必须有
  复活语义或物理删除，二选一并配回归测试**。

### E-20260829-09 pytest 清库三层涟漪（词库/演示数据/旧 JWT）误判为功能故障
- 事实：跑一次全量 pytest 后——①dictionary_words 被清 → 查词 404/500；
  ②演示数据（家长/孩子/押金）被清 → 预约/借阅不可测；③模拟器里旧 JWT 签发的
  parent_id 已不存在 →"孩子不存在"报错。三层叠加让用户以为功能全坏。
- 被抓方式：用户连续报"查词用不了/无法预约"，与代码缺陷交织，定位成本高。
- 根因：conftest ADMIN_TABLES 全库 TRUNCATE + 无恢复流程；JWT 无版本校验。
- 修复：①conftest 排除 dictionary_words（340 万词库是基础数据，清了要重导 8 分钟）；
  ②固化恢复三步：`python -m scripts.seed_wm11_demo` →（旧版清过词库时）
  `python -m scripts.import_ecdict` → **模拟器退出重登**。
- **复发风险：高**（每次跑 pytest 都触发）。
- 防复发：**跑完 pytest 必走三步恢复；排查"孩子不存在/查词 404"先确认 token 是否
  旧库签发（退出重登），再查代码**。

### E-20260829-10 .env 相对路径写入落错文件（目录态残留）

- 修复：确认 admin-web/.env 136 字节纯为本轮误写后整文件删除，改写根 .env。
- **复发风险：中**（长会话 cwd 漂移）。
- 防复发：**写环境变量/配置一律绝对路径；写完 cat 确认落点与内容**（口径类错误，
  同"脚本改文档必须断言+grep 验证"E-10/20260828）。

### E-20260829-11 微信开发者工具自动化通道全面失效，唯官方 wechatide mcp 可用

  （一次误触编辑器向 member.js 输入脏文本，即时 Cmd+Z 撤销并验证磁盘干净）。

- 根因：Nightly 废弃 auto-port 注入；GUI 坐标点击对 IDE 布局/缩放脆弱。

  weixin-devtools-mcp（npx）可作二轨备用**。

### E-20260829-12 execute 裸 SQL 未包 text()（E-01 同族）
