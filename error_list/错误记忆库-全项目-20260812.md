## 一、本轮新增错误（LOOP-2~6 六类种子 + 审计期新增）

### E-20260812-01 台账 evidence 引用虚构文件名（时间戳不匹配）
- 事实：LOOP-3 台账 10 处 evidence 引用 gate-runs 文件名带 `end=` 时间戳（如
  20260811-113554），实际文件为 `start=`（20260811-113538）——引用不可解析，
  `loop_check` 判 FAIL。另 L3-037 原本无 evidence 文件。
- 被抓方式：终审专家独立 `test -f` 逐条验证 41 处 evidence 引用，10 处 MISSING。
- 根因：写台账时凭记忆填 evidence 文件名，未用 `test -f`/`ls` 验证文件真实存在。
- 修复：10 处改真实文件名（test -f 全通过）+ L3-037 补 evidence.txt。
- **复发风险：高**（台账 evidence 是手工填写的自由文本）。
- 防复发：**凡在台账填 evidence 必须 `test -f` 验证文件真实存在**；evidence 文件名
  用 gate-runs 实际 start 时间戳。

### E-20260812-02 loop_check.py 只校验 loop2 台账的误用
- 事实：声称"loop_check full PASS 证明 LOOP-3 闭环"——实际 loop_check.py 硬编码
  `LOOP_DIR=loop2`，**从不读 loop3/LEDGER.md**。L3 的 44 项无机械校验。
- 被抓方式：专家查 loop_check.py 源码（LOOP_DIR 常量）+ 台账对账。
- 根因：把"机制运行成功"误当作"目标闭环"，未核实机制实际覆盖范围。
- 修复：以 `test -f` evidence + gate 日志人工核对 L3；机制扩展留待后续。
- **复发风险：中**（机制外置缺失仍在）。
- 防复发：**声称"X 闭环"前，先核实声称依赖的机制实际覆盖 X**；loop_check 只证明
  loop2。

## 五、LOOP-11 真机验证增量（20260812 晚）

### E-20260812-09 WXML 属性值双引号嵌套 + 无效组件属性（真机编译才暴露）
- 事实：`icon="<text class="icon icon-dizzy-face">😵</text>"`——属性值双引号包裹、内部又未转义
  双引号 → WXML 编译报 `unexpected character`；且 error-view 组件**无 icon property**（图标由 type
  决定），传该属性纯冗余 + 触发语法错误。全库 **14 处**同类（模式 1），历史遗留（V3.10），
  **node --check 查不出 WXML 语法**，只有微信开发者工具真机编译暴露。
- 被抓方式：微信开发者工具真机编译 books.wxml（image-analyzer 识图报错截图确认）。
- 根因：WXML 属性值内嵌 `<标签>` 时用双引号包裹 + 内部未转义；给组件传属性前未核对组件 properties。
- 修复：error-view 删 icon 属性（11 处）+ empty-state 改单引号 `icon='<text ...>'`（5 处，属性合法保留功能）；
  全库 14 文件 + 同类扫描 `="<` 清零；真机验证 7 页编译全 OK（L11-001）。
- **复发风险：中**（WXML 语法无静态检查工具）。
- 防复发：① WXML 属性值内嵌 `<标签>` 必须单引号包裹或 `&lt;` 转义，禁双引号嵌套；
  ② 给组件传属性先核对组件 properties（无效属性 = 冗余 + 潜在语法错）；
  ③ WXML/组件改动靠微信开发者工具真机编译验证，不依赖 node --check。
