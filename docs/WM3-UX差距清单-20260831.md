## 二、差距清单（按优先级）

### P1 — 功能链路/可用性缺陷（3 项）

| # | 项 | 现状 | 基线依据 | 修法建议 |
|---|---|---|---|---|
| W1 | **"为孩子建档"家长 ID 链路断裂** | Modal 要求手输"所属家长ID"数字（L428-429），但 UI 无处可查家长 ID：孩子列表只显示姓名/手机号；新建家长成功提示也不返回 ID。验收表步骤 1→3 实际走不通，馆员只能瞎猜 | 用户 UX 标准（非技术用户） | 家长字段改 Select 远程搜索（输手机号/姓名搜）；新建家长成功提示中带出 ID 并提供"为此家长建档"快捷入口 |
| W2 | **取消订单无错误处理** | L362 `await apiCancelOrder` 无 try/catch：已支付订单后端正确 422，但前端静默吞错，用户无感知、列表不刷新 | U2 | 包 try/catch + message.error，对照同文件其他按钮写法 |
| W3 | **无"待确认收款"运营待办入口** | 馆员每天的核心待办（待人工确认的订单）需手动开下拉选状态筛选；Tab 计数只有两个总量 | U11（对照 WM2 C3 七键/馆员巡库思维） | 订单 Tab 增加状态子计数（至少"待确认 N 笔"），或列表页顶部待办卡 |
