## 6. 本项目血泪教训（新会话开工前必读，防复发）

1. **僵尸进程假绿**：手动起的 uvicorn 占住 8002，dev.sh 健康检查打到旧进程假装 OK → 新代码全 404。已加端口防呆；再遇"接口 not found"先 `lsof -ti :8002` 对 pid 文件
2. **补丁脚本部分写入**：用 python 脚本改文件时断言失败会中途退出，前几处已写入后几处丢失（WM6 音频端点因此丢失两天才在自审中发现）。**教训：脚本改完必须 grep 验证落盘 + 跑导入**
3. **ruff format 会改锚点**：先跑过 format 的文件，补丁脚本的字符串锚点可能不匹配——匹配失败时先 `sed -n` 看实际格式，不要盲试
4. **bash 变量紧邻全角字符**（如 `$pid（`）会被吞进变量名，`set -u` 下崩溃；用 `${pid}` 花括号
5. **WXML 不支持 Math/复杂表达式**：计算放 JS，WXML 只渲染
6. **alembic 非 MySQL 事务 DDL**：downgrade 中途失败留残余表，重升前手工 DROP + 改 version_num
7. **工作区陷阱**：若会话不在 dmkwords 目录打开，Edit 工具会被拒（"restricted to working directory"）被迫走脚本写文件（教训 2 的温床）。新会话必须直接在 `/Users/litianyu/cc-projects/dmkwords` 打开
8. **测试夹具**：哑 MP3 解析不出时长，需改库设 `audio_duration_seconds`；防刷测试用 `_backdate` 把 `last_report_at` 拨回过去模拟时间流逝
