## 二、融合原则

1. **图形在上、数字在下**：第一屏就给出视觉冲击（图表区），运营数字卡片与待办继续留在下方（同事办公仍可用）。
2. **不改后端、不动契约**：全部图形用既有 `GET /api/admin/dashboard` 字段渲染
   （`copy_available/borrowed/maintenance/lost`、`today_borrowed/returned`、`overdue_active`、
   `renew_rate`、`quiz_pass_rate`、`withdrawal_rate`、`member_total`、`milestone_count` 等）。
3. **零新依赖**：手写 SVG + CSS 动画 + paint 令牌（现状 admin-web 无任何图表库；
   绘本风要自己控色控形，通用库默认皮肤"不像我们"；电视机常年开机也省内存与重绘）。
4. **投屏可读性**：环宽 ≥ 14px、中心数字 ≥ 22px、柱宽 ≥ 58px、标签 ≥ 13px；断网保留上一帧数据。

## 三、已实现（2026-09-21 第一版，`admin-web/src/components/DashboardCharts.tsx`）

| # | 图 | 形态 | 数据 |

## 五、红线

- **R1（性能预算）**：单页 DOM < 400 节点、无逐帧重绘、单次刷新请求 ≤ 1。
- **R2（视觉同源）**：颜色/字号/圆角只用 paint 令牌（docs/15）；允许仪表盘用比其它页更强的对比与更大的字号。
- **R3（数字不撒谎）**：任何"看似有一点值"的图形表现都要与真值一致（0 就是 0，本轮已按此修）。
- **R4（投屏可用）**：断网/接口失败保留上一帧、不弹错误框（投屏无人交互，弹窗会一直挂在电视上）。
