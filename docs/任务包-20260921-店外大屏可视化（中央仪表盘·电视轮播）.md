# 任务包｜店外大屏可视化（中央仪表盘 · 电视轮播）— 2026-09-21

> **本文件是施工图纸**（宪法 §六 前置铁律「文档先行」：文档未落地不得动代码）。

---

## 一、需求原文（用户 2026-09-21）

> 「我希望看到的仪表盘不仅仅是数字，还有很多的图，很酷炫的图，让人眼前一亮，**以后我要把这个中央仪表盘投到店外的电视机上**，
> 所以你帮我想想需要展示哪些酷炫的图表来吸引人。」

---

## 二、先说一个判断（决定了方案形态）

**现在的 `/`（今日概览）是"内部运营视角"**：待办审批（退款/退会/转让/收款）、配置变更记录、后台账号数、今日登录数……
这些内容投到店外有三个问题：① 家长不关心；② 内部数据外泄（审批/账号数）；③ 视觉上全是数字与列表，谈不上"眼前一亮"。

→ 因此建议：**另开一块大屏路由 `/screen`**（不替代 `/`）。店里的电视只开这一页，
内部同事仍在 `/` 办公。两者共用同一套 paint 令牌与组件语言。

---

## 三、大屏场景约束（这几条决定设计，不是审美偏好）

| 约束 | 数字口径 |
|---|---|
| 观众在**店外 5–10 米**看 | 主标题 ≥ 48px、图表标签 ≥ 20px、一本书封面至少 200×260px |
| **无人交互**（不会有人点鼠标） | 全自动轮播，每屏 **12 秒**；底部常驻进度条提示"还有几屏" |
| 电视机**常年开机** | 无 canvas 逐帧动画、无 video；CSS transform/opacity 动画；单屏 DOM < 300 节点；每 60 秒拉一次数据 |
| 店里网络会抖 | 拉取失败**保留上一屏数据**（不白屏、不弹错），右下角小圆点表示连接状态 |
| 家长**3 秒**决定要不要进店 | 第一眼必须是"书 / 孩子 / 活动"这类**有情感的画面**，不是数字表格 |

## 四、节目单（轮播 7 屏 · 每屏一张主视觉）

| # | 屏 | 主视觉 / 图表形态 | 数据来源 | 为什么吸引人 |
|---|---|---|---|---|
| 1 | **今日热气榜** | TOP5 **绘本封面墙**（大封面 + 借阅次数徽章，交错错位排列） | `borrow_records` 近 7 天按 `book_id` 聚合 + `books` 封面 | 封面本身就是最好的广告；家长看到"别人家孩子在读什么" |
| 2 | **阅读里程** | 超大数字（动画滚动计数）+ **环形进度**（SVG 圆环，目标达成率） | `words_ledgers` 本周合计词数；阅读时长表本周分钟数 | "全馆本周读了 128 万词"这种数字有冲击力 |
| 3 | **小读者星光榜** | 前三名**头像 + 等级框**（复用 `avatar-ring` 同款视觉）+ 横向词数条 | 周榜快照（`circle_rank_snapshot` / 五榜单服务） | 榜单是"被看见"的成就感，孩子会拉着家长看 |
| 4 | **成长里程碑墙** | A–Z 等级**阶梯塔**（SVG 柱）+ 本周播报卡（"本周 12 位小读者升级""第 3 位读完 10 万词"） | growth 域等级/勋章/里程碑 | 播报感 = 荣耀感，家长会拍下来发朋友圈 |
| 5 | **活动预告** | 下一场活动**封面大图** + 时间/地点 + 剩余名额 + 二维码 | `activities`（`list_upcoming`）+ `MINIAPP QR` | 直接拉进店（活动是到店的最强动因） |
| 6 | **馆藏上新** | 近 14 天新书封面**横向滑动带** + 一句话推荐语 | `books`（按上架时间倒序） | 制造"常来常新"的期待 |
| 7 | **借阅趋势** | 近 30 天**面积折线图**（SVG path + 渐变填充）+ 今日实时大数字 + 底部 ticker「刚刚 XX 借走了《》」 | `borrow_records` 按日聚合 + 实时最新 1 条 | 趋势图有"数据流动"的炫感；ticker 制造热闹 |

**常驻元素**（不参与轮播）：店名 + 欢迎语、日期/时间、小程序二维码、「本店已服务 N 个家庭」。

## 五、技术方案（零新依赖）

- **不引图表库**（现状：admin-web 只有 antd/react，无任何图表依赖）。理由：① 绘本风的图形需要自己控色控形，
  通用库的默认皮肤反而"不像我们"；② 电视机常年开机，重量级库的内存/重绘不划算；③ 宪法 §一.8 最小依赖纪律。
- 全部用 **手写 SVG + CSS 动画 + paint 令牌**（圆环 = `stroke-dasharray`；条形榜 = 带动画宽度的 `rect`；
  面积图 = `path` + `linearGradient`；计数 = `requestAnimationFrame` 缓动）。
- **一个聚合端点**：`GET /api/admin/screen/summary`（一次返回 7 屏所需全部数据，60 秒轮询；
  服务端聚合，避免大屏自己发 7 个请求）。
- 大屏专属样式：`.screen-*` 系列类 + `--screen-*` 令牌（超大字号、深底高对比、无边框阴影干扰）。
- 入口：管理端左侧导航**不加**菜单项（店里电视直接开 URL）；但给 `/` 留一个「打开店外大屏」按钮，方便调试与投屏。
- 权限：沿用 `dashboard.view`（不新增权限码）。

## 六、红线

- **R1（隐私）**：店外大屏**不出现孩子真实姓名与可辨识照片**。默认口径：昵称/英文名 + 卡通头像；
  与活动模块"照片只放不含可辨识孩子的图"同一原则。**本条需用户确认后施工**。
- **R2（内部数据不出门）**：待办审批数、账号数、配置变更、登录数等**一律不上大屏**。
- **R3（性能预算）**：单屏 DOM < 300 节点、无逐帧重绘、单次刷新请求 ≤ 1、断网保留上一屏。
- **R4（视觉同源）**：颜色/字号/圆角只用 paint 令牌与规范（docs/15），不另起一套设计语言；
  但允许大屏用**深底高对比**变体（室外光线强）。

## 八、待用户拍板（不拍板不开工）

1. **隐私口径**：星光榜显示"昵称 + 卡通头像"（推荐）还是完全匿名（"小读者 A / B / C"）？
   大屏在店外，这是必须由你定的红线。
2. 轮播时长：每屏 **12 秒**（推荐，7 屏 ≈ 1 分半转一圈）还是更快/更慢？
3. 是否显示**金额类**数据（如本月借阅带来的续费率）——**建议不显示**（店外无意义且有经营敏感性）。
4. 屏 5 的二维码：用**小程序码**（需后端出图能力，见 PRD §9.2.1 "明确不做 wxacode 出图"）还是先放**小程序搜索指引**？
5. 电视机分辨率与摆放方向（横屏 1920×1080 假设 / 竖屏？）——影响排版基准。
