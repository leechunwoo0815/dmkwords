## 一、生产拓扑（单机，与 dev 同构 ADR-001 但职责分离）

```
微信小程序 ──HTTPS──┐
                    │   nginx（TLS 终结 + 静态 SPA）
馆内浏览器 ──HTTPS──┤     ├─ /api/*      → 127.0.0.1:8002（uvicorn 单进程）
                    │     └─ /（admin-web dist 静态）
                    │
              docker mysql:8.0（127.0.0.1 绑定，容器内 3306 不映射公网）
```

**关键决策**：TLS 在 nginx 层终结，后端保持 `uvicorn --host 127.0.0.1 --port 8002` 裸 HTTP。
理由：dev.sh 的 8443 镜像进程教训（P1-F10：双进程 APScheduler 任务双执行，TaskRunLog 同秒
双条）——生产**单后端进程**，证书装 nginx 一处，杜绝双调度复发。

## 二、生产 compose（`docker-compose.prod.yml`，与 dev 分离）

| 项 | dev 现状（docker-compose.yml） | 生产要求 |
|---|---|---|
| 端口绑定 | `3306:3306`（**全接口暴露**） | `127.0.0.1:3306:3306` 仅本机 |
| root 密码 | `dmkwords_dev`（弱） | 从 `.env` 注入强密码（禁写进 compose） |
| 容器名/卷 | dmkwords-mysql / mysql_data | dmkwords-mysql-prod / mysql_data_prod（防误连 dev） |
| **binlog** | **未开启**（backup_binlog.sh 的 PITR 依赖它） | `--log-bin=mysql-bin --server-id=1 --binlog-format=ROW --binlog-expire-logs-seconds=604800` |
| 时区/字符集 | utf8mb4 +8:00 ✓ | 同款保留 |
| restart | unless-stopped ✓ | 同款 |

## 三、证书（certs/ v6 资产核实）

- `certs/server.crt`：CN=192.168.18.162，SAN=IP 192.168.18.162+DNS localhost，**有效期至 2028-12-02**——馆内 LAN 部署可直接复用。
- **边界（重要，挂甲方决策）**：自签证书对**管理端浏览器**可导入 `ca.crt` 信任后正常使用；对**微信小程序正式版**不可用（wx.request 仅信任受信 CA）——体验版/真机调试可勾选「不校验合法域名」过渡，**正式发布需受信 CA 证书或甲方确认长期用体验版**。此边界写进 P13 验收 checklist 打勾项。
- 若生产机 IP ≠ 192.168.18.162：改 `certs/san.cnf` 重签（CA key 在同目录，自签流程已有）。

## 四、nginx 反代（骨架）

```nginx
server {
  listen 443 ssl;
  server_name 192.168.18.162;           # 生产 IP，与证书 SAN 一致
  ssl_certificate     /path/certs/server.crt;
  ssl_certificate_key /path/certs/server.key;

  client_max_body_size 200m;             # 音频上传大文件（R6：音频资产上百 GB）
  proxy_read_timeout    300s;

  location /api/ {                       # 小程序与管理端同源（media.fullUrl 拼 token 依赖同源）
    proxy_pass http://127.0.0.1:8002;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
  }
  location / {
    root /opt/dmkwords/admin-web-dist;   # pnpm --dir admin-web build 产物
    try_files $uri /index.html;
  }
}
```

**禁 0.0.0.0 红线**：uvicorn 生产启动一律 `--host 127.0.0.1`（dev.sh 的 0.0.0.0 仅开发态）。

## 六、词库导回（R7 联动·ecdict.db 812MB→335 万词）

- 工具已就位：`python -m scripts.import_ecdict`（BATCH=5000，INSERT IGNORE 保已有词，
  unique_checks/foreign_key_checks 会话级关闭，**可随时 Ctrl-C 重跑续传**——幂等）。
- 生产执行窗口：**F8 开工时导入，非上线前**（docs/08 R7 缓解栏原文）——放在读者流量为零的
  时段（如凌晨），实测 dev 3-8 分钟，生产磁盘 IO 弱化预估 ≤30 分钟。
- 限速方案（若有拖慢主库征兆）：调小 `BATCH=1000` + 导入期间临时停 APScheduler 借书任务，
  导完恢复（方案已预留，按需启用）。
- 备份锚点：`~/dmkwords-backups/dictionary_words-full-20260902.sql.gz`（309 演示词态全量）
  ——词库重导后演示词不丢（INSERT IGNORE）。

## 七、备份与恢复（R6 联动·P13 演练项）

**已就位脚本**（A-P2-5/6 安全提取 .env，禁 source 注入）：
- `scripts/backup_db.sh`：每日 mysqldump 全量，保留 30 天 → `backups/`
- `scripts/backup_binlog.sh`：每小时 binlog 增量 → PITR（**生产 compose 必须先开 binlog，见 §二**）

**生产 crontab（部署时安装）**：
```cron
0 2 * * *   /opt/dmkwords/scripts/backup_db.sh    >> /var/log/dmk-backup.log 2>&1
0 * * * *   /opt/dmkwords/scripts/backup_binlog.sh >> /var/log/dmk-backup.log 2>&1
*/30 * * * * df -P /opt | awk 'NR==2 && int($5)>85 {print strftime() " disk >85%"}' >> /var/log/dmk-disk.log
```
磁盘告警阈值 85%（R6：音频上百 GB 磁盘打满风险；OSS 迁移预案见 ADR-004 抽象层，本期不实施）。

**恢复演练步骤（P13 验收必做，演练结果留 LEDGER）**：
1. 恢复全量：`gunzip < 全量.gz | mysql -uroot -p dmkwords`
2. PITR 重放：`mysqlbinlog --start-datetime=... binlog.* | mysql -uroot -p dmkwords`
3. 核对：行数对拍（books/parents/children/orders 四表）+ 起后端 health + 登录冒烟

## 九、与 dev 的隔离纪律

- 生产一律用 `docker-compose.prod.yml`（-f 显式指定），**禁在生产机跑 dev.sh**（0.0.0.0+弱密码+5173 前端热更全不该出现）。
- 数据库密码/SECRET_KEY 与 dev 完全不同值；`.env` 不入库（宪法既有红线）。
- 证书资产 certs/ 已入库（v6 批次）——CA key 属敏感件，生产机单独存放并收紧权限（600）。
