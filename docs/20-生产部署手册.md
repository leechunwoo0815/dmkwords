## 一、生产拓扑（单机，与 dev 同构 ADR-001 但职责分离）

```
微信小程序 ──HTTPS──┐
                    │   nginx（TLS 终结 + 静态 SPA）
馆内浏览器 ──HTTPS──┤     ├─ /api/*      → 127.0.0.1:8002（uvicorn 单进程）
                    │     └─ /（admin-web dist 静态）
                    │
              docker mysql:8.0（127.0.0.1 绑定，容器内 3306 不映射公网）
```

**关键决策**：TLS 在 nginx 层终结，后端保持 `uvicorn --host 127.0.0.1 --port 8002` 裸 HTTP。
理由：dev.sh 的 8443 镜像进程教训（P1-F10：双进程 APScheduler 任务双执行，TaskRunLog 同秒
双条）——生产**单后端进程**，证书装 nginx 一处，杜绝双调度复发。

## 二、生产 compose（`docker-compose.prod.yml`，与 dev 分离）**——已落地（2026-10-08，本地实测通过）**

**⚠️ `name: dmkwords-prod` 不是装饰**：两份 compose 的**服务名都叫 `mysql`**，Compose 按「项目名+服务名」认容器，
项目名默认取目录名——同一目录里跑 `-f docker-compose.prod.yml up` 会把 **dev 容器 `dmkwords-mysql` 直接替换掉**
（卷没动，但容器没了、dev 连不上）。2026-10-08 演练实测踩到，已用独立项目名根治。

### 2.1 后端镜像的定位与时区（R11-01，2026-10-26 第十一轮 R11-a）

**定位（现状）**：`Dockerfile` 是**非生产镜像**（本地构建/预演）。生产唯一路径仍是原生 uvicorn +
`deploy/start-backend.sh`（§一/§四）；`docker-compose.prod.yml` 里只有 mysql，**没有后端服务**。
**2026-10-28 甲方裁定：保持非生产定位**——不接进生产路径；本镜像仅用于本地构建/预演与 CI
构建检查，不得用本镜像部署生产。

镜像自身的两条硬纪律：

1. **时区钉死**：镜像里 `ENV TZ=Asia/Shanghai` 且显式安装 `tzdata`。容器默认 UTC，而 MySQL 容器是 `+08:00`；
   不钉时区会让业务日边界整体偏 8 小时（打卡/到期/周月报/"今日"统计 —— A18-0022 红线）。
   与 `deploy/start-backend.sh` 的 `export TZ` 同源。判据：
   `pytest tests/unit/test_review11_r11a_20261026.py -k dockerfile`（只认指令行，注释里的提及不算）。
2. **禁止 `DEBUG=true` 换可用性**：`validate_production` 的早退门是 `not is_production_env(APP_ENV) and DEBUG`；
   在镜像里打开 DEBUG 会**跳过全部生产红线**（固定验证码 `1234` + mock 支付可结单）。镜像必须保持 `DEBUG=false`，
   生产配置校验一律走 `deploy/start-backend.sh`（由部署方注入 `APP_ENV=production`）。

构建上下文见 `.dockerignore`：词库 `data/`（812MB）与内部报告 `外部专家意见/` 已排除，运行期挂 volume；
判据：`pytest tests/unit/test_review11_r11a_20261026.py -k dockerignore`。

## 四、nginx 反代（模板已落地：`deploy/nginx/dmkwords.conf.template`）

模板就位（占位符 `__SERVER_NAME__` / `__CERT_CRT__` / `__CERT_KEY__` / `__ADMIN_DIST__` / `__BACKEND_ADDR__`），
部署时 `sed` 替换后落到 `/etc/nginx/conf.d/dmkwords.conf`，`nginx -t && nginx -s reload`。要点（文件头也有）：

```nginx
location /api/ {
  proxy_pass http://__BACKEND_ADDR__;            # 127.0.0.1:8002
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $remote_addr; # ★ 覆盖式，禁 $proxy_add_x_forwarded_for
  proxy_set_header X-Forwarded-Proto https;
}
```

- **★ 这一行与 `.env` 的 `TRUSTED_PROXY_COUNT=1` 成对**（审查 P1-5/P2-8）：nginx 覆盖 XFF（不追加），后端按
  "右起第 1 段"取真实 IP。只配一边 = 要么全站共用一个限流桶，要么伪造 XFF 能换桶（等于没限流）。
- 媒体缓存头（内容寻址 `immutable` 长缓存）由后端中间件下发（`backend/middleware/media_cache.py`），
  nginx **不得**覆写 `/api/` 的 `Cache-Control`。
- **安全响应头（第八轮 P2-17）**：server 级下发 `X-Content-Type-Options: nosniff`、
  `X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Permissions-Policy`、
  `Cross-Origin-Opener-Policy`、`Strict-Transport-Security`，外加 SPA 的 CSP
  （`frame-ancestors 'none'` 是点击劫持那道闸；`script-src` 仍为 `'self'`，
  收紧前需对**打包产物**做浏览器实测）。后端 API 侧同款由
  `backend/middleware/security_headers.py` 下发（API 响应是 `default-src 'none'` 的最严 CSP）。
  ⚠ nginx 的 `add_header` **继承规则**：子 location 里只要出现一条 `add_header`，
  server 级的全部失效——将来给某个 location 加头时必须把 server 级那组复制过去。
- **访问日志脱敏（第八轮 P2-16）**：`log_format dmkwords_noquery` 用 `$uri`（**不含 query**）
  替代默认 combined 的 `$request`——媒体端点靠 `?token=` 鉴权，默认格式会把 **30 天有效的
  管理员/家长凭证写进日志文件**。后端 uvicorn 侧同款脱敏（`backend/main.py` 的 `_RedactQueryString`
  挂在 `uvicorn.access` 上，日志仍留、只抹 query）。
- **本机无 nginx（brew 未装、沙箱内拉不到镜像），`nginx -t` 未跑**——已用结构性断言兜底
  （模板断言见 `tests/unit/test_prod_skeleton.py`：覆盖式 XFF 存在、`$proxy_add_x_forwarded_for` 不存在、
  花括号配平、与 `TRUSTED_PROXY_COUNT=1` 成对）。**部署机上必须补跑一次 `nginx -t`**。

**禁 0.0.0.0 红线**：uvicorn 生产启动一律 `--host 127.0.0.1`（dev.sh 的 0.0.0.0 仅开发态）。
生产启动脚本已就位：`bash deploy/start-backend.sh`（单进程、无 `--workers`、只绑 127.0.0.1，
且**启动前先跑 `validate_production`**——配置不合规直接拒启并打印常见修法）。

## 七、备份与恢复（R6 联动·P13 演练项）

**已就位脚本**（A-P2-5/6 安全提取 .env，禁 source 注入）：
- `scripts/backup_db.sh`：每日 mysqldump 全量，保留 30 天 → `backups/`
- `scripts/backup_binlog.sh`：每小时 binlog 增量 → PITR（**生产 compose 必须先开 binlog，见 §二**）。
  **2026-10-12 修复（审查 P1）**：本脚本此前**静默空转**（PITR 能力实际不存在）——两个原因叠加：
  ① 它按 `$MYSQL_DATA_DIR/binlog.*` 在**宿主**找文件，而数据在容器命名卷里（宿主没有那些文件）；
  ② 文件名前缀也不对（compose 用 `--log-bin=mysql-bin`，实际是 `mysql-bin.NNNNNN`）；③ 另有
  `set -e` 陷阱：`SHOW BINARY LOG STATUS` 是 8.4+ 语法，8.0 报 1064 直接中断脚本。
  现在：自动探测容器（`MYSQL_CONTAINER`，默认 `dmkwords-mysql-prod`）→ `docker exec` 列文件 +
  `docker cp` 取回；宿主形态两种前缀都收；8.0 自动回退 `SHOW MASTER STATUS`；
  **零产出即 exit 2 报警**（不再"看起来成功"）。本机实跑：一次取回 6 个 binlog / 25MB。
  部署机核验：首轮 cron 后 `ls -lh backups/binlog/ | head` 必须非空（空 = 立刻查容器名/数据目录）。
- `scripts/restore_drill.py`：**演练脚本**（2026-10-08 新增）——全量恢复 + 五表对拍 + 冒烟；`pitr` 子命令
  做"灾难 + 点对点恢复"（打锚点 → 写探针书 → 误删 → DROP DATABASE → 全量 + binlog 重放到误删前）。
  默认 dry-run，`APPLY=1` 才真跑；库名必须含 `drill` 且与业务库不同名（自毁防线）。

**⚠️ 部署前提（2026-10-08 演练实测踩到，两处工具缺口）**：
1. **宿主没有 mysql 客户端**时 `backup_db.sh` / `backup_binlog.sh` 直接跑不了（本机实测：`mysqldump`/`mysql`/
   `mysqlbinlog` 全部 `command not found`）。两条路：部署机装 `mysql-client`（`apt install mysql-client` /
   `brew install mysql-client`），或把 crontab 命令包一层 `docker exec`（如演练脚本的做法）。
2. **官方 `mysql:8.0` 镜像里没有 `mysqlbinlog`**（只装 `mysql-community-server-minimal`；同镜像的
   MySQL Shell 8.0 也没有 binlog 工具）——**PITR 重放必须在有 mysqlbinlog 的地方做**。所以"开了 binlog"
   不等于"能回放"：部署机装好客户端，或给容器加装 client 包，否则灾难当天才发现回放不了。

**磁盘告警脚本**：`scripts/disk_alert.sh`（**单一来源，本手册不再内联副本**——避免文档与脚本漂移）。

要点：纯 bash（**不用 `strftime` 等 gawk 扩展**，Debian/Ubuntu 默认 `mawk` 下会直接报错）；
超阈值（`DISK_ALERT_PERCENT`，默认 85）时推送 webhook（`DISK_ALERT_WEBHOOK`，企业微信/钉钉机器人），
**未配 webhook 则非零退出**交给 cron `MAILTO` 兜底——不允许"只写日志没人看"。
本机实测三条路径：阈值 99% 静默通过（exit 0）／阈值 1% 无 webhook（exit 1 + 落日志）／
阈值 1% + 本地 webhook 监听（**真收到 JSON 推送**，exit 0）。

> ⚠️ 历史问题（2026-10-12 审查 P2 → 2026-10-18 P3-5 修复）：旧 cron 行用 `df | awk '… strftime(…)'`，
> `strftime()` 是 **gawk 扩展**，Debian/Ubuntu 默认 `mawk` 下直接报错（等于没告警）；三行都写 `/var/log/`
> 需 root crontab。现已改为**纯 bash 无扩展依赖** + 输出到项目日志目录 + **真实推送通道**。
> **上线验收（必做）**：把 `DISK_ALERT_PERCENT` 临时设成 **1%**（或把 `DISK_ALERT_PATH` 指向一个已满的挂载点）
> 手动跑一次 `scripts/disk_alert.sh`，确认**收到推送**且日志有行；收不到就是没接上（不要只看脚本退出码）。
磁盘告警阈值 85%（R6：音频上百 GB 磁盘打满风险；OSS 迁移预案见 ADR-004 抽象层，本期不实施）。

3. **可回滚**：迁移的 `downgrade` 分支必须写（哪怕只是反向 UPDATE）；不可逆操作（删列/删表）先在
   `docs/20` 记"不可逆"。
4. **索引变更同步声明进模型**（既有纪律）：否则 `alembic check` 会报"要删索引"。
