# 21 - 微信小程序与支付配置操作手册（首次开发者版，2026-10-08）

> **定位**：给"第一次做小程序"的人看的手把手指南。回答两个问题：
> ① 每个东西**在哪配**、配成什么；② 该**向甲方要什么资料**、拿到后放在哪。
> **配套文档**：`docs/20`（生产部署手册：服务器/nginx/备份）、`docs/09` WM12 系列（支付口径与验收判据）、
> `docs/04` WM12 步骤表（手动验收动线）。
> **一条纪律**：AppSecret / APIv3 密钥 / 商户私钥是**服务端密码**——只写进 `.env` 或放 `certs/`，
> **不要贴进聊天、不要提交进 git**（`.env` 与 `certs/` 都已在 `.gitignore` 里）。

## 〇、先分清三个地方（90% 的混乱来自把两个后台当成一个）

| 地方 | 网址 | 管什么 |
|---|---|---|
| **微信公众平台**（"小程序后台"） | `mp.weixin.qq.com` | 小程序身份：AppID / AppSecret、服务器域名白名单、订阅消息模板、隐私协议、类目、成员管理、版本发布 |
| **微信支付商户平台** | `pay.weixin.qq.com` | 钱：商户号 mchid、APIv3 密钥、API 证书（商户私钥+证书）、平台证书、回调地址、**AppID 与商户号的绑定** |
| **你的电脑（本仓库）** | — | `.env`（密钥）、`certs/`（证书文件）、`miniapp/project.config.json`（小程序 AppID）、开发者工具 |

**三个"身份证"**，作用完全不同：

| 名称 | 是什么 | 保密级别 | 谁签发 |
|---|---|---|---|
| **AppID**（如 `wxdec0d92e74db7f16`） | 小程序的身份证号 | 公开（可以贴聊天） | 公众平台 |
| **AppSecret** | 小程序的密码：让我们服务器能"替小程序说话"（换 openid、发订阅消息） | **保密** | 公众平台（可重置） |
| **商户号 mchid** | 收款账户号 | 半公开 | 商户平台 |
| **APIv3 密钥** | 支付接口的加密/解密密钥（32 字节） | **保密** | 商户平台（自己设置） |
| **API 证书**（`apiclient_key.pem` + `apiclient_cert.pem`） | 支付接口的签名身份 | **保密（文件）** | 商户平台（**只能下载一次**） |

**一句话流程**：AppID 让微信认得这个小程序 → AppSecret 让我们的服务器能替它说话（微信登录换 openid）
→ 商户号让钱能进出 → **三者靠"AppID 与商户号绑定"串起来**（不绑定，真付会直接报
`APPID_MCHID_NOT_MATCH`）。

## 一、向甲方要的资料清单（按优先级，逐项说明"为什么 / 去哪拿 / 怎么给我"）

| # | 要什么 | 为什么要 | 甲方在哪拿 | 交付方式 |
|---|---|---|---|---|
| 1 | **小程序 AppID** | 项目身份；开发者工具与后端都要 | 公众平台 → 开发管理 → 开发设置 | 可直接贴聊天（公开信息） |
| 2 | **小程序 AppSecret** | 微信一键登录（`code2session` 换 openid）、订阅消息、取手机号 | 同上（**可重置**；重置会让旧的立即失效） | ⚠️ **别贴聊天**：自己写进 `.env` 的 `WECHAT_APP_SECRET=` |
| 3 | **把你的微信号加为"开发者"** | 否则开发者工具打不开这个小程序（会报无权限） | 公众平台 → 管理 → 成员管理 → 添加成员（角色选"开发者"） | 你把微信号给甲方，让他加 |
| 4 | **商户号 mchid** | 收款/退款/对账的主体 | 商户平台（登录后首页可见） | 可贴聊天 |
| 5 | **AppID 与商户号的绑定** | 不绑定真付报 `APPID_MCHID_NOT_MATCH` | 商户平台 → 产品中心 → **AppID 账号管理**（发起关联）；部分流程需在小程序后台确认 | 让甲方完成并截图给你确认 |
| 6 | **APIv3 密钥**（32 字节） | 回调报文解密（AES-GCM） | 商户平台 → 账户中心 → **API 安全** → 设置 APIv3 密钥（**设置后不再显示**，忘了只能重置） | ⚠️ 别贴聊天：写进 `.env` 的 `WECHAT_API_KEY_V3=` |
| 7 | **API 证书**（`apiclient_key.pem` + `apiclient_cert.pem`） | 支付请求签名 | 商户平台 → API 安全 → **API 证书** → 下载（**只能下载一次**，丢了要重置证书） | 两个 PEM 文件放 `certs/`，路径写进 `.env` |
| 8 | **商户证书序列号** | 请求头 `serial_no` 用它 | 证书详情页可见；或本地 `openssl x509 -in certs/apiclient_cert.pem -noout -serial` | 可贴聊天（非密钥） |
| 9 | 微信支付**平台证书** | 回调**验签**（微信用它签，我们用它验） | **不用甲方给**：我们用商户私钥调 `/v3/certificates` 自己拉（部署后跑一次任务 `wechat_cert_refresh`，之后每日自动轮换） | 我们自动获取 |
| 10 | **生产域名 + 备案** | 小程序只能请求**已备案的 https 域名**；支付回调必须公网 https | 甲方确认 `api.dmkwords.cn` 是否已注册、已 **ICP 备案**、已签 HTTPS 证书 | 让甲方确认并给域名管理权限（或他配好告诉你） |
| 11 | **短信通道凭据**（阿里云/腾讯云） | 登录兜底通道 + 换手机号 | 甲方云账号 → 短信服务 → 签名与模板**报备**（要资质，审核 1-3 天） | AccessKeyId/Secret 写 `.env`；签名/模板 ID 可贴聊天 |
| 12 | **订阅消息模板 ID**（10 个） | WM11 通知的"微信推送"那条腿 | 公众平台 → 订阅消息 → 选用模板（见 §四） | 模板 ID 可贴聊天；我填进 `SubscribeTemplate` |
| 13 | **小程序类目与主体资质** | 决定能否开通支付、能否申请订阅消息 | 公众平台 → 设置 → 基本设置 → 服务类目 | 让甲方确认已选对类目 |
| 14 | **隐私协议 / 用户协议文本** | 收集手机号、孩子姓名、头像，必须声明 | 公众平台 → 设置 → 服务内容声明 / 用户隐私保护指引 | 甲方提供文本或确认我们起草 |
| 15 | **体验成员**（可选） | 真机预览、体验版测试 | 公众平台 → 管理 → 成员管理 → 体验成员 | 同上（把你的微信号加上） |
| 16 | （可选）**商户平台操作员账号** | 让你自己进去配回调地址/查账单 | 商户平台 → 账户中心 → 操作员 | 只在甲方愿意时 |

**一句话给甲方的话**（可以直接转发）：
> 请提供：① 小程序 AppID 与 AppSecret；② 把我的微信号加为该小程序开发者；
> ③ 微信支付商户号，并在商户平台把该 AppID 与商户号**关联绑定**；
> ④ 商户平台下载的 **API 证书（两个 PEM 文件）** 与 **APIv3 密钥**；
> ⑤ 确认生产域名 `api.dmkwords.cn` 的备案与 HTTPS 证书情况；
> ⑥ 若有短信通道，提供 AccessKey 与已报备的签名/模板。

## 二、本机配置（一次配好，长期有效）

### 2.1 `.env`（唯一的密钥落点）

```bash
cp .env.example .env        # .env 不进 git（已在 .gitignore）
```

分组说明（模板 `.env.example` 里每一项都有注释，这里说"现在必须有"与"等资料到位再填"）：

| 组 | 键 | 现在必须有？ | 说明 |
|---|---|---|---|
| 应用 | `APP_ENV` / `DEBUG` | ✅ | 本地 `APP_ENV=dev` + `DEBUG=true`；生产 `APP_ENV=production`（**生产校验只看它**，`DEBUG` 关不掉红线） |
| 应用 | `LOGIN_DEV_CODE` | ✅ 本地 | 本地固定验证码 `1234`；**生产必须置空** |
| 数据库 | `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | ✅ | 本地走 OrbStack 容器 `dmkwords-mysql:3306` |
| 安全 | `SECRET_KEY` | ✅ | 本地随便；生产必须强随机 |
| 安全 | `CORS_ORIGINS` | ✅ | 管理端域名；生产禁含 `localhost` |
| 安全 | `TRUSTED_PROXY_COUNT` | 生产 | 反代层数（默认 `0`=不读 XFF）；配 nginx 覆盖式 XFF 时设 `1`（**成对**） |
| 微信登录 | `WECHAT_APP_ID` / `WECHAT_APP_SECRET` | 等资料 ①② | 没有它们：小程序"微信一键登录"按钮会失败（拿不到 openid），只能用手机号+验证码兜底 |
| 支付开关 | `PAYMENT_ENABLED` / `PAYMENT_PROVIDER` | ✅ | 本地 `true` + `mock`（下单即时到账，方便演练）；生产 `true` + `wechat` 或纯人工收款 `false` |
| 支付四件套 | `WECHAT_MCH_ID` / `WECHAT_API_KEY_V3` / `WECHAT_CERT_SERIAL_NO` / `WECHAT_PRIVATE_KEY_PATH` / `WECHAT_PLATFORM_CERT_PATH` / `WECHAT_PAY_NOTIFY_URL` / `WECHAT_REFUND_NOTIFY_URL` | 等资料 ④⑤⑥⑦⑨⑩ | `PAYMENT_PROVIDER=wechat` 时缺一**拒启**（生产校验）；本地 mock 通道不用填 |
| 短信 | `SMS_ENABLED` / `SMS_PROVIDER` / `SMS_APP_ID` / `SMS_APP_KEY` / `SMS_SIGN_NAME` / `SMS_TEMPLATE_CODE` | 等资料 ⑪ | 本地 `mock`（验证码打日志）；生产 `aliyun`/`tencent` 且凭据齐全，否则拒启 |
| 订阅消息 | `WECHAT_SUBSCRIBE_ENABLED` | 等资料 ⑫ | `false` 时只落库不推送（微信订阅消息是"一次授权一次推送"的稀缺通道） |
| 其他 | `SCHEDULER_ENABLED` / `BACKEND_PORT` / `UPLOADS_DIR` | ✅ | 单进程调度器；默认 8002 |

**改完 `.env` 必须重启后端**（`bash scripts/dev.sh restart`）——配置是进程启动时读的。

### 2.2 证书放哪

```
certs/                              # 已在 .gitignore，绝不入库
├── apiclient_key.pem               # 商户私钥（资料 ⑦，权限建议 0400）
├── apiclient_cert.pem              # 商户证书（资料 ⑦，用于核对序列号）
└── wechat_platform_cert.pem        # 微信平台证书（自动拉取后写在这里）
```

`.env` 里对应：

```ini
WECHAT_PRIVATE_KEY_PATH=/绝对路径/certs/apiclient_key.pem
WECHAT_PLATFORM_CERT_PATH=/绝对路径/certs/wechat_platform_cert.pem
```

> 注意：`certs/` 里现有的 `ca.crt` / `server.crt` / `server.key` 是**本地开发用的 HTTPS 自签证书**
> （真机调试时手机要装的那个），与微信支付证书**用途完全不同**，不要混。

### 2.3 小程序项目身份（一行）

`miniapp/project.config.json` 的 `"appid"` 必须换成甲方的小程序 AppID：

```json
{ "appid": "wxdec0d92e74db7f16", ... }
```

> 现状提醒：仓库里原本写的是另一个 AppID（测试号/旧号），**换之前先确认哪个是真的**；
> 换完要在开发者工具里重新打开项目（或「详情 → 基本信息」里核对）。

### 2.4 配完自检（一条命令）

```bash
python -m scripts.check_wechat_credentials              # 离线：文件/格式/证书有效期/回调 URL
python -m scripts.check_wechat_credentials --online     # 追加：AppID+Secret 是否真的有效
python -m scripts.check_wechat_credentials --probe-pay  # 追加：AppID 与商户号是否已绑定
```

它**只输出结论与微信错误码，绝不打印任何密钥**（密钥只用于本地校验/签名）。退出码 0 = 关键项全过。

## 三、微信开发者工具操作（第一次用，按顺序做）

1. **下载安装**：微信开发者工具（稳定版）→ 打开后用**你的微信扫码登录**
   （必须是被甲方加为"开发者"的那个微信号，否则第 3 步会报无权限）。
2. **导入项目**：选择本仓库的 `miniapp/` 目录 → AppID 填甲方的小程序 AppID
   （或先在 `project.config.json` 里改好再导入）。
3. **确认权限**：若报"无权限/不是开发者"，回去找甲方做资料 ③。
4. **本地设置**（详情 → 本地设置）：勾选 **「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**
   —— 开发期小程序要连本机 `http://127.0.0.1:8002`，不勾会被拦。
   （体验版/正式版**必须**走 https 正式域名，见 §四）
5. **编译**：模拟器里跑通「首页 → 我的 → 会员购买」。本地后端要先起来：`bash scripts/dev.sh restart`。
6. **真机预览**：点「预览」→ 手机微信扫码 → 真机跑（真机走 `https://<你电脑IP>:8443`，
   手机需安装并信任 `certs/ca.crt`；换网络后 IP 变了要重新生成证书 SAN）。
7. **上传体验版**：点「上传」填版本号与备注 → 公众平台 → 版本管理 → 设为体验版 → 加体验成员（资料 ⑮）后可用。
8. **提交审核 → 发布**：审核通过后线上版生效（这是"上线"的最后一步）。

**开发者工具常见报错对照**：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打开项目报"无权限" | 你的微信号不是该小程序成员 | 找甲方加开发者（资料 ③） |
| 请求失败"不在以下 request 合法域名列表中" | 开发期没勾"不校验合法域名"，或体验版域名没配 | 开发期勾选；体验版/正式版去公众平台配域名（§四） |
| 「微信一键登录」点了没反应/报错 | `.env` 里 AppID/Secret 没填或填错 | 跑 `check_wechat_credentials --online` |
| `code2session` 报 40013 / 40125 | AppID 无效 / AppSecret 无效 | 核对资料 ①②；Secret 重置过要换新的 |
| `code2session` 报 40029 | 这个 code 无效或已用过（**这是正常的**：说明凭据本身有效） | — |
| 支付按钮不出现 | 该家长未绑微信（口径：只允许微信一键登录的家长线上支付） | 用微信一键登录一次即可 |

## 五、微信支付（商户平台）——资金相关，最详细的一节

### 5.1 开通与绑定
1. 甲方已有/新申请**商户号**（需要营业执照等资质）。
2. **把 AppID 与商户号绑定**：商户平台 → 产品中心 → **AppID 账号管理** → 关联（填小程序 AppID）；
   小程序侧可能要在公众平台确认。绑定成功后再做下面的步骤。
3. 判断是否绑定成功：跑 `python -m scripts.check_wechat_credentials --probe-pay`
   （发一次**注定失败**的预支付请求：报 `APPID_MCHID_NOT_MATCH` = 没绑；报参数类错误 = 绑定与签名都通了）。

### 5.2 密钥与证书（三件套）
1. **APIv3 密钥**：商户平台 → 账户中心 → API 安全 → 设置 32 位密钥 → 写 `.env` 的 `WECHAT_API_KEY_V3`
   （**只显示一次**，务必当场存好；忘了只能重置）。
2. **API 证书**：同页面下载 `apiclient_key.pem` + `apiclient_cert.pem`（**只能下载一次**）
   → 放 `certs/`（§2.2）→ `.env` 的 `WECHAT_PRIVATE_KEY_PATH`。
3. **商户证书序列号**：证书详情页复制，或
   `openssl x509 -in certs/apiclient_cert.pem -noout -serial` → `.env` 的 `WECHAT_CERT_SERIAL_NO`。

### 5.3 平台证书（回调验签用）
- 不用向微信"申请"：用商户私钥调 `/v3/certificates` 就能拉到。
- 我们的项目已内置：定时任务 **`wechat_cert_refresh`**（每日 04:00）。**部署后手动跑一次首刷**：
  管理端任务看板点该任务的「运行」，或 `POST /api/admin/tasks/{task_name}/run`（超管）。
- 成功判据：`certs/wechat_platform_cert.pem` 出现文件，且任务日志 success。
- 证书有效期约 1 年，任务会在临期时刷新；`check_wechat_credentials` 会打印剩余天数并告警 <30 天。

### 5.4 回调地址
- 商户平台 → 产品中心 → 开发配置 → **支付回调 / 退款回调**都填同一个地址：
  `https://api.dmkwords.cn/api/pay/wechat/notify`
  （我们的端点按报文 `event_type` 自动分派支付/退款；口径见 `docs/18`）
- `.env`：`WECHAT_PAY_NOTIFY_URL` 与 `WECHAT_REFUND_NOTIFY_URL` 填同一 URL；**必须 https 正式域名**
  （生产校验会拒启非 https）。
- 该地址必须**公网可达**：开发机做不到（微信回不到你的笔记本），所以"真付/真退"只能在生产域名上测。

### 5.5 生产启动会拦哪些配置（缺一拒启）

### 5.7 支付常见错误码对照

| 错误码/现象 | 含义 | 处置 |
|---|---|---|
| `APPID_MCHID_NOT_MATCH` | AppID 与商户号未绑定 | 商户平台做 §5.1 第 2 步 |
| `SIGN_ERROR` / 验签失败 | 私钥与证书序列号不匹配、或签名串错 | 核对 `WECHAT_CERT_SERIAL_NO` 与 `apiclient_key.pem` 是否同一套；跑自检脚本 |
| 回调 401 验签不通过 | 平台证书不对/过期 | 跑 `wechat_cert_refresh` 首刷/刷新 |
| 回调 400 解密失败 | APIv3 密钥不对 | 核对 `WECHAT_API_KEY_V3`（32 字节） |
| `ORDERPAID` | 同一商户订单号已支付 | 正常幂等路径（我们的回调会认幂等） |
| `NOT_ENOUGH` | 商户账户余额不足（退款场景） | 商户平台充值 |
| JSAPI 报 openid 不匹配 | 下单用的 openid 不是本 AppID 下的 | 确认该家长是**微信一键登录**进来的 |
| `PARAM_ERROR` | 参数问题（金额/单号/描述超长等） | 看返回 message，对照字段 |

## 十、术语小词典

- **openid**：某个微信用户**在这个小程序里**的唯一 ID（换一个小程序就变）。线上支付必须用它，
  所以"只允许微信一键登录的家长线上支付"这条口径成立。
- **AppSecret**：小程序的密码。泄露 = 别人能冒充你的小程序调微信接口（可重置）。
- **mchid**：商户号，钱进出走它。
- **APIv3 密钥**：支付回调报文用 AES-GCM 加密，解密要它。
- **平台证书**：微信自己的证书，用来给回调签名；我们用它**验签**（所以必须能刷新到最新的）。
- **request 合法域名**：小程序能请求的域名白名单（必须 https + 已备案）。
- **体验版**：上传后不公开的测试版本，给体验成员用；**真付测试走它**。
- **类目**：小程序的服务分类，决定能开通哪些能力（支付、订阅消息）。
- **ICP 备案**：域名在国内提供服务的强制登记，小程序与微信支付都要求。
