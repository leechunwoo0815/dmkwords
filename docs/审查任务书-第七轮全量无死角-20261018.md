## 3. 判据：本项目认为"什么才算缺陷"

审查必须先读这三处，否则会把**有意的设计**当成 bug（见 §12 白名单）：

1. **`CLAUDE.md`（项目宪法，最高法律）**：§一 铁律（零容忍）· §二 业务红线 · §三 分层架构（Router→Service→Repository→Model，Router 零 ORM/try/HTTPException）· §四 九域边界 · §五 前端宪法 · §六 开发流程铁律（DoD：门禁全量、门禁后现场恢复、用户验收前不 commit/push）· **§八 验证与门禁分级 A/B/C/D**。
2. **`docs/LEDGER.md`（唯一进度事实源）** 与 **`docs/项目交接-20260824.md` 顶部最新版交接卡**（当前状态 / 红线 1–184 / 待拍板清单）。
3. **红线家族（判缺陷的尺子，摘要）**：
   - 资金：金额一律 `Decimal`；台账记**实际发生额**且 `Σ入账−Σ出账=余额`；押金本金=**订单实收**；重复缴纳判据=**本账户已有本金**；押金每条终态都要有回退边。
   - 并发：全局锁序 **`Child → Reservation → copy`**；`with_for_update()` 必链 `.populate_existing()`；**查重后插入必须锁主体行**；条件 UPDATE 防"覆盖已审结"。
   - 幂等：管理待办去重键 `(scene, ref_type, ref_id, dedup_key, is_deleted)`；家长通知加 `parent_id`；**`INSERT IGNORE` 预检的过滤列必须与唯一索引逐列一致**；**周期类场景的去重键必须带周期**。
   - 状态：状态机只能走 `ALLOWED_TRANSITIONS`；**状态写口必须收拢**（如 `Child.set_member_status`）；**状态时钟要有专属落库字段**（如 `pending_evaluation_at`，禁止挂 `update_time`）；终态不可被改写。
   - 门禁与自证：**门禁必须按视角分别断言**（并集判定=假绿温床）；**检查器的自述必须与实现一致**；**变异自证是唯一有效证据**且必须打在对准的分支；**红/绿必须来自"真的执行过"**（`hook_error`/0 匹配/全量 skipped ⇒ **无效**，不是绿）；**红线 183**：判"某修复有无守护"必须跑**该批次全部**测试，不许只跑 3 条场景就下结论；**红线 184**：静态概括（grep/AST）必须**抽样反证**。
   - 数据：业务主数据**禁物理删除**（软删）；全局唯一索引 × 软删（同号**复活**或**如实报错**，不许裸 500）；派生码唯一冲突转 **409**；多文件上传**先全量校验再落盘**；受保护目录 + 路径判定必须用 `is_within`（**禁止裸 `startswith(root)`**）。
   - 前端：错误态**不许伪装成 0/空**；分母/阈值由**服务端下发快照**；权限三方一致（前端路由/按钮 ↔ 后端 `require_perm` ↔ 菜单）；`pnpm exec tsc --noEmit` 必须 0 错。
   - 运维：进程时区在启动脚本**钉死**；生产配置 fail-closed 自检（空密钥/固定验证码/mock 支付或短信 → 拒绝启动）。

## 4. "全量 · 全维度 · 无死角"的定义与合格线（**本轮核心**）

### 4.1 三全

1. **资产全**：附录 A 的 **1364 行**每一行都要有判定（后端文件 / 端点 / 表 / 迁移 / 任务 / 配置键 / 门禁与检查器 / 运维脚本 / 51 个前端页面 / 304 个 BDD 场景 / 131 个测试文件 / 23 个步骤文件 / 44 份文档 / 90 条 FEAT / 14 条动线 / 24 条轴）。
2. **维度全**：§6 的 **24 条轴**每条都必须有**结论**（不接受"未覆盖"）。
3. **链路全**：§7 的 **14 条端到端动线**逐跳走完，每跳给证据。

### 4.2 覆盖台账怎么用

- `R1` 行：**必须独立判定**，禁止"以上同理""其余同类"；
- `R2` 行：必须有判定，但允许**规则归并**——写法 `RG:<规则号>`，规则必须在报告 §规则表 里定义（规则内容 + 它覆盖哪些行 + 为什么可以归并），并给**反证抽样 ≥3**（写明抽样方法与为什么这 3 个足以反证）。
- 判定词汇：`OK` / `P0`·`P1`·`P2`·`P3`（附报告条目号）/ `VA`（不适用，**必须写理由**）/ `RG:<规则号>` / `MF`（变异失败：发现"检查器抓不到"本身就是发现）。
- **覆盖率算术**：按 A1–A18 逐节给 `已判定行数 / 该节总行数`，再给总计。分母以附录 A 的 `> 本节合计 N 行` 为准。

## 8. 方法协议（必须遵守）

### 8.1 证据三态（标签不许混用）
- `实测✓`：你**亲眼看到**的输出（探针/接口/日志/SQL），必须附原始输出片段；
- `静态`：代码/文档通读成立，但**未构造出端到端复现**（写清"为什么没复现"）；
- `未复现`：你**尝试复现但没成功**——**这不是**缺陷结论，写清阻断了什么。
> 教训：把"没复现"写成缺陷 = 失信；把"静态"写成"实测" = 更严重。

### 8.2 探针规范
- 探针文件 `tests/unit/test_audit7_probe_<日期>.py`，**跑完即删**（连 `__pycache__`）；
- 每条探针**断言"正确行为"**（红 = 缺陷成立），docstring 写明它对应哪条候选；
- **并发探针必须"可判定"**：不许 `sleep` 猜时序；要么行锁验证"对方确实在等锁"，要么事件/信号量同步，要么明确标注"未证实"；
- 探针若需写库，走 §8.4。

### 8.3 独立性与反假绿
- 不把"上轮报告说已修"当证据；反过来，**上轮说修好了而你看到没修**，那是最高价值发现；
- 判"某修复有无守护"**必须跑该批次全部测试**（红线 183）；
- 任何"全仓/所有/不存在/均无"的静态概括，**必须抽样反证**（红线 184）；
- `hook_error` / 0 个场景匹配 / 全量 skipped ⇒ **不是绿**，是无效结果，必须重来。

### 8.4 跑测试/改库的纪律（现场恢复手册 `docs/19`）
```bash
cd /Users/litianyu/cc-projects/dmkwords
bash scripts/dev.sh stop                      # 跑测试前必须停后端（门禁不许叠跑）
# … 跑 pytest / behave / 探针 / 压测 …
bash scripts/dev.sh restart                   # 恢复现场（重启 + 双 seed）
curl -s -o /dev/null -w "%{http_code}" http://localhost:8002/health   # 期望 200
curl -s -o /dev/null -w "%{http_code}" http://localhost:5173          # 期望 200
python -m scripts.check_demo_baseline         # 期望 PASS：35 书 / 3 家长 / 11 孩子 / 4 活动 + 演示孩 10 项
```
环境依赖 OrbStack；容器运行时整体掉线时 `orb status` → `orb start`（数据卷不丢）。
**门禁分级**：A=tsc；B=该域 pytest / `behave -n "<场景名>"` + ruff；C=推送前一次 `bash scripts/gate.sh full`；D=纯文档不跑。
**变异自证**用 `behave -n "<场景名>"` 精确锁场景，不许拿全量跑当自证。

### 8.5 禁止动作
改任何文件（除你自己的探针/报告/台账回填）；读 `.env`/私钥/令牌；`git reset --hard` / `push --force` / `rm -rf`；物理删业务数据；跳过现场恢复。

### 8.6 误报防护（**先读 §12 再定性**）
凡要判为缺陷，先确认它不是：① 产品/甲方的**有意裁定**（§12）；② 已在**待拍板清单**登记的事项；③ 外部条件限制（真通道未验收）。
**口径类**问题必须先读 PRD 与 `docs/09` 的裁定记录——本项目很多"看起来怪"的行为是刻意的。
