### WM10-F1【高·前端】退款中心三个待审列表加载失败被静默置空——「假空态」导致漏审

- **验收可见性**：**验收必撞（断网场景）**——DevTools 断网刷新退款中心，三个 tab
  显示"这里空空如也"无任何错误提示
- **证据**：`admin-web/src/pages/RefundCenter.tsx:88-89`：

```tsx
apiListWithdrawals().then(setWithdrawals).catch(() => setWithdrawals([]));   // 静默吞错
apiListTransfers().then(setTransfers).catch(() => setTransfers([]));
```

`ActivityManage.tsx:54` 同款。对照同文件 `:87` refunds 列表失败有 `message.error`。
- **现象与根因**：待审列表请求失败 → 超管看到空列表以为无事可审 → **漏审资金申请**。
  与项目自己的 U10「禁假 0」原则（useTodoCounts.ts:2 注释）直接冲突——该原则只落地
  在徽标未覆盖列表。根因：catch 静默吞错模式。
- **修复方案**（参照项目内正确范式 Dashboard TodoCard「待办加载失败·点击重试」
  Dashboard.tsx:89-92）：

```tsx
// 三个列表各加 error state（或统一 loadError）：
const [withdrawalsError, setWithdrawalsError] = useState(false);
apiListWithdrawals()
  .then((v) => { setWithdrawals(v); setWithdrawalsError(false); })
  .catch(() => { setWithdrawalsError(true); message.error("退会待审列表加载失败"); });
// 渲染层：error 时显示错误态（Alert/重试按钮）而非 PaintEmpty
```

- **测试要求**：手动断网复核三个 tab 均出现错误提示（不再是空态）
- **验证等级**：A 级（tsc）
- **施工顺序**：与 HC-F3（假空态统一批）、HC-F1（审核/执行弹窗防双击）同文件同批
- **标注**：【事实】

### WM10-F5【中】小程序退款/退会申请 reason 无长度约束：>200 字触发 500

- **证据**【事实】：`backend/domain/identity/miniapp_router.py:32-40`：

```text

    child_id: int
    order_id: int
```

落库列 `RefundRequest.reason = Column(String(200))`（identity/models.py:178），
写入点 wm10_service.py:167 `reason=reason.strip()`。>200 字 → MySQL 严格模式

含申请原因原文）。admin 侧同字段有 `min_length=1, max_length=200` 标准
（admin/schemas.py:17）。

```text
class RefundApplyRequest(BaseSchema):

    order_id: int
    reason: str = Field(..., min_length=1, max_length=200)

class WithdrawalApplyRequest(BaseSchema):
    child_id: int
    reason: str = Field(..., min_length=1, max_length=200)
```

  （TransferApplyRequest 同型核对，有则一并补。）
- **测试要求**：`POST /api/miniapp/refund-requests` 传 300 字 reason 断言 422；
  空 reason 断言 422；正常 200
- **验证等级**：B 级（identity 域）
- **标注**：【事实】
