## 四、遗留与盲区（如实）

1. **🔴🔴 专家审查已回，19 个问题（`docs/审查报告-WM12-2026-10-09.md`）——结论：当前代码不能开启真实收退款。** 批次一（下次 push 前必须，均含单测判据）：
   - **P0-1 退款网关异常被记 `failed` → 管理员重试换新 `out_refund_no` → 可二次出款，且对账看不见**（`refund_online.py` Phase 2/3；专家探针复现状态落点）。链路的可怕之处：迟到的成功通知会把单子推成已退款，第二笔的成功通知被「已退款」守卫忽略 → **钱出两笔、本地只记一笔、无差异记录**。修法：异常保持 `PROCESSING` + 禁未知态重提 + 对账增加「每单退款合计不得超付」；**依赖网关新增 `query_refund` 查单方法（未实现）**。
   - **P0-4 短信验证码校验是「读-改-写」非原子**：20 并发错误码全被处理、库内 `attempts` 只记到 4（上限 5）；配 `X-Forwarded-For` 可绕过登录限流（**P1-5**）。修法：条件更新计数 + XFF 信任收敛（同步 `docs/20` 网关要求）。
   - **P0-2 对账（我们唯一的「漏退/多退」探测器）本身不可信**：跨日退款产生假差异、商品名含逗号会读错列、哈希校验失败被记成 `skipped` 而非 `failed`。
   - **P0-3 线下手机号登录（短信兜底）的家长无法线上支付**（`POST /pay` 返回 422「未取到微信标识」）——**需产品决策**（§五.1）。
   - **P1**：P1-6 `DEBUG=true` 整体绕过 `validate_production`；P1-7 退款回调不校验退款金额。
   - **P2 八项**：退款列表 N+1（200 行上限推算 ≈401 SQL）、对账 L1/L3 的 N+1 与无界查询、订单页支付按钮无重入保护、对账读权限前后端不一致、退款回调对非法状态抛异常会引微信无限重试、支付回调流水号查重在锁外（有 DB 兜底）、`simulate_callback` 对非法金额返 500 等。
   - **P3 四项**：文档漂移；**我改的门禁脚本其实是「放宽」不是「收紧」**（红线 69）；`pay_v3.py`「死代码」说法需修正（包级 `__init__` 有副作用导入、无业务调用）。
   - **未验证（报告 §五，17 条）**：真微信超时语义、真实账单列序/编码（需甲方导出一份放 `tests/fixtures/`）、docs/04 S5–S7 与双击、`DEBUG=true` 启动行为、三位小数舍入等。
