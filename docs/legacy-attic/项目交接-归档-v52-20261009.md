## 三、口径与规范变更（**压缩后理解冲突高发区**）

1. **网关异常 = 未知态**（不是失败）：保持 `processing` + `gateway_unknown_at`，未查单确认前**禁止重提**；只有"查无此单"才允许重试（会换新 `out_refund_no`）。
2. **`skipped` 是白名单**：只有"未开通道""当日无账单"两种；文件不可信（哈希/签名/缺列/解析失败）一律 `failed`。
3. **对账兜底"合计不超付"**：同一订单活跃退款（approved/processing/refunded）合计、同一孩子押金退款合计，超已付必报。
4. **线上支付 = 已绑微信的家长**：判据是 `parents.wechat_openid` 非空（走过微信一键登录）；其他登录态小程序不显示支付入口，服务端 422 兜底；**不做**短信登录补绑 openid 的路径。
5. **生产校验开关是 `APP_ENV`**（`production`），不是 `DEBUG`。
6. **限流默认不读 XFF**；反代后由 `TRUSTED_PROXY_COUNT` 显式声明信任层数（右起第 N 段），与 nginx 覆盖式 `proxy_set_header` 成对。
7. **回调"永久性不一致"不返 5xx**：金额不符 → 400 + 审计（拒绝落终态）；状态不可推进 → 200 + 审计（阻止 24h 重发）。
8. **退款回调金额必须核对**（`amount.refund` vs 申请金额）。
9. **同单并发 prepay 串行化**：前端忙标志 + 服务端进程内锁/短缓存；多 worker 下重复预支付不产生重复资金（商户订单号是微信侧交易幂等键）。
10. **对账读权限与后端同码**（`dashboard.view`），跑一轮超管。

## 八、本轮新增防复发红线（**71~76**，接 v51 的 65~70）

71. **网关异常 ≠ 失败**：调用超时/异常一律按"未知态"处理（保持执行中 + 标记 + 禁止重提），只有查单确认未受理才允许重试——换新幂等键重试是二次出款的入口。
72. **`skipped` 只能是白名单**：对账/体检类"跳过"必须限定在"未配置/无数据"两种明确原因；文件不可信（哈希/签名/解析）一律 `failed`，否则运营把"跳过"读成"没问题"。
73. **校验必须原子**：任何"读-判断-写"的计数/一次性消费都要改成带条件的 UPDATE + `rowcount`；并发测试（≥20 线程）是这类修复的验收判据，不是可选项。
74. **一个开关不许关掉全部红线**：生产校验的判定开关必须独立（`APP_ENV`），不得复用 `DEBUG` 之类会同时影响行为的变量。
75. **代理头默认不信任**：`X-Forwarded-For` 只在显式声明信任层数时读取，且取右起第 N 段；与网关配置必须成对（配一半等于没配）。
76. **回调的"永久性不一致"不返 5xx**：状态不可推进/唯一索引冲突 → 200 + 审计（重试不会自愈，只会让微信重发 24h）；金额不符 → 拒绝落终态 + 审计。
