# A. 专家复审问题清单

> 本清单保留给开发模型理解"为什么要这样修"。

## EXP-P0-01：R-225 权益转让状态机不完整

缺：申请状态机 / 审核超时 / 家长撤销 / 审核通过时二次校验 / 锁定完整范围 / 大孩押金退款联动 / 已退会二孩如何受让 / 大孩可否重新入会 / 转让期间可否新购订单 / 转让后大孩成就数据展示。

风险：转让审核期间大孩又购买年费；转让通过后押金无人处理；转让锁定不完整导致资金/借阅状态变化；二孩继承会员后大孩仍可退款。

对应修正：R-301 / R-302 / R-303 / R-304 / R-305。

## EXP-P0-02：R-223 等级体系不能仅靠唯一约束开发

缺：初始等级 / 等级进度流水 / 第 100 本计入哪级 / Z 级封顶 / 配置变更重算 / 人工调整 / 升级通知 / 展示字段。

风险：同一本书既算 A 级第 100 本又算 B 级第 1 本；配置调低后无法重算；Z 级后继续升级；后台可随意改等级。

对应修正：R-306 / R-307。

## EXP-P0-03：用户端退款与退会流程联动不完整

缺：退款申请状态机 / 拒绝后订单状态 / 用户撤销 / 可退金额为 0 是否允许提交 / 会员费退款成功是否自动退会 / 退款申请期间是否锁定借书 / 押金如何被触发退款 / 活动费退款校验 / 99 元退款中资格。

对应修正：R-308 / R-309 / R-310 / R-321。

## EXP-P0-04：退会申请状态机缺失

V1.0 多处引用退会（押金退款走退会 / 转让后大孩走退会 / 退会中冻结 Quiz）但未定义：家长端可否发起 / 状态机 / 锁定范围 / 审核权限 / 审核失败处理 / 退会完成后押金处理。

对应修正：R-311。

## EXP-P0-05：押金补缴模型不完整

缺：补缴订单类型 / 金额公式 / 支付状态 / 补缴后押金状态 / 流水 / 退款时退哪个金额。

对应修正：R-312。

## EXP-P0-06：未缴费权限矩阵有缺口，且未缴费线下借书风险高

缺：总榜 / 报告 / 积分明细 / 生词本 / 查词 / 收藏夹 / 押金补缴 / 权益转让 / 档案删除 / 退款申请。
V1.0 写"未缴费线下借书软提示可放行"→ 只付 99 元未入会未缴押金的孩子可借走实体书，遗失无押金保障。

对应修正：R-313。

## EXP-P0-07：收藏夹只有术语，没有功能规则

缺：收藏入口 / 列表 / 取消 / 是否按学生 / 未缴费可否 / 下架后展示 / 分页 / 是否影响额度。

对应修正：R-314。

## EXP-P0-08：孩子档案删除被引用但未定义

缺：谁能删 / 前置条件 / 软删还是物理删 / 删后展示 / 能否重建。

对应修正：R-315。

## EXP-P0-09：封面格式扩展后资源路径冲突

封面扩为 JPG/JPEG/PNG/WebP，但路径固定 `.jpg`，PNG/WebP 会造成格式与扩展名不一致。

对应修正：R-316。

## EXP-P0-10：总榜展示范围不完整

缺：未缴费是否可见 / 退会展示文案 / 可否点击详情 / 软删是否展示 / 超管可否隐藏个别记录。

对应修正：R-317。

## EXP-P0-11：进步榜表述有歧义

"负增量且 <100 词不上榜"可被理解为：负增量绝对值大于 100 是否上榜？正增量小于 100 是否上榜？零增量是否上榜？

对应修正：R-318。

## EXP-P0-12：新增功能未同步通知、定时任务、SystemConfig

新增（评估报告/转让/用户端退款/补缴/等级/收藏夹/活动取消审核/99 元待安排）未同步补通知场景、定时任务、配置项、数据模型。

对应修正：R-319 / R-320 / R-321 / R-322 / R-323。

# B. V1.0.1 正式修正规则

# R-300：开发执行总原则

```text
1. 开发模型必须先阅读问题清单，再阅读修正规则。
2. 禁止绕过状态机直接修改状态。
3. 禁止物理删除业务主数据。
4. 禁止在资金、押金、退款、赔偿场景使用浮点数。
5. 所有人工审核、人工放行、人工调整必须记录操作人、时间、原因。
6. 所有线上自助操作必须硬校验，不允许人工放行。
7. 所有状态变更必须写入对应日志。
8. 所有可配置数值必须进入 SystemConfig。
9. 所有跨模块联动必须使用事务或事件保证最终一致。
10. 本文件未覆盖的边界，不得擅自推导，必须提交需求确认。
```

# R-301：会员状态机补充

```text
新增状态转换：
withdrawn → observation（重新入会观察期订单支付确认成功）
withdrawn → formal（重新入会年费订单支付确认成功，或权益转让审核通过[受让方]）

规则：
1. 已退会学生可以重新入会。
2. 重新入会不清空历史数据。
3. 历史有效词数、积分、等级、打卡、Quiz、借阅记录保留。
4. 重新入会后生成新的会员有效期。
5. 重新入会订单按既有价格与折扣规则判断。
```

# R-302：权益转让申请状态机

```text
实体：membership_transfer_request
状态：pending_review / approved / rejected / cancelled / expired
流转：pending_review → approved | rejected | cancelled | expired
禁止：approved 后不可回退；rejected/cancelled/expired 后不可恢复。
转让记录禁止物理删除。
```

# R-303：权益转让发起条件

```text
发起入口：家长小程序
16 项条件（转出方 formal + 剩余天数>0 + 无借阅/逾期/遗失/损坏/赔偿 +
无进行中退会/退款/转让 + 受让方 none 或 withdrawn + 无进行中流程 + 双方未锁定）。
任一不满足：申请不可提交，前端展示具体失败原因。
```

# R-304：权益转让锁定规则

```text
锁定期间禁止：借书/预约/续借/退款申请/退会申请/孩子档案删除/
创建观察期订单/创建年费订单/创建押金补缴订单/发起新转让/成为其他转让受让方/人工修改会员到期日。
锁定期间允许：查看书目/收藏夹/报告/护照历史/排行榜历史/积分明细/归还已借图书（前置条件已保证不应发生）。
锁定解除：审核拒绝/用户撤销/审核超时/审核通过后转入退会-受让流程。
```

# R-305：权益转让审核与通过事务

```text
审核权限：仅超级管理员。
审核超时：默认 72 小时（transfer_review_timeout_hours），超时 expired + 解锁 + 通知。
家长撤销：pending_review 状态可撤销 → cancelled + 解锁。
审核通过时二次校验 6 项（转出方仍 formal/剩余天数>0/前置条件/受让条件/双方锁定中/申请 pending_review）。

审核通过后同一事务 12 步：
1. 转让申请 = approved
2. 转出方会员状态 = withdrawn
3. 转出方退会原因 = membership_transfer
4. 转出方生成退会记录
5. 转出方年费不退款
6. 转出方押金自动生成押金退款申请
7. 受让方会员状态 = formal
8. 受让方会员开始日 = 转让审核通过日
9. 受让方会员到期日 = 转出方原会员到期日
10. 生成转让记录
11. 解除双方转让锁定
12. 通知家长

押金退款规则：进超管审核；校验失败则挂起提示超管人工处理。
转让后：转出方成就数据保留、护照只读、可重新入会；受让方不继承成就、借书需自行满足押金规则。
```

# R-306：阅读等级体系工程化规则

```text
实体：student_level（level_code/level_progress/total_effective_books/is_max_level）
流水：level_progress_ledger（含 level_at_entry/progress_after，unique(student_id, book_id)）
初始：新学生等级 = A，progress = 0。
计数触发：Quiz 首次 passed + 未退会 + word_count_ledger 入账成功。
同事务驱动：词数流水/积分折算/等级流水/等级更新/升级判定/升级通知。

等级进度规则：
1. 同一学生同一书目终身只计一次。
2. 重新借阅/重测通过/重置次数后重新通过：不重复计级。
3. 触发升级的那本书只计入升级前等级。
4. 升级后新等级进度从 0 开始。
5. 一本书不得同时计入两个等级。

升级：progress + 1 >= level_up_books → 升级 + 归零 + 通知。
Z 级：封顶不再升级；继续累计 total_effective_books；展示"当前等级 Z + 累计 N 本"。
人工调整：禁止直接改等级/进度；超管仅可基于流水触发重算；重算只升不降；记录原因。
```

# R-307：等级配置变更规则

```text
level_up_books 调低 → 全量重算（只升不降，幂等，可查询，记录日志）。
level_up_books 调高 → 不追溯降级；当前进度保留但不超过新阈值 - 1。
重算公式：new_level_index = floor(total_effective_books ÷ level_up_books)，最大 Z。
示例：100 本 → B；2500 本 → Z。
```

# R-308：用户端退款申请状态机

```text
实体：refund_request
状态：pending / approved / rejected / processing / refunded / failed / cancelled
订单新增 refund_status 字段：none/pending/approved/processing/refunded/failed/rejected
流转：pending→approved|rejected|cancelled；approved→processing；processing→refunded|failed；failed→processing

提交规则：家长端提交/必填原因/金额服务端计算/可退为 0 不允许提交/
同一订单 pending|approved|processing 期间不可重复提交/拒绝后可再申请/pending 可撤销。
审核权限：仅超级管理员。
审核拒绝：必填原因，用户可见；订单 refund_status=rejected 仍为 paid；会员权益恢复，锁定解除。
```

# R-309：退款申请期间锁定规则

```text
first_activity_fee / activity_fee：不锁定会员权益。
活动费退款校验：未签到/活动未开始或符合协商/开始前 2 小时内不可线上申请/已签到不可申请/取消按 R-226。

observation_fee / formal_fee：退款申请本质=退会申请，同时创建 refund_request + withdrawal_request。
发起后退会锁定：禁借书/预约/续借/开始新 Quiz/提交新 Quiz/权益转让/档案删除/新会员订单/押金补缴。
允许：还书/查看历史/查看退款进度/处理未结赔偿。
已开始未提交 Quiz 会话作废；已提交成绩保留；已入账词数保留。
```

# R-310：会员费退款成功后的退会联动

```text
退款成功前再校验 6 项（无借阅中/逾期/未处理遗失/未处理损坏/待结清赔偿/进行中转让）。
校验失败：退款不能执行，提示超管先处理线下异常。
校验通过：执行退款 → withdrawn（原因 user_refund）→ 自动生成押金退款申请 → 超管审核 → 退可用余额。

特殊规则：观察期到期进入待评估后观察期费可退为 0，不允许提交 0 元申请，应走退会流程。
```

# R-311：退会申请正式规则

```text
实体：withdrawal_request
状态：applying / pending_settle / refunding / completed / rejected / cancelled
流转：applying→pending_settle|rejected|cancelled；pending_settle→refunding；refunding→completed|pending_settle（退款失败人工处理）

提交校验 7 项：无借阅中/逾期/未处理遗失/未处理损坏/待结清赔偿/进行中转让/进行中会员费退款。
锁定范围：同 R-309 会员费退款锁定。
审核权限：仅超级管理员。
审核通过：计算三类可退金额 → 生成退款单 → 退款流程 → 全部成功后 withdrawn + completed。
退会后：无任何会员权益/不可音频/不可 Quiz/不再新增词数积分/周期榜不展示/总榜按 R-317/历史数据保留。
```

# R-312：押金补缴正式规则

```text
订单类型：deposit_supplement
入口：家长端押金页
条件：押金 partially_deducted 或 fully_deducted + 未退会 + 可用余额 < deposit_amount + 无进行中补缴单。
金额：补缴金额 = deposit_amount - available_amount
状态：复用订单状态机。
补缴成功：available_amount = deposit_amount；deducted_amount 保留历史；supplemented_total 累加；状态 = paid；生成流水+通知。
押金退款：退 available_amount，不退 deducted_amount。
补缴不触发会员状态变化。
```

# R-314：收藏夹功能正式规则

```text
收藏对象：学生 × 书目。数量不限。unique(student_id, book_id)。
收藏不影响额度/不产生权益/不与借阅联动。列表按时间倒序分页。
权限：未缴费可收藏；在册/过期可收藏；退会只读。
书目下架：仍展示标注"已下架"；不可借/约/听。
```

# R-315：孩子档案删除本期不开放

```text
1. 家长端无删除入口。
2. 运营专员无常规删除入口。
3. 仅超管可因数据修复软删除（必填原因）。
4. 软删除前提：无未结资金/借阅/赔偿/转让/退款/退会流程。
5. 财务、订单、退款、押金、赔偿、转让记录永久保留。
6. 软删除学生不展示在排行榜与总榜。
7. 软删除不可恢复（除超管数据修复）。
V1.0 所有"删除锁定"保留为未来预留；R-223 级联删除本期不启用。
```

# R-316：封面资源路径修正

```text
封面支持 JPG/JPEG/PNG/WebP，服务端统一转 JPG 存储：
cover/{isbn前4位}/{isbn13}.jpg
无 ISBN：cover/local/{internal_code}.jpg
转换失败=上传失败；重复上传直接覆盖。
音频仅 MP3：book_audio/{isbn13}/audio.mp3（无 ISBN 用 internal_code）。
```

# R-317：总榜展示正式规则

```text
定位：历史荣誉榜。
范围：曾产生有效词数的学生；过期可展示；退会可展示（历史学员）；未缴费不展示；软删除不展示。
字段：英文名/昵称 + 头像 + 词数 + 状态标签（在册/已过期/历史学员）。
```

> 本附录为架构师对 V1.0.1 的评估记录，非专家原文。

## 一、12 个问题逐条核实：全部属实

对照 V1.0 原文逐一复核，EXP-P0-01~12 无一虚报。其中 EXP-P0-06 是对 V1.0 R-221 的**实质纠错**（未缴费线下借书软提示放行是我方错误——未入会+未缴押金用户无信用基础，不适用全局放行原则；该原则只覆盖"会员体系内异常"，不覆盖"无会员身份"）。

## 二、关键数学/逻辑验证（已人工核算）

1. **R-307 重算公式与 R-306 每级独立计数数学等价**：读 N 本、阈值 K → 等级索引 = floor(N/K)，当前级进度 = N mod K。与"每级归零累计"完全一致。
2. **R-309 与 R-310 自洽**：会员费退款=退会申请（同时创建两实体）、锁定范围与 R-311 退会锁定一致。
3. **R-305 转让事务 12 步闭环**：押金自动生成退款申请 + 前置校验保证押金可退（转让条件已排除借阅/赔偿）。

## 三、V1.0.1 自身的 3 处措辞级缺口（建议随采纳一并修正）

| M2 | R-310 | "退款申请状态保持 approved 或进入 failed"的"或"表述开发无法执行 | 明确：校验失败 → 保持 approved 不流转，生成超管待办；failed 仅用于网关退款失败（processing→failed） |

## 五、M1-M3 措辞修正（随采纳生效，2026-08-21 终裁）

1. **M1**（R-308 补）：用户撤销退款申请后，解除全部锁定，订单 refund_status 回 none。
2. **M2**（R-310 修正）："保持 approved 或进入 failed"明确为——退款执行前校验失败 → 申请保持 approved 不流转，生成超管待办，处理线下异常后重新执行；failed 仅用于网关退款失败（processing → failed）。
3. **M3**（R-313 补）："未缴费用户"判定口径 ≡ member_status = none（按订单判定与状态机判定对齐）；仅缴押金未入会学生仍属未缴费/未入会，押金缴纳状态不影响该判定。
