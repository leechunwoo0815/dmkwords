# 任务包 2026-09-20｜活动模块重构（签到码搬家 + 图文详情 + 往期回顾）

> 来源：客户新需求（用户 2026-09-20 转述）+ 用户五项拍板。施工方 = 开发大模型；验收方 = 用户（甲方）。
> 本文件是**自包含施工说明**：开工读本文件 + `CLAUDE.md`（宪法）+ `docs/19`（门禁后恢复）即可。

## 一、需求（客户原话口径）

1. **签到码不该出现在活动详情页**：应在「已报名的活动」那边，每个已报名活动加一个按钮，点了才显示签到码/二维码。
2. **活动详情页要能放"像公众号一样"的图文**：除了活动简介与费用，下方要有丰富的文字与图片信息，用来吸引人报名。
3. **已结束的活动进「往期活动回顾」**：小程序里能查看往期活动的回顾内容。

## 二、用户拍板（**终局，不可重问**）

| # | 决策 | 选定 |
|---|---|---|
| 1 | 图文详情的形态 | **结构化图块**（段落块 / 图片块，管理端增删排序；小程序 `wx:for` 渲染 + 点击大图预览）。不引入富文本编辑器、不引第三方渲染库、不做 HTML |
| 2 | 签到码的交互 | **独立「我的入场券」页**（从列表按钮跳入；亮度/常亮逻辑随页面生命周期） |
| 3 | 「我的报名」列表补什么 | **出示签到码 + 进入活动详情**两个入口（取消/退款仍在详情页做） |
| 4 | 往期回顾的内容模型 | **复用同一份图文 + 现场照片图集**（同一编辑区维护；活动结束后放行编辑） |
| 5 | 照片合规口径 | **只放不含可辨识孩子的图**（场景 / 物品 / 背影 / 马赛克）。**绝不涉及任何孩子的隐私**——这条是硬约束，见 §五 红线 R3 |

### 两个存量盲区（本批顺手收口）

- **黑洞活动**：有人报名但未签到的活动过期后，既不在「可报名」（时间过滤掉了）**也不会变成 finished**（活跃报名数 ≠ 0）→ 家长与管理端都看不到它的入口。**往期列表按「时间已过」取数即可覆盖**（而非 `status=finished`）。
- **待收款也能出示二维码**：现在只要 `my_enrollment` 存在就显示码，而 `pending_payment`（待馆员确认收款）时码尚无意义（报名成功弹窗自己写的是"确认收款后入场券生效"）。A 批一并收口：**仅 `enrolled` / `checked_in` 可出示**。

## 五、纪律红线（本批特有，其余照 `CLAUDE.md`）

- **R1 媒体引用集同步**：任何新增的图片落盘路径，必须同步进 `cleanup_uploads.py` 的引用集；
  否则跑清理脚本会把新图当孤儿删掉（`cover/` 在白名单"可再生目录"里，是上一次同类事故的形状）。
- **R2 编辑约束放行要显式**：`admin_service.py:76-79` 的"已开始/非 published 不可编辑"是资金与报名安全相关约束，
  只放行**纯展示字段**（图文 / 照片），不得顺手放宽时间、名额、费用等字段。
- **R3 照片合规（客户口径）**：往期照片**只放不含可辨识孩子的图**（场景 / 物品 / 背影 / 马赛克）。
  运营上传前自查；管理端在图文编辑区写明该口径。**任何含孩子正面/可辨识形象的图不得入库**——
  这是未成年肖像权与微信审核红线，不是审美问题。
- **R4 视觉先出样稿**：B 批渲染样式先出 1 场样稿经用户目视，再批量（视觉资产设样图门的既有纪律）。
- **R5 门禁**：小程序批（A/C）→ `check_miniapp_style` + `check_miniapp_bindings` + `check_docs_code_alignment` +
  模拟器截图；动后端与门禁的（B/C）→ **C 级全量 `bash scripts/gate.sh full`**；门禁后按 `docs/19` 恢复现场。
