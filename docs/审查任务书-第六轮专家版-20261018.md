## 1. 项目背景（自包含）

**DmkWords**：儿童英语分级阅读系统的门店运营平台。四类角色：超级管理员（店主）、会员运营专员（馆员）、家长（小程序主体）、孩子（**无独立账号**）。

**形态**：微信小程序（家长端 33 页）＋ 管理后台（React 18 + TS + Vite + Ant Design，18 页）＋ FastAPI 后端（179 文件 / 约 3.3 万行 / 9 域）＋ MySQL 8（OrbStack 容器 `dmkwords-mysql:3306`，**无 Redis**，缓存=进程内 `ConfigService` 60s TTL）。

**业务主线**：馆员建档 → 家长微信/短信登录 → 缴押金 → 观察期会员（500/月）→ 借书（30 天）→ 听音频/读 → 测验 → 词数/积分/等级/勋章 → 预约/续借/逾期 → 活动报名/签到 → 退款/退会/权益转让（严格审核流）→ 对账。**一切金额与阈值走配置中心**。

**规模实取（2026-10-18）**：接口 **194** · 表 **42** · 迁移 **35** · 定时任务 **21** · 配置键 **58** · 管理端**待办场景** 20+ · BDD **243 场景 / 936 步**（另有 100 skipped = 未解封 @draft）· 单测 **134 文件 / 861+ 用例 / 覆盖率 ~89%** · 文档 41 份（含 PRD 定稿 V1.1、`docs/03` Feature 全量清单 90 项、`docs/04` 手动验收手册 S1–S151、`docs/18` API 规范、`docs/19` 门禁后现场恢复、`docs/20` 生产部署、`docs/21` 微信与支付配置）。

**外部通道**：微信登录（code2session）、微信支付 V3、微信订阅消息、短信（阿里云/腾讯，开发态 mock）。**真通道尚未验收**（外部条件）。

## 2. 判据：本项目认为"什么才算缺陷"

审查必须先读这三处，否则会把**有意的设计**当成 bug（见 §10 防误报白名单）：

1. **`CLAUDE.md`（项目宪法，最高法律）**：§一 铁律（零容忍）· §二 业务红线（甲方终裁）· §三 分层架构（Router→Service→Repository→Model，Router 零 ORM/try/HTTPException）· §四 九域边界 · §五 前端宪法 · §六 开发流程铁律（含 DoD：门禁全量、门禁后现场恢复、用户验收前不 commit/push）· **§八 验证与门禁（A/B/C/D 分级）**。
2. **`docs/LEDGER.md`（唯一进度事实源）** 与 **`docs/项目交接-20260824.md` 顶部 v96**（当前状态 / 红线 1–182 / 口径 13 条 / 未解封清单）。
3. **红线家族（判缺陷的尺子，摘要）**：
   - 资金：金额一律 `Decimal`；台账记**实际发生额**且 `Σ入账−Σ出账=余额`；押金本金=**订单实收**；重复缴纳判据=**本账户已有本金**；押金每条终态都要有回退边。
   - 并发：全局锁序 **`Child → Reservation → copy`**；`with_for_update()` **必链 `.populate_existing()`**；**查重后插入必须锁主体行**；条件 UPDATE 防"覆盖已审结"。
   - 幂等：管理待办去重键 `(scene, ref_type, ref_id, dedup_key, is_deleted)`；家长通知 `(parent_id, scene, ref_type, ref_id, dedup_key, is_deleted)`；**`INSERT IGNORE` 预检的过滤列必须与唯一索引逐列一致**；**周期类场景的去重键必须带周期**（否则第二周期永久静默）。
   - 状态：状态机只能走 `ALLOWED_TRANSITIONS`；**状态写口必须收拢**（如 `Child.set_member_status`）；**状态时钟要有专属落库字段**（如 `pending_evaluation_at`，禁止挂 `update_time`）；终态不可被改写。
   - 门禁与自证：**门禁必须按视角分别断言**（并集判定=假绿温床）；**检查器的自述必须与实现一致**；**变异自证是唯一有效证据**，且必须打在对准的分支上；**红/绿必须来自"真的执行过"**（`hook_error`/0 匹配/全量 skipped ⇒ 无效）。
   - 数据：业务主数据**禁物理删除**（软删）；全局唯一索引 × 软删（同号**复活**或**如实报错**，不许裸 500）；派生码唯一冲突转 **409**；多文件上传**先全量校验再落盘**；受保护目录 + 路径判定必须用 `is_within`（**禁止裸 `startswith(root)`**，且要 `isfile`）。
   - 前端：错误态**不许伪装成 0/空**；分母/阈值由**服务端下发快照**；权限三方一致（前端路由/按钮 ↔ 后端 `require_perm` ↔ 菜单）；`pnpm exec tsc --noEmit` 必须 0 错。
   - 运维：进程时区在启动脚本**钉死**；生产配置 fail-closed 自检（空密钥/固定验证码/mock 支付或短信 → 拒绝启动）。

## 7. 方法协议（**必须遵守**）

### 7.1 证据三态（标签不许混用）
- `实测✓`：你**亲眼看到**的输出（探针/接口/日志/SQL 结果），必须附原始输出片段。
- `静态`：代码/文档通读成立，但**未构造出端到端复现**（要写清"为什么没复现"）。
- `未复现`：你**尝试复现但没成功**——这**不是**缺陷结论，要写清阻断了什么（例：被另一道守卫挡住）。

### 7.3 独立性
不得把"上轮报告说已修"当作证据；你要**自己读代码 + 自己跑**。反过来，如果上轮报告**说的和你看到的相反**，那正是最高价值发现（第五轮逮到 4 处）。
