## 六、外部审查 P0+P1 修复记录（2026-08-29 二轮）

### P0（阻塞）：notifications.send 并发撞唯一索引会连坐回滚主事务
- **审查发现**：原实现 `flush()` 撞唯一索引后 `self.db.rollback()`——EventBus 同步
  共享事务下会撤销主业务未 commit 的写入（如订单 paid）。
- **修复**：改用 **MySQL `INSERT IGNORE`**（宪法 MySQL-only）幂等写入——撞唯一约束
  静默忽略（rowcount=0）返回 False，零异常、零 ORM flush、不污染事务。曾尝试
  `begin_nested()` savepoint，但 SQLAlchemy flush 异常后 session 强制 PendingRollback
  （仍需整体 rollback），savepoint 方案不可行——INSERT IGNORE 是唯一既保留
  唯一索引防线又不碰主事务的 MySQL 原生方案。
- **测试**：`test_send_integrity_error_keeps_pending_main_write`（mock count 返回 0
  强制走冲突分支 → 断言主事务待写入家长仍持久化、未重复插入）。

### P1-1：直改 DB 造状态处加注释
- 5 处"定时任务造历史态无 API 路径，有意直改"显式标注（test_wm11_tasks.py）。

### P1-2：补专门测试 + 补课清单
- 新增 `test_transfer_expire_check_unlocks_both_sides`（转让超时 → expired + 双方
  解锁 + 幂等重跑零副作用）。
- 预约释放已有专门测试（test_reservation_expire_check_releases_copy_and_notifies）。
- **WM12 前补课清单**：逾期标记 / 活动自动结束 / 99 元 90 天提醒 三个任务补边界专项
  （当前已有主路径测试，补课=异常分支参数化）。
- **INSERT IGNORE 注意**（外部审查非阻塞记录）：INSERT IGNORE 会吞掉**所有**错误
  而非仅唯一约束冲突——当前 values 全部服务端构造（无用户输入/触发器），无风险；
  **通知表后续新增任何约束时，必须回归 test_send_integrity_error_keeps_pending_main_write**，
  确认非唯一类冲突未被静默吞掉。
