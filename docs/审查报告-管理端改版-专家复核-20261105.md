## 2. 缺陷清单（P1 / P2）

> 字段口径沿用本项目体例：现象 / 位置 / 证据 / 复现 / 影响 / 建议 / 守护 / 置信度。

### P1-1 「健康度」半圆仪表阈值**语义反向**，且与自身副标题矛盾

- **现象**：三个仪表共用一套"越高越绿"阈值，但其中「退会率」是**越低越好**。同时卡片副标题写「优秀：续借≥60% · 通过≥80% · 退会≤10%」，代码却要 ≥80 才绿。
- **位置**：`components/DashboardCharts.tsx:184-186`（`const color = pct>=80 ? success : pct>=50 ? warning : danger`）、`:463-467`（三个 `<Gauge>` 调用）、`:460`（副标题阈值）。
- **证据**：`静态`（代码直读，无需运行时）：
  ```bash
  grep -n "pct >= 80\|优秀：" admin-web/src/components/DashboardCharts.tsx
  # 184: const color = pct >= 80 ? ... : pct >= 50 ? ... : danger
  # 460: 优秀：续借≥60% · 通过≥80% · 退会≤10%
  ```
  由此外推（可判定）：退会率 **5%（优秀）→ 红色危险**；**90%（灾难）→ 绿色良好**；续借率 **60%（副标题称优秀）→ 黄色警示**。S445/S453 与 docs/31 §8.7 B 都写「≥80 绿 / ≥50 黄 / <50 红」，即**文档与代码一致地错了**。
- **影响**：仪表盘明确要"投到店外电视上"，管理员/店长会据颜色判断经营健康度；这是**唯一一条会直接导致错误经营判断**的问题。
- **建议**：`Gauge` 增加 `direction: "higher-better" | "lower-better"` 与每指标阈值（续借 ≥60 绿、通过 ≥80 绿、退会 ≤10 绿 / >20 红），或至少让阈值表与副标题同源（抽一个 `GAUGE_RULES` 常量，副标题由它生成）。
- **守护**：加一个纯函数 `gaugeTone(metric, value)` + 单测，覆盖 `{renew:60→success, quiz:80→success, withdrawal:5→success, withdrawal:90→danger}`；再给三个仪表加 `data-tone` 供快照断言。
- **置信度**：**高**（静态可完全判定；文档与代码双向印证）。

- **位置**：各页 `columns` 列宽与 `scroll.x`。
- **证据**：`实测✓` 无头 Chrome 1366×768、admin 登录、企业风，测 `.ant-table-body.scrollWidth - clientWidth`：

  | 页面 | 企业风 | 绘本风 | 深色 |

  | 阅读圈 `/circle` | 44 | – | – |
  | 通知中心 `/notifications` | 36 | – | – |

- **影响**：S458「1366 无横向滚动」、S461「操作列固定在右」、S465「1366 下表格无横向滚动」按清单验收会不通过；退款中心 313px 意味着几乎一半表格内容要横滚才能看到。
- **建议**：**先定口径**——antd 宽表格允许内部横滚是正常设计（docs/31 §8.3 自己也这么写），那就把 S458/S465 改为「页面级无横滚；宽表格内部允许横滚且操作列固定可见」，并把 7 页实测值写进 docs/33；**再修真问题**——退款中心 313px 与配置页 55/85/90px 按图书页的列合并经验重排。两条路不要混着写。
- **守护**：把「页面级 `docOverflow===0` + 每页表格内溢出阈值」做成前端检查器或 CDP 快照，门禁第 [7] 步后跑。
- **置信度**：**高**（真实计算值，三主题 × 13 页）。

- **位置**：`pages/Dashboard.tsx:231-246`（`useEffect(load, [])` 仅挂载取一次）、`components/DashboardCharts.tsx:425-441`（独立 `setInterval(load, 60000)`）。

### P2-7 `buildAntdTheme` 注释说"不许写死颜色"，实际有 4 处飞书蓝硬编码

- **位置**：`theme/index.ts:223`（`controlOutline`）、`:336/:342/:354`（`activeShadow`），均为 `rgba(51, 112, 255, 0.12)`；另有 `:382` Tooltip 底色 `rgba(31,35,41,.92)`（antd 默认深底，可接受）。
- **证据**：`静态` 代码直读；`实测✓` 三主题输入框边框色确实随主题变（企业 `rgb(229,230,235)` / 绘本 `rgb(212,197,181)` / 深色 `rgb(42,50,60)`），但**焦点光圈探针未触发**（headless 下 `:focus-visible` 未激活，`boxShadow` 三主题均为 `rgba(0,0,0,0)`）→ **运行时影响标 `未复现`，不作为缺陷结论**。

- **建议**：改为 `c.primary` 派生的 rgba（或加一个 `primaryOutline` 令牌），并用真实用户键盘 Tab 触发焦点态复现一次。
- **置信度**：中（静态确定，运行时未复现）。

### P2-8 登录页无主题切换入口、无语义 h1

- **证据**：`实测✓` `/login` 页 `h1=0`、`.paint-header-theme=0`（`cdp3_result.json` / `cdp5`）。`App.tsx:60` 把 `/login` 放在 `Layout` 路由之外，`Layout` 里的 `<h1 className="sr-only">` 与顶栏主题按钮都不覆盖登录页。
- **影响**：① 未登录状态无法切换主题——S455「点 🎨 切绘本风 → 刷新后仍是绘本风 → 看登录页」实际需要**登录 → 切换 → 退出登录**三步，验收清单没写，甲方容易卡住；② docs/33 §三「每页 1 个语义化 h1」不成立；③ 读屏器进登录页无页面标题。
- **建议**：登录页加一个轻量主题切换（或至少加 `<h1 class="sr-only">`）；S455 补一步操作说明。
- **置信度**：高。

### P2-9 `fixed:"right"` 覆盖率与 docs/33 §三 不符

- **证据**：`静态` 15 个含 `<Table>` 的页面里，仅 8 个有 `fixed: "right"`；预约、审计、通知、阅读圈、任务看板、图书详情、借阅操作台等为 0。docs/33 §三 列「图书/会员/活动/退款/员工/押金/成长/系统配置/**预约**/**审计** 全部 `fixed:"right"`」。

- **建议**：先给有横滚的页面（预约、配置、退款中心）补 `fixed:"right"`，再把 §三 的"全部"改成实测清单。
- **置信度**：高。
