## 三、现状核查（代码事实，非文档转述）

### 3.1 三处与"扫码闭环"目标不符（自证结论）

1. **"自己预约的可以直接借"目前做不到**：`backend/domain/circulation/service.py:269` 对**任何**非 `available` 副本一律 `409`（文案"预约锁定请走预约核销"），**不比对 `reservation.child_id`**；唯一放行路径是 `预约管理 → 核销借出`，且只收 `reservation_id`（`backend/domain/reading/service.py:660`），没有按"孩子+书"反查的入口。
2. **"被他人锁定不能借"现状更严**：谁预约都锁；ISBN 路径挑副本时只挑 `available`（`service.py:82-91`），别人预约的那册被**静默跳过**（借走同书另一册），UI 完全看不到"该书有预约"。
3. **"扫书码自动判借/还"缺少判定入口**：借书端点接受 `isbn`/`copy_id`，还书端点**只接受 `copy_id`**（`backend/domain/circulation/router.py:120-127`）；前端现在是"在借表点还书 → 弹窗选状态"，没有扫码还书。且无任何端点接受 `copy_code`。

### 3.2 额度口径 bug（用户 2026-09-21 报障 → 复核为真，**误差是两个方向**）

| 位置 | 公式 | 偏差 |
|---|---|---|
| `backend/domain/circulation/service.py:69`（卡片显示） | `上限 − len(overdue) − len(active)`，而 `active` 已含逾期 | ① **每本逾期多扣 1**（`active` 里那本又被 `overdue` 减一次）→ 无预约时卡面比真值**少 1**；② **完全没减预约中** → 有预约时卡面**多报** |
| `backend/domain/circulation/service.py:259`（借书链） | `上限 − 在借(含逾期) − 预约` | 真值（与用户新口径一致） |

**两类误差在"1 本逾期 + 1 个预约"时正好抵消** —— 演示孩现场就是这种巧合（旧卡面 30−1−2=27，真值 30−2−1=27，
所以它的数字一直"看着对"）；而无预约、有 1 本逾期的孩子旧卡面给 28、真值 29（**这才是用户看到的"扣 2 本"**）。
→ 修复：卡面改用与借书链**同一公式**；PRD §5.4「每逾期 1 本上限减 1」的额外扣减**废止**（宪法 §二 借阅并发红线同步修订）；
回归锁 `tests/unit/test_borrow_quota_overdue.py`（含"卡面数字必须可兑现：显示可借 1 就真能借出来"与"预约占 1 个额度"两向断言）。

### 3.3 操作台交互现状（0/8 对齐本项目扫码标杆）

- 页面：`admin-web/src/pages/CirculationDesk.tsx`（265 行）；菜单 `admin-web/src/pages/Layout.tsx:104`（`borrow.operate`）
- **无 `autoFocus` / 无 `useRef` / 无 `.focus()`**；成功后仅 `setIsbn("")`，**不回焦**、无提示音、无最近操作列表、无 in-flight 锁（仅 `busy` state）、输入是**受控 state**（扫码枪高速输入有丢字符风险）
- 标杆：`admin-web/src/components/ScanCheckin.tsx`（活动扫码面板，已验收）——非受控 DOM 读值 + `busyRef` 防重 + **成败都回焦** + 就绪指示灯 + 提示音 + 最近 20 条列表

### 3.4 会员码能力现状

- `Child` 模型（`backend/domain/identity/models.py:24-102`）**无任何码字段**、无唯一索引；小程序孩子对象（`backend/domain/identity/auth.py:67-102`）只返回 `id/name/english_name/member_status/...`
- 已登记未实现：`docs/09:81` **C11「借阅台识别学生二维码」**（"三方式（二维码/姓名/手机号）现只有后两种"）；PRD §5.2:452 早已写"出示孩子的二维码（推荐）"；PRD §9.2.1 末尾预告"借阅是两个码（读者码+书码）……另立需求"

### 3.5 借还记录查询现状

- **管理端没有任何历史借阅查询端点**：只有 `children/{id}/card`（只返回 `ACTIVE+OVERDUE`）与 `circulation/overdue`（无分页/无筛选）

- 标准范式可抄：订单列表（`MemberManage.tsx:562-644` 筛选+分页+URL 镜像）、审计日志页+导出（`AuditLog.tsx`、`backend/domain/admin/service.py:574-615` openpyxl）

## 四、流程图

### 4.1 现状（代码实际路径）

```
点「借阅操作台」
   │  ❌ 光标不落任何框（需手点）
   ▼
[孩子姓名/家长手机号] ──回车──> 结果列表 ──点击──> 孩子卡片(在借/逾期/可借/押金)
   │                        ↑ 只搜 姓名/英文名/家长名/手机号（不认 id、不认码）
   ▼
[扫图书 ISBN 或手输] ──回车/点「借出」──> POST /circulation/borrow {child_id, isbn}
   │  锁孩子行 → 冻结? → 同书未还? → 定位副本(取第一个 available，预约册被静默跳过)
   │  → 会员态 → 押金 → 额度(上限−在借含逾期−预约) → 副本状态≠available 一律 409
   │  → AR 软提示 → 落库+审计
   │  ❌ 不回焦 / 无音 / 无最近操作
   ▼
还书：必须在卡片在借表点「还书」→ 弹窗选 正常归架/转维护/标记遗失 → POST /return {copy_id}
      ❌ 扫书码还不了（端点不认 ISBN / copy_code）
```

### 4.2 目标（改造后）

```
点「借阅操作台」 ──> 光标自动落 [扫会员码]（重试 3 次，抗布局抖动）
   ▼

   ▼

   ├─ 该副本被"当前孩子"有效预约锁定 ─────────────> 自动核销借出（拍板前是 409，本次打通）

   ▼

   ▼
```

## 五、本批红线

- **R1（文档先行）**：每刀必须先有文档改动（宪法 §六 前置铁律）；口径变更必须同时改 PRD 并注明修订日期。
- **R2（预约核销不破守卫）**：`borrow()` 对 `reserved` 的硬拒绝**保持不动**——扫码端点负责比对 `reservation.child_id` 后**分流到既有 `checkout()`**，不改既有不变量、不复制借书逻辑。
- **R3（会员码不可枚举）**：码由后端生成（前缀 + 校验位），禁止前端派生；码与 `child_id` 的映射只在服务端。
- **R4（额度单一口径）**：卡面与服务端必须同一公式（`上限 − 在借含逾期 − 预约`）；新增回归测试锁死"两处一致"。
- **R5（扫码交互对齐标杆）**：一律复用 `ScanCheckin` 的八项机制，抽 `ScanInput` 通用组件，**禁止写第二份扫码实现**。
