## 二、P0 必须修复（3 项）

### P0-1 CSS 变量 `--font-display` / `--font-body` 未定义

**位置**：`paint.css` L25-51（:root）缺少变量定义，但 L62、L452、L483 使用了它们。

**问题**：
```css
/* paint.css L62 */
body { font-family: var(--font-body); }

/* paint.css L452 */
h1, h2, ... { font-family: var(--font-display); }
```

但 `:root` 中只定义了颜色变量，**没有 `--font-display` 和 `--font-body`**。

**影响**：标题和 body 字体会回退到浏览器默认（通常是 Times/SimSun），而不是预期的 ZCOOL KuaiLe / Nunito。

**修复**：在 `:root` 中添加：
```css
:root {
  /* ...现有颜色变量... */
  --font-display: 'ZCOOL KuaiLe', 'Nunito', 'PingFang SC', 'Microsoft YaHei', sans-serif;
  --font-body: 'Nunito', 'PingFang SC', 'Microsoft YaHei', 'Helvetica Neue', system-ui, sans-serif;
}
```

### P0-2 表格行"卡片化" CSS 无效

**位置**：`paint.css` L298-325

**问题**：
```css
.ant-table-tbody > tr.ant-table-row {
  border: 2px solid var(--paint-ink) !important;
  border-radius: var(--paint-radius) !important;
  box-shadow: var(--paint-card-shadow) !important;
  margin-bottom: 10px !important;
  display: table-row;  /* ← 致命问题 */
}
```

`display: table-row` 的元素在 CSS 规范中**不支持** `border-radius`、`box-shadow`、`margin-bottom`。浏览器会直接忽略这些属性。

**实际效果**：表格行看起来和之前没有本质区别——没有圆角、没有阴影、没有间距，只是背景色变了。

**修复方案**（三选一）：

**方案 A（推荐，改动最小）**：放弃行级卡片化，改为标准表格但加粗横线分隔：
```css
.ant-table-tbody > tr.ant-table-row > td {
  border-bottom: 2px solid var(--paint-ink) !important;
}
```

**方案 B（视觉最佳，改动较大）**：把 Table 改为卡片列表（非 table 布局），每个数据项是一个独立 div 卡片。这需要重构 BookManage 等页面的渲染逻辑。

**方案 C（折中）**：保持 Table，但在每行的第一个和最后一个 td 上通过伪元素模拟圆角卡片效果（hack 较重，不推荐）。

### P0-3 全局 Empty 未按页面传角色

**位置**：`main.tsx:14`

**问题**：
```tsx
<ConfigProvider renderEmpty={() => <PaintEmpty />}>
```

没有传 `character` 参数，所有页面的空状态都显示 `default` 角色（简单笑脸），而不是我规范中建议的页面专属角色（图书管理 = 书虫贝贝、会员管理 = 星星点点等）。

**修复**：ConfigProvider 的 renderEmpty 无法接收页面上下文。需要改为：
1. 移除全局 `renderEmpty`；
2. 在各页面需要空状态的地方显式使用 `<PaintEmpty character="xxx" />`；
3. 或保持全局 renderEmpty 但接受一个默认角色，同时在各页面 Table 的 `locale={{ emptyText: <PaintEmpty character="xxx" /> }}` 中覆盖。

当前 MemberManage.tsx L547 已经用了第二种方式（显式覆盖），但其他页面没有。

## 五、覆盖遮挡检查

### 5.1 paint.css 的 `!important` 策略

paint.css 使用了大量 `!important`（约 60 处），这是有意为之的全局覆盖策略，但带来了以下风险：

| 场景 | 影响 | 评估 |
|---|---|---|
| `.ant-btn { border-radius: 999px !important }` | 所有按钮强制胶囊化 | ✅ 符合设计意图 |
| `.ant-tag { border-radius: 999px !important }` | 所有标签强制 pill 化 | ✅ 符合设计意图 |
| `.ant-card { border: 2px solid !important }` | 所有卡片强制粗边框 | ✅ 符合设计意图 |
| `.ant-table-tbody > tr > td { border-bottom: none !important }` | 表格行间横线消失 | ⚠️ 与卡片化意图配套，但若 P0-2 不修复则表格只剩色块 |
| `.ant-tabs-ink-bar { display: none !important }` | 下划线完全隐藏 | ⚠️ active 状态只靠背景色，对部分用户可能不够明显 |
| `html, body, #root, .ant-layout { background: !important }` | 全局底色强制覆盖 | ✅ 确保统一 |

### 5.2 表格行卡片化的 CSS 限制（重申 P0-2）

再次强调：`display: table-row` 不支持 `border-radius`、`box-shadow`、`margin`。

浏览器实际渲染结果：
- `border: 2px solid` ✅ 生效（table-row 支持 border）
- `border-radius` ❌ 被忽略
- `box-shadow` ❌ 被忽略
- `margin-bottom: 10px` ❌ 被忽略
- `transform: translateY(-2px)` ❌ 被忽略

所以当前表格行的实际效果是：**每行有粗黑边框，但仍然是直角、无阴影、无间距**，和"卡片"差距很大。
