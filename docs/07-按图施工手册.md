# docs/07-按图施工手册.md — 后续开发大模型施工标准

> **定位**：宪法（CLAUDE.md）管"什么不能做"，本手册管"怎么一步步做"。
> 全部内容从 WM2 标杆（2026-08-28 ACCEPTED，tag acceptance-baseline-wm3-wm10）提炼，
> 含三轮外部审查 + 33 项修复 + 40 个测试的实战经验。
> **每轮开工必读**：宪法 → 错误记忆库最新版 §二/§三 → LEDGER 取未闭环项 → 本手册对应章节。
> **冲突裁决**：宪法 > 本手册。本手册未覆盖的新场景，参照 WM2 同类实现 + 写入本手册沉淀。

---

## 〇、七步施工闭环（总流程图）

```
① 接任务包 → ② 拷问清单（开工前） → ③ RED→GREEN 施工
→ ④ 分级验证（A/B/C） → ⑤ 简报（贴原始证据） → ⑥ 外部复核（如实答查）
→ ⑦ push 授权 → 文档闭环（LEDGER/handoff/手册/错误记忆库）
```

**任何一步跳过 = 返工**。WM2 三轮修复中所有返工（门禁证据缺失、数据处置顺序、
派生字段丢失）都是跳步造成的，无一例外。

## 一、第①步：接任务包

任务包标准字段（缺一字段即可反问发出方）：

| 字段 | 说明 | WM2 实例 |
|---|---|---|
| 编号 | R-xxx / P2-x / D-x / C-x，全局唯一不复用 | R7 AR 值校验 |
| 位置 | 文件 + 行号（约数即可） | service.py 约 L155 |
| 现象 | 用户/审查方看到的事实，不是猜测 | "馆员看到'副本状态为 reserved'" |
| 根因 | 已定位则附上；未定位写"待定位" | — |
| 修法 | 方向性描述，实现自由度留给你 | "加状态中文映射" |
| 测试要求 | RED→GREEN 或 验收步骤表（前端无测试框架时） | 断言 409 detail 含"预约锁定" |
| 验证等级 | A（纯前端 tsc）/ B（单域 pytest）/ C（全量门禁） | C 级：动了 schema/service |

**读任务包三查**：
1. 查引用的代码行号是否还存在（代码在动，行号会漂移）
2. 查任务包之间是否有交织（同一文件多项改动 → 规划 commit 切分）
3. 查口径是否需要用户定夺（数据处置类必须问，见第②步）

## 二、第②步：拷问清单（开工前必做，不问不动手）

WM2-P2 批次 13 问拷问直接拦截了 3 个任务包原文缺陷（判断题误报、import 校验
遗漏、C1-C3 规格缺失）。**拷问不是质疑任务包，是把模糊点显式化**。

### 四类必问

**1. 范围类**
- 任务包说"包含 X"但没给 X 规格的 → 要规格
- 多处相似代码（如 import 和 create 两条路径）→ 问"是只改 A 还是 AB 都改"
- 既有测试会受影响吗 → 先 `rg` 全库找同类调用点再答

**2. 数据处置类（E-08 铁律前置）**
- 查出存量脏数据 → **列出清单报用户定夺，禁止静默改**
- 备份验证 → 处置 → 证据落盘 → 最后才跑测试（顺序不可换）
- 处置证据（审计导出/操作记录）存 gate-runs/，防测试清库冲掉

**3. 边界细节类**
- 交互流：什么触发 → 弹什么 → 取消什么行为
- 显示规则：0 显示什么、空显示什么、非法值显示什么
- 并发/时序：重复点击、中途取消、失败重试

**4. 流程类**
- commit 切分方案（文件交织时提出替代切分 + 理由）
- 验证等级归属（自评 A/B/C，等确认）
- push 时机（攒批还是逐项）

### 拷问输出格式

```
## 拷问清单（N 问）
### Q1（阻断项）：...
- 我的分析：...
- 推荐方案：A / B（附理由）
### Q2-Qn（口径确认）：...
- 已有既定答案的写"我有既定答案，确认即可"
统一答复后开工。
```

## 三、第③步：RED→GREEN 施工

### 纪律（宪法第六节的操作化）

1. **先写测试看它红**——红的原因必须是被测行为缺失（如 KeyError: copy_total），
   而不是 import 错误/夹具问题
2. **禁止实现后补测试**——后补测试的最大风险是"照着实现写断言"（把 bug 当预期）
3. **前端无测试框架的场景**：先写"验收步骤表"（步/操作/预期三列），用户照表测
4. **测试配了但顺序错了**（历史违规）：需做"断言锚点复核"——每个断言标注
   锚点（FEAT-xxx / 手册 WMx 步骤 x / R-xxx），找不到锚点 = 无效测试重写

### 施工中的三个高频动作

**改默认值/口径前**：`rg` 全库找受影响调用点。WM2-D1 改"新书默认下架"时
扫出 20 个受影响测试用例，新增 helpers.py::force_book_on 统一适配——
**不是改断言迁就新行为，而是走真实 API 辅助函数**（关开关→上架→恢复）。

**写操作完成前**：问自己"响应里的派生字段重算了吗"（E-09）。
响应模型含 missing/counts/statistics 类字段时，每个写端点必须显式重算，
否则前端 setBook(updated) 整体替换 state 就丢数据。

**catch 异常时**：detail 必须中文、必须具体到操作者能行动
（"存在 N 本借出中副本，请先归还再删除"而不是"操作失败"）。

## 四、第④步：分级验证

| 级 | 适用 | 动作 | WM2 实例 |
|---|---|---|---|
| A | 纯 admin-web 前端改动 | npx tsc --noEmit + 浏览器目视 | C1 文案 |
| B | 单域 backend/tests 改动 | 该域 pytest + ruff + tsc（若含前端） | D1 收尾：catalog 28 passed |
| C | models/迁移/公共层/跨域/schema | **全量门禁 tee 落盘** | 所有 C 级批次 |

**门禁证据铁律**：报任何数字前，原始输出必须已 tee 到 gate-runs/YYYY-MM-DD/*.log。
"只写到 /tmp 就报数字" = 宪法违规（凭记忆报进度）。

**格式化预检**：跑门禁前先 ruff format 一次（两轮因格式 FAIL 重跑的教训）。

## 五、第⑤步：简报模板

简报是外部复核的唯一输入，格式（GLM WM2 收官简报为范本）：

```markdown
## WMx 任务包简报（全部完成，已提交未推送）
### 一、口径执行确认（逐条对任务包/拷问答复）
### 二、测试与验证
- RED→GREEN：test_xxx.py N 用例（列关键断言）
- 全量门禁：gate-runs/.../xxx.log → PASS exit 0（N passed / 覆盖率 X%）
- 首轮 FAIL 原因如实报（格式疏漏重跑属操作严谨性，不算隐瞒）
### 三、浏览器实测证据（headless Chrome 截图/文案原文）
### 四、当前状态（commit 列表 / 演示数据 / 待办）
```

**简报三禁**：禁报未落盘的数字；禁报不可复现的现象；禁"含审计留痕"但证据会被
后续清库冲掉的声明（要么先导出存 gate-runs/，要么不声称）。

## 六、后端施工图（九模式，WM2 实证）

### 模式 B1｜单一事实源
**是什么**：多处消费同一口径的逻辑（列表筛选、Tab 计数、详情统计）必须共用一个构造函数。
**WM2 实证**：catalog/service.py `_filtered_query()`——list_books 与 tab_counts 共用，
C3 Tab 计数与实际筛选永不漂移。
**检查点**：新写任何"统计/计数"前，先找既有 filter 构造；没有就抽出来，禁止复制粘贴查询条件。

### 模式 B2｜状态机转移矩阵 + 运维安全子集
**是什么**：状态流转合法性由模型层 ALLOWED_TRANSITIONS 硬拦截；前端只渲染矩阵的
"运维安全子集"（手工可做的），业务动作（借出/预约）不开放手工转移。
**WM2 实证**：BookCopy.can_transition（models.py L60-66）+ 前端 COPY_STATUS_TRANSITIONS
（BookDetail.tsx）——reserved 可"释放锁定"（WM11 前预约异常的唯一解法），
available→borrowed 不开放（必须走借书流程）。
**检查点**：新状态机先画矩阵对照需求（宪法红线 8）；前端下拉 = 矩阵 ∩ 运维操作。

### 模式 B3｜批量操作部分成功语义
**是什么**：批量端点逐条处理，单条失败不中断，返回 {success, failed, errors[]}，
errors 带 ID + 原因。
**WM2 实证**：batch_delete_books / batch_toggle_status（service.py）。
**检查点**：批量响应 errors 前端必须展示明细（P2-2），只报数字不报原因是 UX 断裂。

### 模式 B4｜审计全覆盖
**是什么**：每个写操作 publish_audit，action 命名 域.动作，detail 含可回溯字段。
**WM2 实证**：R9 补齐 QuizQuestion 四写操作（quiz.create/update/toggle/delete，
detail 含 question_id + 变更摘要）——之前漏了，外部审查抓的。
**检查点**：新 Service 写方法完成时对照本表自查；target_type 用宿主对象
（题目操作记 book_id，便于按书查轨迹）。

### 模式 B5｜派生字段随写重算（E-09）
**是什么**：响应模型含派生/统计字段（missing/counts/active_count）时，
**每个写操作端点**的响应必须显式重算该字段。
**WM2 实证**：D1 收尾——upload_cover/upload_audio/update_book 三处响应统一走
get_onboarding_missing 重算；前端上传成功改 load() 全量刷新兜底。
**检查点**：响应加派生字段的那一刻，grep 所有返回该模型端点的写路径逐一核对。

### 模式 B6｜业务开关走 SystemConfig
**是什么**：新业务校验/阈值做成配置（bool/int），中文名主视觉，seed 入库，
说明文案写清开/关各是什么行为。
**WM2 实证**：book_onboarding_check（默认 true，关=演示场景可上架不完整书）。
**检查点**：配置 key 走 seed_configs.py；前端 SystemConfig 页自动可见；
开关读取加默认值参数 get_value("xxx", "true")。

### 模式 B7｜中文报错铁律
**是什么**：所有 detail 面向馆员中文 + 具体可行动；**禁止英文状态码/字段名泄漏**。
**WM2 实证**：C2——"副本状态为 reserved，不可借出" 改为
"副本当前状态：预约锁定，不可借出（预约锁定请走预约核销）"；
D1——"无法上架：《书名》未传封面、未满 5 道测验题（当前 3 道）"（具体到缺什么）。
**检查点**：raise 前自查 f-string 里有没有裸枚举/状态码；数字带上单位/当前值。

### 模式 B8｜唯一约束冲突优雅处理
**是什么**：并发撞唯一索引（uq_copy_code）会抛裸 IntegrityError 500，
必须 catch → rollback → ConflictError 中文提示。
**WM2 实证**：P2-10 add_copies（monkeypatch next_copy_code 测试断言 409）。
**检查点**：新写 create/bulk 路径时问"并发两个人同时做会怎样"。

### 模式 B9｜输入清洗三路统一
**是什么**：同一字段的校验/清洗规则，schema/Excel 导入/前端三路必须同源
（常量收敛到一个模块）。
**WM2 实证**：AR_LEVEL_RE + AR_LEVEL_MAX（schemas.py）+ 前端 AR_LEVEL_RULE
（constants/book.ts）；ISBN 清洗 clean_isbn 三路（constants.py）。
**检查点**：新校验规则写成共享常量 + 校验函数，三处 import 使用，禁止各写一份正则。

## 七、前端施工图（十模式，WM2 实证）

### 模式 F1｜所有 await 必 try/catch
每个 API 调用点的 catch → message.error(e.message)。后端精心写的友好报错
（"ISBN 已存在（补货请走副本管理增加副本）"）被前端吞掉 = 白写。
WM2 抓出 6 处漏网（R4/R5/P2-9），新页面起手就全覆盖。

### 模式 F2｜Select 动态 options 恒含当前 value（E-07）
options 只含目标状态时，当前状态无匹配 → antd 显示英文原始值。
修法：options 头部加 { value: r.status, label: 中文, disabled: true }。
**改完必须浏览器实测显示**（tsc 测不出这个）。

### 模式 F3｜危险操作 Popconfirm 带后果说明
title 说清影响（"下架后小程序不可见、不可借阅预约，已借出的仍需归还"），
比干巴巴"确认吗"防误操作得多。批量按钮按选中数显隐。

### 模式 F4｜上传三件套
disabled（进行中禁再选）+ Progress（进度条）+ 文案切换（"导入中，请稍候…"）。
大文件才有感知窗口，但逻辑必须都在——双倍导入是资损级后果（R6）。

### 模式 F5｜Modal 脏数据保护
Form 用 isFieldsTouched()；受控 state（非 Form 管理的选项数组）用快照对比
（打开时 JSON.stringify 存 ref，取消时比对）——判断题固定选项恒非空，
非空启发式必误报（P2-11 拷问修正）。

### 模式 F6｜URL 写后镜像
tab/page/keyword 进 useSearchParams，变化时 setSearchParams(..., {replace: true})
不堆历史。URL 是镜像不是事实源（不处理 popstate 逐步回退）。
分页 hook 加 initialPage 参数向后兼容（其余 8 个列表页零改动）。

### 模式 F7｜Tab 计数走后端 counts
多口径 Tab（7 个）必须后端批量返回 counts 对象，禁止 N 次请求、禁止前端自己算
（口径漂移）。label 模板字符串：`上架中（${tabCounts.on ?? 0}）`。

### 模式 F8｜双口径显示
同一实体两个统计维度时（启用/总数），显示"启用 X / 总 Y"，筛选口径用 active。
后端返回双字段（question_count + question_active_count），前端不二次计算。

### 模式 F9｜受控排序
sorter: true + sortOrder 由 state 控制 + onChange 解析 sorter → 传后端
（sort/order 参数，后端白名单校验非法静默回默认）+ 排序变更重置第 1 页。

### 模式 F10｜InputNumber min 不是校验（D2 陷阱）
min=1 会**静默 clamp**（输 0 变 1 无提示）——用户以为存了 0。
必须加 rules validator（value<1 reject"总词数至少为 1"）。
通用规则：**数值边界一律 validator 拦截，min/max 只做输入辅助**。

## 八、测试施工图

### 原则
1. **真实链路**：TestClient + 真 MySQL，禁 mock 被测对象；造状态走 API 不直改 DB
2. **断言锚点**：关键断言旁注锚点（FEAT-xxx / 手册 WMx / R-xxx），无锚点 = 重写
3. **边界参数化**：@pytest.mark.parametrize 覆盖 [-1, 0, +1] 类边界
   （WM2 范本：AR 值 ["abc","1.2.3","-1","13.0","99"] 全 422 + ["0","4.5","12.9"] 通过）

### 四种测试写法（WM2 全用过）

**1. 常规功能**：造数据走 API → 断言响应字段/状态码。
范本 test_c3_tab_counts_exact：**字典精确断言**（counts == {七键全列}）而非散点断言。

**2. 异常注入**：monkeypatch 制造失败，断言系统行为不变式。
范本：monkeypatch db.commit 抛 RuntimeError → 断言旧封面文件还在（R2 删除顺序）；
monkeypatch next_copy_code 返回已存在码 → 断言 409 非 500（P2-10）。

**3. 流程性校验**：完整业务链多步断言。
范本 test_d1_toggle_on_blocked_incomplete：造不完整书 → toggle → 409 +
detail 含书名含缺失项 + **再 GET 确认状态仍为 0**（拦截不产生半套写入）。

**4. 测试辅助函数**（tests/unit/helpers.py）
跨文件复用的造数逻辑抽公共函数。范本 force_book_on：
关配置开关 → 上架 → 恢复开关，**全走真实 API**。用途：D1 默认下架后，
下游域（wm6/7/8）需要上架态书的老用例统一适配，**无断言弱化**。

### 新功能影响面排查（改默认值/口径时）
`rg` 全库找受影响测试 → 列清单 → 统一适配方案（辅助函数）→ 简报如实报
"影响 N 个用例，适配方式：xxx"。禁止改断言迁就新行为。

## 九、验收交付物规范

### 验收步骤表（前端功能的标准交付物，无测试框架时唯一验收依据）

格式硬约束：**步/操作/预期** 三列，操作写到"点哪、填什么值"，预期写到"看到什么字"。

范本（D1 上架强校验节选）：

| 步 | 操作 | 预期 |
|---|---|---|
| 1 | 新书入库（书名"测试书"） | 提示"已入库（下架状态）"，列表状态列=下架 |
| 2 | 列表点该书"上架" | 弹"无法上架：《测试书》未传封面、未传音频、未配置 AR 值、未满 5 道测验题（当前 0 道）" |
| 4 | 详情页传封面 | "待完善"Tag 内容更新（从含"未传封面"变不含） |
| 7 | 系统配置关"图书上架完整性校验" | 不完整书可上架（测完开回来） |

**验收表自检三问**：用户能不看代码就照做吗？预期含具体文案吗？边界态
（0/空/非法）有步骤覆盖吗？

### 演示数据规范
- 每轮交付重建演示数据，覆盖验收表需要的**所有状态**（含异常态：
  reserved 副本、下架书、过期会员）
- 数据名带语义前缀（"绘本示例 01"），禁用无意义名（"test1"）
- 简报里写明演示数据状态分布（"6 本下架，01 含 reserved+borrowed 副本"）

### 门禁证据落盘
gate-runs/YYYY-MM-DD/gate-{批次名}.log，简报引用路径 + 尾部三行
（passed 数 / 覆盖率 / 退出码）。数据处置证据同目录（disposal-*.json）。

## 十、WM2 案例回放：一个功能从需求到验收（D1 上架强校验）

**背景**：用户手动验收 WM2 时提出——不完整的书（无封面/音频/AR/词数/测验）
不该能上架，小程序用户会看到半成品。

**① 需求澄清（拷问前置）**：发出方给出三个待定口径（存量处置/校验时点/提示形态），
用户逐条拍板：存量已手动下架；新书一律下架入库；提示具体到缺什么。

**② 方案设计**：校验只拦"上架"动作（下架方向/编辑不校验）；五项检查抽
_onboarding_missing()；开关 book_onboarding_check 兜底演示场景；
**附带排查了小程序侧 status 过滤**（只查不改，确认无漏洞——需求本质是
"小程序看不到半成品"，后端拦截是手段，查询侧过滤是防线，两道都验证）。

**③ 施工**：RED→GREEN 13 用例（新建默认下架/导入默认下架/五项缺失参数化/
测验数动态文案/全齐可上架/开关关放行/批量混合部分成功/missing 两态）。
影响面：rg 扫出 20 个老用例依赖"新书默认上架"→ helpers.force_book_on 统一适配。

**④ 验证**：C 级全量门禁（187 passed / 78.72% / exit 0 落盘）+ tsc + 浏览器实测
（Tab 计数、拦截弹原文、待完善 Tag）。

**⑤ 验收抓 bug**：用户实测发现"传封面后待完善 Tag 消失"→ 定位：上传响应未重算
missing（E-09 诞生）→ 修：三处写响应重算 + 前端 load 兜底 → 复测通过。

**⑥ 闭环**：push 10 commit → CI 绿 → tag acceptance-baseline-wm3-wm10 →
LEDGER ACCEPTED → 错误记忆库 E-09 入库 → 本手册收录模式 B5/F10。

**这个回放展示完整闭环的所有环节**——后续模块照此走，遇到本手册没覆盖的新坑，
修完就补录进来（这就是手册的更新方式）。

## 十二、UX 增强基线（每个模块交付前必过，2026-08-28 用户裁决）

> **裁决背景**：WM2 在 PRD 功能之外新增了大量体验增强（Tab 计数/批量操作/排序/
> URL 状态/脏保护/上架强校验等），用户明确要求：**其他所有模块同等对待**。
> 定位：PRD = 功能底线（做没做对），本基线 = 体验底线（好不好用）。
> 执行方式：每个模块进 MANUAL_TEST 前，开发模型提交「UX 基线对齐表」
> （12 项逐项标注 已实现/不适用+理由/本批新增），外部审查复核后随验收一起判定。

### 基线十二项

| # | 项 | 标准 | WM2 实证 |
|---|---|---|---|
| U1 | 状态全中文映射 | 任何状态码/枚举出现在 UI 必有中文标签；报错 detail 无英文码泄漏 | COPY_STATUS_LABEL + C2 借书报错 |
| U2 | 所有 await 有 try/catch | 后端友好报错必须可见（message.error 展示 detail） | R4/R5/P2-9 共 6 处补齐 |
| U3 | 筛选/Tab 带计数 | 多口径 Tab 由后端 counts 批量返回，禁 N 次请求 | C3 七键 + MemberManage 模式 |
| U4 | 批量操作部分成功 | 单条失败不中断，失败明细展示（ID+原因） | B3 模式 + P2-2 |
| U5 | 危险操作确认带后果 | Popconfirm title 写明影响，不是干巴巴"确认吗" | 下架/删除确认文案 |
| U6 | 数值边界 validator 拦截 | 禁 InputNumber 静默 clamp；非法值红字 + 阻止提交 | D2 词数陷阱 |
| U7 | 提示具体可行动 | 报错/拦截写到"缺什么、带当前值、下一步做什么" | D1"未满 5 道测验题（当前 3 道）" |
| U8 | URL 状态镜像 | tab/page/keyword 进 URL（replace 不堆栈），刷新/分享不丢 | P2-6 |
| U9 | Modal 脏数据保护 | 填一半取消有挽留确认（Form 用 touched，受控 state 用快照） | P2-11 |
| U10 | 表格完整体验 | 排序（常用数值列受控后端排序）+ 空态插画 + loading + 加载失败报错（禁假 0） | P2-4/P2-7/P2-5 |
| U11 | 运营视角异常 Tab | 列表提供"待处理/缺资料"类筛选（馆员巡库思维） | 未传封面/未传音频/测验未满 5 道 |
| U12 | 演示数据覆盖异常态 | 交付时重建演示数据，含该模块全部状态（含 reserved/过期/欠费等异常态） | 绘本示例 01 含 reserved+borrowed |

### 适用节奏
- **WM3-WM10（已开发待验收）**：验收时由外部审查按此基线出各模块差距清单
  （等同 WM2 的 P2 清单），按模块批量补齐后再 ACCEPTED
- **WM11/WM12（未开发）**：任务包 DoD 直接含"基线对齐表"，开发时同步满足
- **新页面/新功能（任何模块内）**：代码评审 checklist 含 U1/U2/U5/U6 四项硬检查

### 为什么单独成章而不是并入模式库
模式库管"怎么实现"，基线管"交付门槛"。门槛必须可勾选、可复核、可拒收——
这三性要求它独立存在并在验收流程里有 teeth（不过基线 = 不进 MANUAL_TEST）。
