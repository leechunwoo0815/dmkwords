# 23 · 产品口径拍板（2026-10-27，高级产品经理决策）

> 来源：第十轮/第十一轮审查遗留的“需产品口径”条目，由产品经理逐项选择。本文是后续代码与验收的唯一口径依据。

## 一、活动报名默认仅会员

- **规则**：新建活动默认勾选「仅限会员」；运营可在活动上显式取消（首场体验、开放日、亲友场）。
- **会员口径**：沿用 `Child.is_active_member`（观察期/待评估也算有效会员；none/expired/withdrawn 不算）。
- **后端**：`Activity.member_only` 默认值 1；创建接口 `member_only` 默认 `True`。
- **管理端**：新建表单默认勾选；编辑保留已存值。
- **种子**：演示活动显式写 `member_only=False`（保持现有演示动线）。
- **页面可见性**：非会员仍能看到活动列表/详情（便于了解权益），报名时由后端拒绝并提示“该活动仅限会员报名”。

## 二、活动结束时间与签到时间窗

- **规则**：活动新增「结束时间」；签到只允许在 **开始前 60 分钟 ~ 结束后 30 分钟**。
- **数据**：`activities.end_at`（可空以兼容历史行；服务端创建时未传则默认 `start_at + 3 小时`；迁移回填历史行同值）。
- **管理端**：新建/编辑表单必须填结束时间（校验 > 开始时间）；列表/详情展示。
- **后端校验**：创建/编辑 `end_at > start_at`；签到早于窗口提示“签到通道未开启（活动开始前 60 分钟开放）”，晚于窗口提示“签到通道已关闭（活动结束后 30 分钟关闭）”。
- **小程序**：活动详情展示“开始 ~ 结束”时间。

## 三、AR 分档边界

- **规则**：左闭右开 `[lo, hi)`，最后一档 `[4, ∞)`。
- **后端**：`ar_min ≤ AR < ar_max`（`ar_max` 为空表示无上界）。
- **前端**：档位文案改为 `AR 0–1.9 / 2–2.9 / 3–3.9 / 4 以上`，避免边界歧义。
- **效果**：AR 2.0/3.0/4.0 只落在唯一一档。

## 四、押金退款后的订单展示

- **规则**：押金退款不改订单状态（订单仍是「已支付」，支付事实不篡改）；订单列表按**押金台账**显示「押金已退 / 押金部分退 ¥X」。
- **后端**：押金类订单在家长端与管理端列表附带 `deposit_refunded_amount`（累计退款额）与 `deposit_status`。
- **前端**：仅押金/押金补缴订单显示该行；无退款不显示。
- **部分退款**：按台账累计额展示，不以订单二值状态表达。

## 五、验收要点

1. 活动：新建默认仅会员；取消勾选后非会员可报名；种子演示数据仍可报名。
2. 签到：窗口外拒绝（含早到/晚到两条判据）；窗口内成功；窗口以 `end_at` 计算。
3. AR：`AR=2.0` 只出现在 `2–2.9` 档；`AR=4.0` 只出现在 `4 以上`。
4. 押金：全额/部分退款后订单状态仍 `paid`，列表展示累计退款额；无退款不显示。
