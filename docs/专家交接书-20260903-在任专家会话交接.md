## 七、审查方法论增量（本会话新沉淀，压缩后必须带着）

1. **CI 验证法**："CI 有这么快吗"式质疑必须 `gh run view --json`（job/step 计时）
   +`--log`（grep 关键行）逐步骤实锤，不采信简报数字
2. **性能归因**：本地慢≠测试慢——CI 最慢单测 0.66s vs 本地均 1.75-2.3s，
   根因是本机 swap 5.5GB+OrbStack 嵌套虚拟化；durations=20 是判据
3. **修复者自证循环**：110 刀新代码的测试是修复者自己写的——最薄弱区；
   审查重点=修复是否引入回归+漏做未声明（R1 教训：任务卡明写项没做且简报
   不报=纪律违规，下不为例条款已口头警告）
4. **"没找到≠不存在"**：PRD/ 文件夹漏盘事故——全量盘点必须 ls 目录树，
   不能只搜文件（rg 找文件名会漏目录）；失误当场如实留痕（LEDGER 已记）
5. **rg 参数坑**：`rg -rn` 的 -r 是 replace！我两次踩（输出全成替换痕迹）——
   正确是 `rg -n`；见到诡异单字母输出先查自己命令参数
6. **数字巧合陷阱**：可退=订单金额（seed 无 paid_at→永远全额退）——数据 bug
   让正确逻辑看起来像没做；UX 反馈"看不到 X"先查数据是否让 X 不可见
7. **防呆优于提示词**（E-20260901-04）：流程性纪律（mkdir/tee）写进提示词
   三遍仍犯，进脚本一次灭绝
8. **混编日志切分**：防呆补丁重跑同批次名会追加——按 `[gate] 本轮日志自动归档`
   行切分轮次；重跑建议换名（-fix4b）
9. **四件套不变**：代码对源码/测试查假绿/门禁验尾/数字 git 实测；前端批次
