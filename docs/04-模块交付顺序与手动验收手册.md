# 04 模块交付顺序与手动验收手册

> 目的：**按模块开发、按模块验收**。每个模块交付时 = 后端 API + 管理端页面 +（涉及小程序时）小程序页面 + 种子数据/测试物料 + 本手册对应测试步骤。
> 铁律：**交付的模块绝不依赖未开发模块**——你验收时一定可以完整走通，不会遇到"这个按钮没反应因为 XX 还没做"。

## 一、验收双层制

| 层 | 谁做 | 内容 |
|---|---|---|
| 自动闭环 | AI（我） | `bash scripts/gate.sh full` 退出码 0（单测/BDD/架构/反假绿/覆盖率） |
| 手动验收 | **你** | 按本手册步骤在浏览器/微信开发者工具逐条操作，有问题报给我修，修完重测 |

**模块状态流转**：IN_DEV（开发中）→ GATE_PASS（自动门禁过）→ **MANUAL_TEST（等你测）** → ACCEPTED（你确认）→ 进入下一模块。你测试期间我可以并行开发下一模块（不同分支），但**验收通过才算交付**。

**与原 P 序（顶层规划）的差异及原因**：
- 退款（原 P3）→ WM10：退款要联动退会/转让才测得完整，且审核流需要订单/押金/会员全部就绪；
- 微信支付（原 P3）→ WM12：无商户号无法真测；人工收款路径（WM3）已覆盖全部业务语义；
- 活动（原 P10）提前到 WM9：纯管理端可完整测试，且不依赖阅读链；
- 预约（原 P5）随 WM6：预约由家长小程序发起，与小程序同批交付才能测。
