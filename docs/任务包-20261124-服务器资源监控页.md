## 一、目标与边界

**目标**：管理员在管理端左侧「系统」组 →「服务器监控」看到**后端所在服务器**的实时资源、可选区间的趋势曲线、服务状态、进程 Top、MySQL 与应用指标；页面打开即自动刷新，可作为日常运维主界面（及时发现 CPU/内存/磁盘/IO 异常），不需要再人工上服务器查。

**做（v1）**：
- 主机：CPU（总/分核）、负载、内存/缓存/Swap、磁盘使用率/Inode、磁盘 IO、网络进出、运行时长。
- 服务：后端进程、MySQL、nginx、调度器、`/health`。
- 进程：CPU Top 5、内存 Top 5（进程名/PID/RSS/CPU%，**不显示命令行/env**）。
- MySQL：连接数、运行中、QPS、慢查询。
- 应用：最近 1 分钟/今日请求量、4xx、5xx、错误率、P95 延迟。
- 趋势曲线（区间可选：10 分钟实时 / 30 分钟 / 1 小时 / 6 小时 / 12 小时 / 24 小时；CPU/内存/网络/磁盘 IO/负载/请求量/错误率/P95）。
- 图表交互：同色渐变面积填充、5 个时间刻度、峰值竖向标注（含数值）、悬停十字线 + 该时刻全部读数、区间均值/峰值统计条。

**不做（v1）**：
- 腾讯云平台级指标（CPU 积分、带宽包、云盘 IOPS）——需要腾讯云 API/CAM，放 v2。
- 多台服务器聚合/切换——v1 只监控“后端所在这一台”；换腾讯云部署后自动看新机器。
- WebSocket/SSE——10 秒轮询足够，避免 nginx 长连接配置。
- 告警通道改造——现有 cron/webhook 不动；本页只展示状态与阈值。
- 不做 24h 之外的回看（数据只保留 24h）；不做导出/报表。

- **页面可见性**：`document.visibilityState` 隐藏时暂停轮询；回到前台立即补拉一次。
- **关闭页面**：清除 interval，不再请求；服务端无后台“页面采集”进程（24h 采样任务独立，见下）。

- **首次进入**：立即拉一次 live 并作为第一个点；之后每 10 秒追加；**默认 10 分钟区间不拉 history**，切到长区间才拉。

## 三、技术方案

### 3.1 采集库

新增依赖 **`psutil`**（轻量、跨平台、生产 Linux 可用）。若 CentOS 7 / Python 3.13 的 wheel 不可用，退化为读 `/proc`（实施时先验证，不通过再换，禁止硬上）。

### 3.2 24h 历史存储

- 新表 `system_metrics`（MySQL），每 60 秒一行；保留 24 小时（每小时清理一次过期行）。
- 采样**不挂进 21 项任务看板**：60 秒一次若走 `TaskSpec`，每天会多 1,440 条 `TaskRunLog`，看板会被刷爆。改为**调度器内部 job**（`system_metrics_sample`，60 秒，`_start_jobs_now()` 注册，首启与抢锁接管共用），仍受调度器单实例锁保护；不进任务看板、不写 TaskRunLog。
- 采样失败（如 DB 短暂不可用）只记日志并返回，不抛出、不影响业务任务。
- 历史按 5 分钟聚合返回给前端（24h = 288 点），避免一次传 1,440 点。

**字段（草案）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | |
| `collected_at` | DATETIME，索引 | 服务器本地时间 |
| `cpu_percent` | FLOAT | 总 CPU |
| `load1/load5/load15` | FLOAT | 系统负载 |
| `mem_total_mb` / `mem_used_mb` / `mem_available_mb` / `mem_cached_mb` | INT | 内存 |
| `swap_total_mb` / `swap_used_mb` | INT | Swap |
| `disk_total_gb` / `disk_used_gb` / `disk_percent` / `inode_percent` | FLOAT | 根分区 |
| `disk_read_kbps` / `disk_write_kbps` | FLOAT | 磁盘 IO |
| `net_rx_kbps` / `net_tx_kbps` | FLOAT | 网络 |
| `process_count` | INT | 进程数 |
| `mysql_connections` / `mysql_running` | INT | MySQL |
| `mysql_qps` | FLOAT | 由 Questions 差值计算 |
| `mysql_slow_queries` | BIGINT | 慢查询累计 |
| `app_requests` / `app_4xx` / `app_5xx` | INT | 当分钟应用请求 |
| `app_p95_ms` | INT | 当分钟 P95 |
| `uptime_seconds` | BIGINT | 主机运行时长 |

### 3.3 应用指标中间件

- 新增轻量 ASGI/HTTP 中间件：仅统计 `path.startswith("/api/")` 的请求。
- **排除** `/health` 与 `/api/admin/system/*`（监控页自己的 10 秒轮询不能污染请求量/错误率）。
- 线程安全计数器 + 固定桶直方图（5/10/25/50/100/200/500/1000/2000/5000ms），P95 由桶累计估算。
- 每分钟由采样任务 `snapshot_and_rotate()` 写入 `system_metrics`；live 接口读当前窗口，不重置。
- 开销：一次 `perf_counter` + 锁内自增，微秒级。

### 3.4 API

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/admin/system/live` | `config.view` | 实时快照（主机/服务/进程/MySQL/应用 1 分钟+今日） |
| GET | `/api/admin/system/history?hours=24` | `config.view` | 回看历史；粒度自适应（1h=60s、6h=120s、12/24h=300s，最多 300 点），页面 30 分钟–24 小时区间使用 |

- 服务端缓存：live 3 秒、history 60 秒（按 `hours` 分键）、今日汇总 30 秒，防多标签页/多人重复采集。
- 响应只含聚合指标与进程名，不含命令行、环境变量、密钥、公网 IP。
- 契约三件齐：OpenAPI 快照 + `schema.d.ts` 重新生成（gate [8]）。

### 3.5 前端

- 新页面 `admin-web/src/pages/ServerMonitor.tsx`；路由 `/system-monitor`。
- 左侧「系统」组、**系统配置下面**新增「服务器监控」，图标建议 `CloudServerOutlined`；权限复用 `config.view`（菜单/路由/后端三处一致）。
- 图表组件 `admin-web/src/components/ServerMonitorCharts.tsx`（手写 SVG，不引 ECharts）：平滑折线 + 同色渐变面积填充、5 个时间刻度、峰值竖向标注（含数值）、悬停十字线 + 深色读数框；堆叠面积（内存构成）；半圆仪表（CPU/内存/磁盘）。
- 轮询：live 10 秒（KPI + 10 分钟实时窗口）；长区间 history 60 秒；`visibilitychange` 暂停/恢复；卸载清理；切回 10 分钟即停止 history 请求。
- 区间选择：`Segmented`（10 分钟 / 30 分钟 / 1 小时 / 6 小时 / 12 小时 / 24 小时）；12/24 小时刻度带日期；右上角标注采样粒度、点数、实际覆盖时长；历史为空时回退本次页面数据并提示。
- 页面标题、面包屑、`document.title` 同步 `PAGE_TITLES["/system-monitor"] = "服务器监控"`。
- 响应式：桌面双列，窄屏单列；KPI 卡自动换行。

## 四、验收判据

### 手动验收（docs/04 新增 S466–S470）

- **S466 入口与权限**：admin 能看到「系统 → 服务器监控」并打开；无 `config.view` 的账号菜单不可见，直接访问 URL 被拒（403/重定向）。
- **S467 实时刷新**：打开页面 10 秒内出数；等待 30 秒可见数字/曲线更新；关闭页面后浏览器 Network 不再有 `/api/admin/system/*` 请求。
- **S468 趋势曲线**：10 分钟视图每 10 秒追加一个点、最近 10 分钟滚动；切 30 分钟/1 小时/6 小时/12 小时/24 小时从服务端历史取数（标注粒度/点数/覆盖时长），切回 10 分钟停止历史请求；折线有面积填充，悬停显示该时刻全部读数，峰值标注带数值。
- **S469 失败态**：停 MySQL → 10 秒内 MySQL 状态变红、页面不白屏；恢复后自动转绿。停后端 → 页面显示“连接失败，10 秒后重试”，不伪装成 0。
- **S470 应用指标**：制造几次 API 请求（含一次 4xx）→ 1 分钟请求量/错误率上升；监控页自身轮询不计入；今日累计与 DB 汇总一致。
- **主题与响应式**：三套主题切换图表/卡片颜色跟随；窄屏不横向溢出。

## 五、风险与取舍

| 风险 | 处置 |
|---|---|
| psutil 在 CentOS 7 / glibc 2.17 / Python 3.13 无 wheel | 实施前先验证；不行改读 `/proc`（不阻塞方案） |
| 60 秒采样 + DB 写入 | 1,440 行/天、24h 保留；每小时清理；写入失败只记日志 |
| 多 worker/多实例 | 当前生产单进程 uvicorn；采样走调度器单实例锁；应用指标按进程统计（多 worker 时需改为共享存储，v1 不支持） |
| 监控页自身流量污染应用指标 | 中间件排除 `/health` 与 `/api/admin/system/*` |
| 进程信息泄露 | 只给进程名/PID/RSS/CPU%；不给命令行、env、端口、路径 |
| 历史断点 | 后端重启 <60 秒空档；DB 中旧数据保留 |
| 服务器时间/时区 | 记录服务器本地时间，页面标注“服务器时间”，不混用浏览器时区 |
