# docs 索引与状态标签（2026-11-05 建立）

> **为什么有这一页**：仓库里同时存在「现行规范」「某轮审查的现场快照」「已被取代的方案」三类文档，
> 文件名和日期都看不出来。曾经出现过照历史审计报告去修已闭环问题、按旧任务书等 v156 状态的情况。
> **先看本页状态列，再决定读不读**。
>
> 状态口径：
>
> | 标签 | 含义 | 能不能据此施工 |
> |---|---|---|
> | **现行** | 当前实现/口径的事实源 | 可以，但仍以代码与 `LEDGER` 当日状态为准 |
> | **历史** | 某次审查/交付的现场快照，问题多已闭环 | **不能**：只能当证据与复盘，不能据此判断"现在还没修" |
> | **已取代** | 明确被更新文档或实现取代 | **不能**：正文可能保留旧结论 |
> | **归档** | `legacy-attic/`，整体跳过扫描 | **不能**：只作考古 |
>
> 任何文档里的「当前状态 / 待办 / 下一步」都不如这两处新：
> **`docs/LEDGER.md`（进度唯一事实源）** 与 **`docs/项目交接-20260824.md`（v171 交接卡）**。

## 维护规则

1. 新增文档必须在本页登记状态；未登记的文档默认视为**历史**。
2. 文档结论被推翻时，**改正文或加 banner**，不要只在下一次交接卡里口头纠正。
3. 历史文档不要删除（审计链），但要标明"历史"；真正无价值的临时产物放 `legacy-attic/`。
4. 本章末尾这份索引由人维护，不参与门禁自动校验；`check_docs_code_alignment` 只保证**引用的文件/接口/符号真实存在**。
