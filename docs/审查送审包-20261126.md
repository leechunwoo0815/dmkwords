## 五、已知残余风险（我主动交代，不是隐瞒）

1. **演示通道仍能看真实数据**：登录载荷已脱敏，但 `GET` 榜单/阅读圈仍返回真实孩子姓名与头像。彻底解法是 0.1.15 发布后把 `DEMO_LOGIN_PHONE` 置空关停入口（已在任务书 B0-6 里写明）。
2. **本轮并发类改动未做双会话实测**：B1-4 的金额比对、B0-5 的撤销都用单线程用例 + 静态核验；真正的并发压测（退款双发、退会双发）留给 B1-1/B1-2 那批。
3. **生产出过一次 2 分钟不可用**：改 nginx vhost 时我的脚本用 `open('w')` 写文件，中文注释在生产 python3.6 的 ASCII 默认编码下编码失败 → 文件被截断为 0 字节；更糟的是 **`nginx -t` 对"只剩一段 log_format"的配置仍报语法 OK**，于是一路 reload 过去。已用改前备份恢复，随后改为**原子写 + 内容断言（两个 `server {` 必须在）+ reload 后必须 `https_root==200`** 才落盘。教训已进错误记忆库（§一百四十七同族，另记"配置写入必须原子 + 语义断言"）。
4. **`alembic.ini` 曾让生产跑不了迁移**：中文注释 + `encoding="locale"` + C locale CentOS → `UnicodeDecodeError`，本轮改纯 ASCII 后才可跑（已实测 `alembic current`）。这意味着**在此之前任何"生产已跑迁移"的说法都要重新核对**。
5. **单进程是硬约束**：限流/指标/live 缓存/调度器锁都在进程内；多 worker 已硬拦，但若将来上多进程必须先改共享存储。
6. **CentOS 7 EOL + `performance_schema=OFF`**：慢查询只靠 `slow_query_log`，`performance_schema` 关着（我方未改，属 B6 观察项）。
7. **回滚只覆盖代码**：`release_rollback.sh` 不动数据库；若将来迁移有破坏性变更，回滚必须人工决定是否 `alembic downgrade`（脚本会把两边版本打出来）。
