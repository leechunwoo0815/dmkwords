## 二、P0 阻断项（上线前必须处置）

### P0-1　99 元首场「每账号一次」在线上通道无复检 → 可双收 198 元 **[亲验·已复现]**

- 位置：`backend/domain/identity/payment_service.py:238`（预支付复查）、`backend/domain/identity/order_service.py:456-457`（结算链仅 `child = None`）、`backend/domain/identity/payment_service.py:407-420`（`except ConflictError` 分支对该场景不可达）。
- 机制：资格检查只查 `status == PAID`。两笔 99 元待支付单先后**预支付**时彼此都还不是 `paid` → 都放行；随后两个回调各自走 `_settle_online → _settle_paid`，**线上结算链没有任何 99 元资格复查**（人工确认收款路径有，见 `order_service.py:376-390` 的 P1-F6 修复——两条路只补了一条）。
- 复现输出（本轮实跑，模拟真实通道：`type(gw).supports_instant_payment = False`）：

```
两张 99 元待支付单：DMK20261009040035F70B32 / DMK202610090400356F6E10
① 预支付 A → 200 | 返回 pay_params: True
② 预支付 B → 200 | 放行（资格未拦）
③ 回调 A → 200 {'code': 'SUCCESS', 'message': '成功'}
④ 回调 B → 200 {'code': 'SUCCESS', 'message': '成功'}
   订单 A 最终状态: paid / 流水号=txn_repro_A2
   订单 B 最终状态: paid / 流水号=txn_repro_B2
复现家长的已付 99 元单数（应为 2 = 双收）: 2
```
- 后果：**198 元**收进商户号、两单都合法、**无 `payment.anomaly` 审计**；对账看两笔正常支付，无差异；家长不主动要求退款就不会被发现。
- 触发前提：真实微信通道（回调异步）+ 家长双击/两笔待支付单并存。mock 通道即时到账，掩盖了这条路径。

### P0-2　小程序「提交退款申请」是死按钮（handler 被删、绑定还在） **[亲验]**

- 位置：`miniapp/pages/order-pkg/refund-apply/refund-apply.wxml:30` `bindtap="onSubmit"`；同页 JS 只定义 `onLoad/onShow/onReason/_ensureRefundable/onCancelRefund`（**无 `onSubmit`**）。
- 交叉证据：`miniapp/utils/api.js:109 applyRefund(...)` 全仓**零调用点**；后端 `POST /api/miniapp/refund-requests` 无任何小程序页面触达。
- 后果：家长选单 → 看到退款预览与金额 → 填原因 → 点「提交退款申请」→ **没有任何反应**（微信对缺失 handler 静默忽略）。资金类入口，用户会以为"提交成功"。
- 门禁盲区（结构性）：`scripts/check_miniapp_bindings.py` 只做**数据面**断链检查（wxml 读到的变量 vs js 写入），**不校验 `bind*` 指向的方法是否存在**；`check_miniapp_style` 的 R12 只看 wxml 用到的类名，也不看 handler。

### P0-3　生产短信会「假成功」：SDK 缺失时静默降级，验证码前 4 位进日志 **[亲验·已复现]**

- 位置：`backend/integrations/sms/aliyun.py:72-81`（同款 `tencent.py:71-80`）、`pyproject.toml:6-21`（**未声明 `alibabacloud-dysmsapi` / `tencentcloud-sdk`**）、`backend/config.py:117-123`（生产校验只查凭据非空）。
- 机制：`if not _HAS_SDK or not self.app_id or not self.app_key:` → 走 dev 分支：**不发送**、`SmsSendResponse(success=True, code=...)`、`logger.info("[AliyunSms(dev)] 验证码 %s ...", code[:4])`。**服务端会把"发出去的"这个码写进库并接受它。**
- 复现输出（`SMS_PROVIDER=aliyun` + 假凭据实跑）：

```
INFO:backend.integrations.sms.aliyun:[AliyunSms(dev)] 验证码 9013 已生成（SDK/凭据未配置，未实际发送）phone=138****1111
```

- 修法方向：把「SDK 可导入 + 凭据齐」都纳入 `validate_production` 拒启条件；网关缺 SDK 时**fail-closed**（返回失败而不是假成功），并禁止打印验证码任何位。
