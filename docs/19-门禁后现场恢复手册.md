> **定位**：本手册是 CLAUDE.md §六"完工（DoD）"第 2 条的执行细则——**gate PASS ≠ 现场可用**。
> 来源：2026-09-06 用户裁定"每换一个新的大模型都要重新教一次"的终结方案（此前翻车 4 次的

## 〇、为什么需要本手册（30 秒前世今生）

本项目 **pytest/behave 与 dev 后端共用同一个 MySQL 库**——测试的 TRUNCATE 会清空
全部业务表（书/家长/孩子/订单/待办全没了）。所以：

```text
gate PASS 只证明代码对，不证明现场能用。
```

## 一、标准流程（gate/pytest 之后，一字不漏）

### 第 1 步：看 gate 尾部——自动恢复是否已跑

看门禁日志最后几行（`gate-runs/YYYY-MM-DD/gate-*.log` 或终端尾部输出）：

- 出现 `----- 现场已自动恢复 ✓ -----` → 自动恢复已执行，**跳到第 4 步核验**（核验不能省——自动恢复也可能失败）
- 出现 `⚠ 业务表已被门禁清空` 或无恢复输出 → **手动执行第 2、3 步**

> 自动恢复机制：`scripts/gate.sh` PASS 分支检测本地 dev 环境存在时自动 `dev.sh restart`
> （重启后端加载最新代码 + 双 seed 恢复）。**它只是提醒+尽力，核验责任在你。**

### 第 2 步：完整 restart（不是 start！不是单跑 seed！）

```bash
bash scripts/dev.sh restart
```

**三条铁律**：

1. **restart 而非 start**：`start` 对已运行进程幂等跳过——旧进程还在跑旧代码
   （E-20260905-01 实锤：代码是对的，用户看到的是旧进程的行为）。
2. **禁止单跑某支 seed**：演示数据双支构成——
   - `scripts/seed_demo_library.py`：30 本书（绘本封面 + 音频 + 每本 5 测验题）
   - `scripts.seed_wm11_demo`：6 本书（其中 Dog Man `9780545582889` 因缺 `uploads/book_audio/9780545582889/audio.mp3` 被跳过 → 实入 5 本）+ 演示家庭（13800008888）/ 订单 / 管理待办四态 / 真链路测验三态 / **活动 4 场**（2 场可报名含图文详情配图 + 2 场往期回顾演示，含签到与取消报名记录，2026-09-20 起）

   只跑前者 = 无家长无订单；只跑后者 = 图书馆空。`dev.sh restart` 内置完整链
   （MySQL → 迁移 → admin/configs/双 seed → 后端 → 前端）。
3. **本批含后端代码改动时，无论 gate 是否自动恢复过，交付前必须再 restart 一次**
   ——你 commit 后的代码要加载进进程才算数。

### 第 3 步（仅手动恢复时）：核对 restart 输出四段全 OK

```text
[1/4] MySQL OK → [2/4] 数据库迁移 + 种子（幂等） → [3/4] 后端 :8002 OK → [4/4] 前端 :5173 OK
```

任何一段报错：**停止，贴完整输出问专家**，禁止带着残缺现场往下走。

### 第 4 步：三项核验（数据/进程/接口，缺一不可）

```bash
# ① 数据回来了 —— 一键（推荐）：按本手册清场（pytest 清库）+ restart 双 seed + 计数 + 比对基线
python -m scripts.check_demo_baseline        # 退出码 0 = 与基线一致；1 = 不一致
#   --no-clean   跳过清场只计数（调试用；读数可能是门禁残留）
#   --count-only 只打印计数
#   **2026-09-23 起本命令断言两组**（G3 落地）：① 四表计数 35/3/11/4；② **演示孩数字**
#   （词账 109320 / 积分 1133 / 零头池 20 / 勋章 [100000] / 在借 2 其中逾期 1 / 可借 28 /
#    生词本 8 词 / 押金已缴 1200）——口径与 `docs/04` 演示账号表同源：**改演示数据必须同步改两处**，
#   否则本命令红（历史：书 30 改名 +7,000 词/+70 分，手册与现场漂了半天没人拦）
#
# **为什么必须清场**：门禁（pytest **与 behave**）和 dev 共库，跑完门禁库里必然留着**最后一批
# 场景数据**，而种子**不会清它**。实测残留样本（2026-09-16）：behave 的
# features/wm3_member_edit.feature 留下「学籍家长B / 学籍孩B」→ 直接 COUNT 读到 家长 4 / 孩子 12，
# 干净基线其实还是 3 / 11（E-20260916-41 就是"不清场直接读数 → 误判文档基线过期"的翻车现场）。
#
# 手工等价命令（想看细节时用）：
.venv/bin/python -c "
from backend.database import SessionLocal
from backend.domain.catalog.models import Book
from backend.domain.identity.models import Parent, Child
from backend.domain.activity.models import Activity
db = SessionLocal()
print(f'书目: {db.query(Book).filter(Book.is_deleted==0).count()} | 家长: {db.query(Parent).filter(Parent.is_deleted==0).count()} | 孩子: {db.query(Child).filter(Child.is_deleted==0).count()} | 活动: {db.query(Activity).filter(Activity.is_deleted==0).count()}')
db.close()"
# **干净基线（清场后实测）：书目 35 / 家长 3 / 孩子 11 / 活动 4**（含封面[轮播数据]；活动 4 = 2 场可报名 + 2 场往期回顾演示，2026-09-20 C 批起）
# + 阅读圈帖 **10**（thumb_v4 JPEG 双规格；2026-09-17 由 3 帖扩到 10 帖，卡型 7 种）/ 周榜快照 5 / 演示头像 6；演示锚点：家长 13800008888、书 Brown Bear

# ② 后端进程是新的（启动时间须晚于刚才的 restart）+ 健康检查
ps -eo pid,lstart,command | grep "uvicorn.*8002" | head -1
curl -s http://localhost:8002/health

# ③ 管理端起得来
curl -s -o /dev/null -w "admin-web %{http_code}\n" http://localhost:5173
```

三项全过 = 现场恢复完成 = 用户可以目视。**任何一项不过：回第 2 步，两轮不过上报专家。**

### 第 5 步：交付简报必须声明（不许含糊）

简报固定句式：

```text
gate 后现场已按 docs/19 标准流程恢复：restart + 双 seed，三项核验通过
（书目 35 / 后端进程 <启动时间> 新启 / health ok / 5173 200）
```

**禁止只写"跑了 seed"**——哪支？全了吗？进程重启了吗？历史事故全部源于这种含糊。

## 二、四个防呆基建（认识它们，别绕过它们）

| 基建 | 位置 | 作用 |
|---|---|---|
| gate PASS 自动恢复 | `scripts/gate.sh` 尾部 | 检测本地 dev → 自动 restart+双 seed（可能失败，第 4 步核验兜底） |
| gate 后恢复提醒 | `scripts/gate.sh` PASS 分支 echo | 未检测到 dev 环境时输出 ⚠ 提醒行 |
| 交付完整性检查 | gate 步骤 [9] | 外部专家意见/docs/error_list 下 untracked 文件 → 硬失败（防 LEDGER 引用了文件本体却没提交） |
| 基线核验脚本 | `scripts/check_demo_baseline.py` | 把第 4 步 ① 固化成一条命令：清场（pytest 清库）→ restart 双 seed → 计数 → 与基线比对，退出码 0/1（E-20260916-41：防止"不清场直接读数"导致误判）。**2026-09-23（G3）扩为两组断言**：四表计数 + 演示孩数字（词账/积分/零头池/勋章/在借/逾期/可借/生词本/押金），与 `docs/04` 表同源 |

## 三、常见坑速查

| 症状 | 根因 | 处置 |
|---|---|---|
| 图书馆/会员管理全空 | 门禁 TRUNCATE + 没恢复 | 第 2 步 restart |
| 改了后端代码用户却说没生效 | 旧进程未重启（start 幂等跳过） | restart；`ps lstart` 核对 |
| 恢复了但只有书没有家长 | 只跑了 seed_demo_library | 补跑双 seed（或直接 restart） |
| 恢复了但只有家长没有书 | 只跑了 seed_wm11_demo | 同上 |
| 库里孩子 id=1 等陌生数据 | pytest 清库后的测试残留 | 不是演示数据，别拿来当验证依据；再跑一次 restart 覆盖 |
| gate 日志显示自动恢复 ✓ 但数据还是空 | 自动恢复进程失败 | 手动第 2 步 + 看输出报错段 |
| gate PASS 后自动恢复 ✓，但**多出**陌生家长/孩子（多到 4 家长 12 孩子） | 自动恢复 = `restart`（起服务 + 双 seed），**只保证"演示数据在"，不保证"测试残留不在"**——残留正是刚才那道门禁自己跑的 pytest 留下的（第 2 步全量测试与 dev 共库） | 再跑一次 `.venv/bin/python -m scripts.check_demo_baseline`（**不带** `--no-clean`）→ 应回 35/3/11/4；若本次清过场，接着按上一行重登小程序。（2026-09-23 第二十七轮实证：gate 退出码 0 并打印"现场已自动恢复 ✓"之后，基线仍是 4 家长 / 12 孩子） |
| 清场重建后管理端「媒体体检」显示**回收站 2 张**，但 `find uploads/.trash -type f` 有几千个 | 清场走的 pytest 会 `TRUNCATE media_trash_entries`（媒体体检的**记账表**），而 `uploads/.trash/` 是**磁盘事实**——账被抹掉、文件还在（2026-09-23 实测 3452 张，全都是已判定孤儿，一张没删） | **什么都不用做**：每日盘点（或管理端点「重新点数」）会先跑 `reconcile_trash()` 自动补账/搬回（docs/15 §22.2 第 7 道），补完它们重新出现在回收站列表里可还原/可清空。**别手动删 `.trash/` 里的东西**——那是唯一能救回它们的地方 |
| 演示孩词账/积分比文档大（实测 187320 / 1923，文档是 109320 / 1133） | 有人在**小程序真机答了一次题**（真答必真入账，且 `create_time` 是当下、不是 seed 的回拨日期）——2026-09-23 实测：23:38 一次《Harry Potter》5/5 入账 78000 词 | 按清场复原（`.venv/bin/python -m scripts.check_demo_baseline`，**不带** `--no-clean`）回 109320/1133。**若想保住这次真实阅读**，就别清场，改为同步改 `docs/04` 演示口径与 `check_demo_baseline` 的 `DEMO_FIGURES`（要用户拍板） |
| 重登小程序后首页数字与孩子对不上（名字对、数字是别人的） | 重登脚本**沿用了旧的 `currentChildId`**：清场重建会重排 id，旧 id 现在属于别的孩子；而"我的/首页"的数字来自服务端实时查询、名字来自登录缓存 | 重登时**先 `wx.removeStorageSync('currentChildId')`**，再按登录响应的 `children[0].id` **强制覆盖**写入（见下方命令块 → docs/15 §二十 纪律 3） |
| DELETE/UPDATE 中文条件匹配 0 行 | 连接未设 utf8mb4 | 检查连接串 charset（插修 19 T-B 教训） |
| 小程序"我的"页显示**别的家长的孩子**（如"演示家长 正在陪伴 导出孩甲"） | ① 跑过 pytest 只做 `restart`（未清场）→ 测试造的孩子残留库里；② 清场重建后**小程序还留着旧登录态**——旧 token 里的 `parent_id=1` 在重建后指向了另一个家长，而"我的"页每进一次都会**从服务端拉孩子列表**（家长资料却是登录时的缓存）→ 拼出"张冠李戴"的画面 | ① 按本手册 §一 第 4 步 ① **走清场路径**（`check_demo_baseline` 不带 `--no-clean`），别图省事用 `--no-clean`；② **清场重建后必须重新登录小程序**（`automation_evaluate` 打 `/api/miniapp/login` 写 storage，见 docs/15 §二十 纪律 3）。**这是演示环境特有的**（生产 id 不重排、不会出现），产品代码无需改 |
