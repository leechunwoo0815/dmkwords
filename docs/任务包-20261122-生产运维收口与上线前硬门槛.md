## 任务清单（按序执行；标注【等甲方】的先跳过做后面的）

### T1 · SSH 收口（治 P1-9；可立即执行，全程零停机）

1. 验证密钥通道：`ssh -o PreferredAuthentications=publickey -o ConnectTimeout=10 ecs true` 成功输出 true（已由主审查会话预验证通过）。
2. 备份：`ssh ecs 'sudo -n cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak-20261122'`。
3. 改两行：`PermitRootLogin prohibit-password`、`PasswordAuthentication no`（注意确认没有被 `/etc/ssh/sshd_config.d/*` 或行尾旧配置覆盖）。
4. `sudo -n sshd -t` 通过 → `sudo -n systemctl reload sshd`（reload 不断当前连接）。
5. **验收**：新开会话 `ssh -o PreferredAuthentications=password ecs true` 被拒（Permission denied）；密钥新会话正常；`sudo -n sshd -T | grep -Ei '^(permitrootlogin|passwordauthentication)'` 显示 `prohibit-password` / `no`。当前会话保持不断。
6. **证据留痕**：以上命令输出贴简报 + LEDGER 行。
7. **回滚**：`cp /etc/ssh/sshd_config.bak-20261122 /etc/ssh/sshd_config && systemctl reload sshd`（1 分钟内可恢复）。

### T2 · 安全组盘点（15 分钟；需甲方在控制台核对，你只出清单）

产出一份盘点表（控制台截图由甲方提供）：22 / 80 / 443 / 8888 各自的来源规则；3306/33060/888/8002 保持关闭（外部 filtered 已实测）。建议项（甲方拍板，不强制）：22 限固定 IP。8888 按决策留痕 1 保持现状、只登记。

### T3 · 告警通道贯通（45 分钟；**【等甲方】webhook URL**）

1. 甲方提供企业微信/钉钉群机器人 webhook URL → 生产 `/opt/dmkwords/.env` 追加 `BACKUP_ALERT_WEBHOOK=<url>`、`DISK_ALERT_WEBHOOK=<url>`（追加不回显内容）。
2. crontab（lcw）追加：`*/10 * * * * cd /opt/dmkwords && bash scripts/disk_alert.sh >> backups/disk-alert.log 2>&1`。
3. `log_alert.sh` 调度从每日 9:00 改每小时（`0 * * * *`），并在脚本环境里设 `LOG_ALERT_SINCE="70 minutes ago"`（避免窗口重叠/漏扫；脚本本身支持 `since` 参数，先读 `scripts/log_alert.sh` 确认参数形态，不改逻辑只改调度口径，属 B″ 级脚本刀，改完 `bash -n` + 跑一次真实巡检）。
4. **验收**：阈值演练一次（临时把 disk_alert 阈值调到当前用量以上 → 手机真收到推送 → 还原）；`backup_status.sh` 手动注入一次失败（临时改错一个无关紧要的键或断开式演练，勿动备份产物本体）确认 webhook 推送到达。

### T4 · 外部拨测（30 分钟；治 P1-10）

阿里云云监控「站点监控」（或 UptimeRobot 免费档）：`https://saisenyoo.cn/health` 每 1–5 分钟、两个探测点、告警走**短信+邮件第二通道**；另加证书到期监控（Let's Encrypt，续期 cron 在但要有外线兜底）。**验收**：与甲方配合演练一次——手动 `systemctl stop dmkwords-backend` 30 秒（**挑审核员不活跃时段，先与甲方确认窗口**；stop 期间 `/health` 502 → 收到告警 → 立即 start 恢复 200）。若甲方不允许审核期演练，此项降级为"配置完成、演练挪到审核结论后"，如实留痕。

### T5 · 异地备份 OSS（2–3 小时；**【等甲方】开通 OSS + RAM 子账号**）

1. 甲方开通：OSS bucket（杭州、私有读写、SSE 加密）+ RAM 子账号（仅该 bucket 的 Put/Object/List 权限）+ 30 天生命周期规则。
2. 服务器安装 rclone（或下载单文件二进制），配置 remote；AK 存 `/root/.config/rclone/rclone.conf` 或 lcw 家目录 `600` 权限，**不进仓库**。
3. cron：`30 5 * * * rclone copy /opt/dmkwords/backups oss:dmkwords-backup --transfers 4 --min-age 10m --bwlimit 20M >> backups/rclone.log 2>&1`（**用 copy 禁 sync**——本地 14 天保留 + sync 镜像语义会在第 14 天删 OSS 副本）。
4. 周日 `rclone check` 对拍一次；日志进 `backups/rclone.log`。
5. **验收**：OSS 控制台见 2 天副本；**从 OSS 下载最近一个全量 → 恢复到临时库 `dmkwords_restore_check` → 关键 8 表行数对拍**（不是只 check 字节）；rclone.log 无 ERROR。
