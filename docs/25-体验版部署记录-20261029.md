## 六、CentOS 7 部署坑（下次照做）

1. **glibc 2.17**：`greenlet 3.5.5`、`Pillow 13` 只有 glibc 2.28 的 wheel → 服务器改用
   `greenlet==3.2.4`、`Pillow==12.0.0`（均有 manylinux2014 wheel）。
2. **`uv sync --frozen` 不认镜像**：它按 `uv.lock` 里的 `files.pythonhosted.org` 下载，`UV_INDEX_URL` 覆盖不了；
   改用 `uv export --format requirements-txt --no-hashes` + `uv pip install -r ... --index-url 腾讯镜像`。
3. **Pillow 13 源码编译会链到 CentOS 7 旧 FreeType**，运行期 `FT_Done_MM_Var` undefined → 换 Pillow 12 的
   manylinux2014 wheel（自带 FreeType）。
4. **编译类包用 devtoolset-11**（CentOS 7 自带 GCC 4.8 太老）；SCL 仓库需把 baseurl 指向
   `https://mirrors.aliyun.com/centos-vault/7.9.2009/sclo/x86_64/rh/`。
5. **Alembic 读中文注释需要 UTF-8 locale**：`LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 PYTHONUTF8=1`；

## 十二、2026-10-30 播放器重做 + 阅读圈图片自愈

### 1. 听书播放器（客户端，需上传 0.1.3）

- **根因**：三个入口（书详情/首页/书架）都只传 `book_id`，reader 的 `duration` 只认入口对象 → 恒 0；
  `sliderMax = max(1, 0) = 1` ⇒ 时长 `0:00`、滑块永远卡最右。iOS `audio.duration` 对部分 MP3 恒 0，
  不能作为总时长真源。
- **改法**：进页必拉详情；**时长唯一真源 = 后端 `audio_duration`**；未知时长显示 `--:--` + 滑块禁用；
  状态机 idle/loading/playing/paused/ended/error（错误码 + 重试）；拖动不被 `onTimeUpdate` 顶回；
  续播贴尾不续、播完可重听；seek epoch 防在途上报回写旧起点。
- **上传**：开发者工具 → 上传 **0.1.5** → 公众平台「版本管理」设为体验版（0.1.2～0.1.4 仍有旧问题）。
- **续播竞态（2026-10-30 甲方报障）**：进度接口先回、音频实例后建时续播被跳过；iOS 的 `canplay`
  又常在按下播放后才触发，于是从 0 开始。修法：`_applyResume` 在「建实例后 / canplay / 起播前 /
  onPlay 后」四处触发，且只有 `onSeeked` 回报落点才算完成（音频未就绪时 seek 会被丢弃）。
  模拟器实证：60 秒书 + last_position=30 → 进页 `0:30`、播放 2 秒后 `0:32`。

### 2. 阅读圈图片 404（服务端，需部署）

- **根因**：`uploads/circle` 属可再生目录，但 `post_card_image` 只回库里的 `image_path`、
  文件缺失**不重渲染** → 清缓存后管理端/小程序全 404。
- **改法**：`card_render.ensure_post_images` 单帖自愈（缺失才渲染、只补缺失列、坏快照不渲染空卡），
  admin/miniapp 的 image/thumb 端点取路径前先自愈。
- **部署后**：打开管理端阅读圈，首屏会逐帖重建（每张 ~0.2–0.5 秒），之后走原文件；
  验证 `GET /api/admin/circle/posts/{id}/image?token=…` = **200 + image/jpeg**。
