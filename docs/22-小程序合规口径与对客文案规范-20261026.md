# 22 · 小程序合规口径与对客文案规范（2026-10-26）

> 适用：微信小程序（家长端）全部**用户可见文案**、微信支付**商品描述**、家长通知/订阅消息文案。
> 性质：工程口径规范，**不构成法律意见**；最终表述以法务审阅与平台审核结果为准。

## 一、背景与边界

| 项 | 事实 |
|---|---|
| 主体 | 上海杜蒙文化传播有限公司（统一社会信用代码与注册地址以营业执照为准） |
| 经营范围 | 组织文化艺术交流活动、文艺创作、文化场馆管理服务、图书管理服务、文具用品零售、体验式拓展活动及策划等 |
| 主体资质缺口 | **不含出版、出租、教育培训**类许可 |
| 小程序类目 | 甲方已选「工具 - 预约/报名」；是否补挂生活服务族类目由甲方在公众平台按实际类目树确定 |
| 支付 | 使用微信支付；**不得售卖任何虚拟服务**；费用须呈现为线下服务费，线上仅为付款方式 |

本文只解决"**怎么说**"（对客文案与支付描述）；"**选什么类目/商户行业**"属于甲方后台操作，见 §七。

## 二、五条总则

1. **线下实体服务口径**：图书借阅发生在馆内（到店取书/还书）；活动为馆内线下活动。
2. **线上支付 = 付款方式**，不是服务交付方式；会员权益以到店核验/馆方确认为准。
3. **线上功能是附赠权益**：随书配套音频、阅读小挑战、生词本、打卡、成长报告随会员借阅服务附赠，**不单独售卖**。
4. **禁用词**（对客可见层）：出租、租赁、课程、培训、教育、教学、课时、图书馆、绘本馆、老师、测验、成绩单、线上课程。
5. **费用命名**：会员费 → 线下会员服务费；活动费 → 线下活动服务费；押金 → 图书借阅押金。

### 4.1 后端（支付描述与通知）

| 文件 | 符号 | 口径要求 |

| `backend/domain/identity/payment_service.py` | `TYPE_LABELS` | 六个订单类型的支付商品描述/方案名/订单备注统一为线下服务口径（见下表） |

### 4.3 管理端

管理端属内部运营界面，不在微信审核面，本轮**不做**对客文案改造。
项目内**不存在**对客收据/小票功能（`admin-web/src` 全量搜索 `收据/小票/receipt` 零命中），专家复核提出的"导出口径"建议作废；将来新增该功能时再按 §二 执行。

## 五、专家复核订正记录（2026-10-26）

1. **并入 6 处漏项**：`leaderboard.wxml`、`report.wxml`、`privacy-policy.wxml`、`withdrawal.wxml`、`quiz-result.js`、`book-detail.wxml`（老师）。
2. **订正 2 处引用**：押金页实际文案是「可用余额/已扣除/标准押金」，不存在「押金余额」；用户可见层不存在「及格」一词（实际为「测验通过/再试一次」）。
3. **删除 1 条悬空建议**：项目无对客收据/小票功能。
4. **采纳 3 消费点提示**：`TYPE_LABELS` 同时喂方案名、订单备注、微信支付描述；改后三处均需验证。
5. **类目名不定论**：专家第十轮拉取的微信支付官方类目表中未见「会员俱乐部/文化场馆管理服务」字样，本轮在线检索也无法坐实。因此**代码与文档不写死该名称**；商户号行业以管理员在商户平台表单中的实际类目树为准（优先无特殊资质的生活服务族）。

## 六、验证方式

- `tests/unit/test_compliance_copy_20261026.py`：
  ① 禁用词静态扫描（小程序 wxml 去注释文本 + json 导航标题/tabBar + js 用户可见字符串）；
  ② `TYPE_LABELS` 六条均为线下服务/图书借阅口径且不含禁用词；
  ③ 每个引用 `session.*` 的小程序 JS 必须有模块级 `require`（防 `purchase.js` 同类运行期 ReferenceError）；
  ④ **三消费点运行时探针**（购买页方案名 / 订单备注 / 微信支付描述）；
  ⑤ **家长可见的后端字符串**（`PARENT_FACING_MODULES`，跳过 docstring；管理端专用字符串逐条登记）。
- 端上证据：`docs/compliance-ide/`（2026-10-26 七页截图 + 复现命令；判据 ⑤ 就是端上取证抓到的漏网）。
- 定向检查器：`check_miniapp_style`、`check_copy_emoji`、`check_docs_code_alignment`。

## 七、人工动作（不由代码完成）

1. 公众平台：小程序名称/简介/服务类目复核（甲方）；类目是否补挂生活服务族由甲方按实际类目树决定。
2. 商户平台：超级管理员选择行业时**以表单内真实类目树为准**，优先无特殊资质的生活服务族；不要照抄未核实的类目名。
3. 服务协议/隐私政策最终文本交法务审阅（页面顶部仍有"待法务审阅"占位提示）。
4. 提审前用真机走一遍：购买页、订单列表、微信支付账单，确认三处显示一致（方案名/备注/账单描述）。
