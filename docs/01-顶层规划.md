# 01 顶层规划（DmkWords v1.0）

> 依据：业务需求文档定稿 V1.1 + 决策链 V1.0.1 + 2026-08-22 四项架构终裁。
> 本文档回答：项目做什么、分几步做、怎么治理、做到什么程度算完成。

## 1. 项目边界

- **做**：线下实体英文图书馆 + 线上阅读成长管理的完整运营系统（小程序 + 管理后台 + 后端）。范围 = 业务需求文档 V1.1 全部章节；
- **不做**：业务需求文档第十三章 23 项"本期不做"清单（分享社区/班级教学/盘点/离线借还/字幕/短信/积分兑换等）——此清单为开发范围唯一边界；
- **非我方交付**：图书音频录制（甲方线下生产，但为上线前提，进度需跟踪）；微信小程序主体/类目/商户号资质（甲方持有，申请状态需跟踪）。

## 3. 治理与决策机制

| 事项 | 决策者 | 机制 |
|---|---|---|
| 业务规则/数值 | 甲方 | 书面确认进决策链；口头不算 |
| 架构/技术选型 | 架构师（AI） | 产出 ADR（背景/备选/取舍/后果），重大项知会甲方 |
| 宪法修改 | 架构师提案 + 甲方/用户确认 | 禁止 AI 自行修改 |
| 完成判定 | 门禁脚本 | `gate.sh full` 退出码 0，唯一裁决，禁止读输出文本自行判定 |
| 进度事实 | `docs/LEDGER.md` 台账 | 状态流转必须先落证据（gate-runs/）再改台账 |
| 需求变更 | 甲方书面 | 变更 → 冲突检查（rg 全库同口径）→ Feature/Gherkin 局部更新 → 台账登记 |

## 4. Definition of Done（三层）

- **单任务 DoD**：门禁全量命令退出码 0 + 证据落盘 + 台账流转 + 提交；
- **单 Feature DoD**：四件套齐全 + Gherkin 场景全绿（覆盖正常/边界 [-1,0,+1]/异常路径）+ 覆盖率达标 + 数值全配置化 + 架构关通过；
- **阶段 DoD**：里程碑验收项通过 + 回归全绿 + 文档（API/配置/部署说明）同步。

## 5. 风险控制点

见 `08-风险登记册.md`。Top3 需主动管理：大模型施工漂移（对策：按图施工手册+门禁）、需求再变（Gherkin 需求锚点标注，局部替换）、微信资质阻塞（立即启动申请跟踪）。
