## 附：验证分级纪律（2026-08-24 由用户裁定，立即生效）

### 9.2 门禁单测+覆盖率双跑合并（用户裁定：先方案 1+2）

- **实测数据**（gate-wm1013-fix4.log）：原步骤 [2] 纯单测 550s + [7] 同批测试带
  覆盖率 712s = 两遍跑同一批 315 测试，占总时长 96%，且双轮内存高峰（用户机器
  swap 5.5GB）；其余步骤合计 <3 分钟。
- **裁定**：合并为单次 `pytest --cov --cov-fail-under=25 --durations=20`
  （[2]/[7] → [2]，tsc 顺位 [8]→[7]）；预计门禁 22 分钟 → ~13 分钟（-42%）；
  `-x` 快速失败语义随合并取消（门禁本就要看全貌）；cov 卡线照常拦截。
- **铺路**：`--durations=20` 每轮输出 top 慢测试清单，为 pytest-xdist 分库并行
  （方案 3，理论再省 50%+）积累数据——真实 MySQL + 每测试 TRUNCATE 25 表重 seed
  是反假绿的代价，单测试均 ~1.7s，并行是唯一根治路径，挂横切-门禁债批次。
- 历史锚点：§八覆盖率偿债窗口的第二步（抬线）仍待 WM11 后偿债窗口执行，
  本裁定不动卡线（25% 保持）。
