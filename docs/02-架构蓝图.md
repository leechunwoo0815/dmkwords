## 2. 八域划分与依赖（箭头=允许的读方向/事件流）

```text
identity(账号/会员/转让) ──事件──▶ billing(订单/押金/退款)
     │                              │事件
     ▼                              ▼
circulation(借还/预约) ◀──额度── reading(进度/Quiz/词数)
     │                              │事件(词数入账)
     ▼                              ▼
catalog(书目/副本/音频)        growth(等级/积分/榜单/报告)
     ▲                              ▲
     └────── activity(活动/报名) ────┘
admin(RBAC/配置/看板/通知) = 横切编排层，不持有业务规则，禁止域反向依赖
```

跨域写副作用唯一通道 = EventBus（同步共享事务，发布先于 commit）；跨域读走白名单单向边（架构门禁执法）。

**横切防护层（2026-09 增补）**：
- **权限矩阵 guards**（identity/guards.py）：会员态 × 动作（BORROW/RESERVE/AUDIO）矩阵——AUDIO 2026-09-08 落地（C-13 提前：未缴费禁/在册允/过期仅手头在借允/退会禁），audio 流+进度上报双端点同源收口，播放入口前置预检端点共享同一判定（禁漂移）；
- **admin-web ErrorBoundary**（2026-09-08，E-20260831-04 欠账清偿）：根部兜底捕获渲染异常（antd5 DatePicker 传 JS Date 白屏事故驱动），单点渲染错误≠全站白屏；
- **退款执行六项复核**（2026-09-07 T41/H-1）：`_outstanding_obligations` 共享方法（退款六项与退会 7 项前提同源加法结构），会员资格类+押金单触发，「人工放行：」备注前缀豁免+审计 manual_override 字段。

## 3. 关键数据流（三条主干）

1. **资金流**：下单 →（微信回调/人工确认）→ 订单 paid → 事件 → 会员开通/押金状态 → 退款申请 → 超管审核 → 原路退/人工退登记。全程 Decimal + 状态机 + 行锁 + 幂等（模式手册 P1-P9）；
2. **阅读成果流**：音频进度上报（防刷校验）→ 95% 判定 → 一次性触发（时长+打卡+Quiz 解锁）→ Quiz 提交（快照）→ passed → 同事务入账（词数唯一约束+积分折算+等级进度）→ 事件 → 榜单/里程碑/报告；
3. **借阅流**：识别学生 → 锁主体行 → 校验（会员/押金/额度=30−逾期数/副本状态）→ 副本行锁 + 原子扣库存 → 借阅记录 → 事件（库存/副本状态联动）；预约为 reserved 锁定 72h 定时释放。

## 5. ADR 索引（决策全文见 docs/ADR/）

| # | 决策 | 结论 | 否决的备选 | 核心理由 |
|---|---|---|---|---|
| ADR-001 | 部署形态 | 单机 Docker Compose；开发用 OrbStack | K8s/微服务 | 单馆规模，复杂度即风险 |
| ADR-002 | 域结构 | 8 域（+growth/activity vs 旧 7 域） | 旧 7 域 | 活动/成长激励无家可归会挤肥 admin/report |
| ADR-003 | 数据库 | MySQL 8.0 only + alembic 全 schema | SQLite 开发分支 | 环境同构；旧项目 with_for_update 教训 |
| ADR-004 | 音频存储 | 本地磁盘 + 存储抽象层预留 | OSS/COS | 零成本零备案复杂度；可后迁 |
| ADR-005 | 缓存/锁 | 不引入 Redis；JWT 无状态+进程内锁 | Redis | 单机够用；开发机内存受限 |
| ADR-006 | 协作流程 | trunk-based + 门禁即审 | GitFlow/人工 PR 评审 | 单人+AI，门禁比人审可靠 |
| ADR-007 | 前端 | React18+TS+AntD / 小程序原生 | Jinja2/Taro | 旧宪法第十节论证沿用（类型=编译期门禁） |
| ADR-008 | 定时任务 | 进程内 APScheduler | Celery/独立 worker | 单机规模；任务逻辑在域 service |
| ADR-009 | 完成流程 Demo | 系统配置管理为样板 Feature | 借书流程 | 小而全，覆盖 TDD/BDD/门禁全链路 |

## 6. 异常处理策略

- Service 层统一异常体系（ValidationError/ConflictError/PaymentError…→ HTTP 映射在公共层）；
- 资金网关调用三段式（PENDING→commit→调网关→终态），失败保持 PENDING 由僵尸单清理任务善后；
- 定时任务全量幂等（幂等键）+ 失败重试 + 失败写站内告警；
- 通知双通道：站内必达 + 微信订阅尽力，发送状态全记录。
