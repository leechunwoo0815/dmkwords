### 3.8 封面预览"又小又糊"五层修复（commit `53d0bd9`，用户报障）
用户报障轨迹（每次都是复验时当场发现下一层，**说明"一次修一层"必然被打回来**）：
1. **① 尺寸链**：antd `.ant-image-preview-img{max-height:70%}` 是**百分比高度**，而预览 wrapper 绝对定位 +
   flex 居中，父级高度在 **Safari** 下按内容算 → 链退化：784 高窗口里预览只剩 212px（Chromium 是 549px）。
   → 改**视口单位** 82vh。
2. **② 竞态（真凶）**：预览大图没有显式 width/height，布局取决于"解码出的 intrinsic size"，挂载时未解码完
   就按错尺寸栅格化且 **Safari 不回刷**（Chromium 会重栅格化 → 我侧复现不出）→ "每次刷新换一本书"。
   → `useNaturalSize()` 预加载取真实尺寸交给预览 + `object-fit: contain`（否则 max-height 会把图**压扁**）。
3. **③ 预滚帧**：rc-motion 的 appear class 晚一帧，动画前先按最终位置画约 60ms → "先闪一下再跳到起点"。
4. **④ 动画重做**：③ 我把动画整个关掉了，**用户否掉**（原话「以前有动画的，就很丝滑，点击之后像直接从小图
   放大到大图的预览」）→ 改为自己写 `pv-fly-in`：点击瞬间把缩略图相对屏幕中心的位移/起始缩放写进
   `--pv-dx/--pv-dy/--pv-scale`，img **从第一帧**即起始态飞入居中。逐帧实测首帧 101×108 @(272,285)
   （缩略图 72×100 @(277,289)）→ 平滑到 600×643。
5. **⑤ 滚轮滚页面**：`.ant-image-preview-wrap` 带 rc-dialog 的 `overflow-y:auto`，Safari 把滚轮默认行为
   落在它身上（出滚动条、图被滚走）；rc-image 的滚轮处理器是**被动监听**、`preventDefault` 无效
   → `.ant-image-preview-wrap{overflow:hidden}`。
- 用户 2026-09-17 复验：「ok 了，没问题了」→ **ACCEPTED**。错误库 **§八十一 / E-20260917-42**（五层全记）。
