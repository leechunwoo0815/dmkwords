## §禁做清单 v173（照着旧结论/旧路径做会翻车）

1. **CI `cancelled` ≠ `failed`**：连续 push 时 concurrency 取消上一 run。只看最新 run 的 conclusion；最近真实失败是 docs job 的两次（依赖/浅克隆），已修。
2. **docs-only CI 三件套别拆**：`core.quotepath=false`（中文路径带引号）、`uv sync --frozen`（配置键 60 vs 正则 53）、`fetch-depth: 2`（浅克隆把整棵树当新增，历史 LEDGER 尾随空格误报）。
3. **备份脚本别回退**：`backup_db.sh` 必须保留 `--no-tablespaces`（生产账号无 PROCESS）；`mysqlbinlog --raw --result-file=X` 会**追加原文件名**，必须传临时目录 + 结尾 `/`；`restore_check.sh` 的库名必须含 `restore_check`。
4. **PFS 不要随手开**：`performance_schema=OFF` 是省 321MB 的生产决定，`my.cnf.bak-20261106` 是回滚锚点；开回前先算内存。
5. **测试点赞必须清**：生产 post 9 / 本地 post 10 是临时目视数据，**正式上线前必须删除**并把 `like_count`/`admin_liked` 恢复原值。
6. **小程序只认 0.1.12（未上传）**：0.1.8（旧隐私）、0.1.9（无点赞墙）、0.1.10（点赞行挤）、**0.1.11（审核已驳回）** 都不要提审。
7. **0.1.11 的 CSS 没有 CI 全量**（被并发取消）：别声称它过了全量门禁；下次代码推送会补。
8. **生产探针不写数据**：除本次经甲方授权的测试点赞外，验证口径一律用只读请求。
9. **部署路径**：前端 `/opt/dmkwords/admin-web/dist`（先备份再 `rsync -az --delete`）；后端 rsync 后 `sudo systemctl restart dmkwords-backend`，核 `/health` 200 + 日志无 error。
10. **别再把真机 baseURL 绑到 `envVersion`**（2026-11-12 审核驳回根因）：`envVersion === 'develop'` 在审核环境同样成立，会把审核员请求打到内网 `192.168.18.162:8443`，表现是「网络异常」而服务端零日志。真机一律生产、模拟器才走本地，真机联调靠 `dev_base_url` 覆盖。
11. **演示 token 的只读是服务端保证**：`get_current_parent` 对 `demo:true` 的非 GET/HEAD/OPTIONS 一律 403（`/logout` 例外）；不要退化成"前端隐藏按钮"的软约束。
12. **`get_settings()` 是 `@lru_cache`**：测试里改 `DEMO_LOGIN_PHONE` 等环境变量后必须 `get_settings.cache_clear()`，否则端点读的还是导入时那份（首批实测一直 422）。
