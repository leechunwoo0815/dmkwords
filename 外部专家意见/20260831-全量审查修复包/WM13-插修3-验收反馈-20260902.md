## W1 RefundCenter tab 标签语义

- **现象**：用户批准退会后，退会待审 tab 显示 0，但记录在表内且可操作「执行退款」——
  "待审 0 却有活干"观感矛盾。
- **根因**：`RefundCenter.tsx:170/226/267` tab 标签「退款待审（N）」N 只数 pending，
  但表格显示全量记录（含 approved 待执行/processing/completed）。
- **修复**：三个 tab 标签改为双计数——
  - 退款：「退款（待审 N · 待执行 M）」M=approved+failed 数，M>0 时 M 红字
  - 退会：「退会（待审 N · 退款中 M）」M=refunding 数
  - 转让：「转让（待审 N）」（转让无执行态，保持）
  - 数据源：三个 tab 的列表数据已在手（pendingRefunds 等数组同文件），纯前端计算
- **gate**：tsc。

## W2 通知列表 60s 轮询（页面激活时）

- **现象**：小程序申请新退款后，管理端通知列表不刷新看不到（徽标会变——那是
  useTodoCounts 60s 轮询；列表只在进页/切 tab 拉）。
- **证据**：`Notifications.tsx:210-213` useEffect 仅依赖 box/loadParent/loadInbox。
- **修复**：列表加载挂 60s setInterval（与 useTodoCounts 同周期），依赖页面可见性
  （document.visibilityState，隐藏时暂停避免后台空转）；卸载清理。复用既有
  loadInbox/loadParent，不新造请求。
- **gate**：tsc。

## W3 凭证预览图限高整屏显示

- **现象**：查看收款凭证 Modal 图片过大需滚轮上下看。

## W5 小程序退款申请撤销入口（WM13 灵魂设计 S1 前端断链）【高】

- **现象**：用户在小程序找不到退款申请的撤销入口（无按钮无入口）——
  WM13 验收动线步骤 10（S1 撤销反例：撤销后管理端显示"已失效·家长已撤销"）
  无法执行。
- **三层证据（专家全链实锤）**：
  1. 后端**全就绪**：`wm10_service.py:190` RefundService.cancel +
     `miniapp_router.py:192` `POST /refund-requests/{request_id}/cancel`
  2. `miniapp/utils/api.js` **缺封装**：有 cancelTransfer(L105)/cancelEnrollment(L125)/
     cancelReservation(L181)，独缺 cancelRefund
  3. `refund-apply.wxml:41-43` **缺按钮**：渲染了"我的退款申请"列表（tip-card），
     每行无撤销按钮
- **修复**（纯小程序前端，后端零改动）：
  1. api.js 加 `cancelRefund(requestId)`（对齐 cancelTransfer 模式）
  2. refund-apply.wxml 退款申请行：`status === 'pending'` 时显示「撤销申请」按钮
     （样式对齐页面既有按钮），非 pending 态不显示（已审结/已失效不可撤）
  3. refund-apply.js 加撤销处理：wx.showModal 确认（"撤销后需重新申请"）→
     api.cancelRefund → 成功后 load() 刷新列表
- **后端 cancel 语义复核**（施工前必读 `wm10_service.py:190-228`）：撤销仅
  pending 态可撤（已审结拒撤），撤后 RefundRequest → cancelled；管理端
  todo_service 已有 cancelled → "已失效·家长已撤销" 显示逻辑（零改动）。
- **验证**：真机/模拟器——申请退款 → 列表见「撤销申请」按钮 → 点击确认 →
  列表该行消失/状态变已撤销 → 管理端待办该行变灰"已失效·家长已撤销"（S1 闭环）。
- **gate**：tsc 不覆盖小程序（无 TS）——验证走真机目视 + 后端行为已有测试覆盖
  （test_wm13 系列含 cancelled 态）；如需测试层保障，后端 cancel 端点已有测试
  则纯前端改动免测。
- **BDD**：features/refund.feature 若已有撤销场景（rg 显示该文件含"撤销"），
  核对是否走 UI 入口（BDD 走 API 层则本卡无需新增）。
