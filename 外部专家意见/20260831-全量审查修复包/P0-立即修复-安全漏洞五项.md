## P0-F1【阻断】reading 域 6 个小程序端点缺 child 归属校验，可水平越权操作任意孩子

- **验收可见性**：验收测不出（需双家长账号构造攻击场景）——但双账号验收时会**互写脏数据**（A 账号操作误写 B 孩子），修掉后验收数据才干净
- **证据**：`backend/domain/reading/miniapp_router.py:157-221`，6 个端点全部为 `db.query(Child).filter(Child.id == child_id).first()`，无 `Child.parent_id == parent.id` 过滤：

```text

def report_progress(body: ProgressReportRequest, auth: Any = Depends(get_current_parent)):
    _, db = auth
    child = db.query(Child).filter(Child.id == body.child_id).first()   # ← 无归属校验
    if not child:
        raise ValidationError("孩子不存在")
```

受影响端点（全量）：`GET /books/{id}/progress`(L158)、`POST /reading/progress`(L167)、`GET /checkins`(L178)、`GET /reservations`(L186)、`POST /reservations`(L203)、`POST /reservations/{id}/cancel`(L213)。

同文件 L324-332 已有现成规范函数 `_child_of_parent`，但这 6 个老端点（WM6 交付早于该规范引入）未使用。identity/billing/growth/activity 四域抽查 15 端点归属校验齐全，唯 reading 域失守。

- **现象与根因**：家长 A 的 token + 家长 B 的 child_id（自增可枚举）可：读 B 孩子进度/打卡/预约、**替 B 孩子上报进度（污染防刷数据与积分）**、替 B 创建预约（消耗 B 额度+锁死公共副本 72h）、取消 B 的预约。根因：老端点未回刷新规范。
- **附带 bug**【事实】：`list_reservations` L189-190 对 child 无 None 检查即调 `list_mine(child)`，child_id 不存在时 `child.id` → AttributeError → 500。本卡修复顺带解决。

- **修复方案**：6 个端点统一改用文件内现成的 `_child_of_parent`。以 `report_progress` 为例（其余 5 个同模式）：

```text

child = db.query(Child).filter(Child.id == body.child_id).first()
if not child:
    raise ValidationError("孩子不存在")
return ReadingService(db).report_progress(child, body.book_id, body.position, body.session_start)

# 修复后（_child_of_parent 内部已做 parent_id 归属校验 + None 检查，

child = _child_of_parent(db, parent.id, body.child_id)
return ReadingService(db).report_progress(child, body.book_id, body.position, body.session_start)
```

注意：先读 `_child_of_parent` 的实际签名（L324-332，参数可能是 `(db, parent_id, child_id)` 返回 Child 或抛错），按真实签名接线；`get_current_parent` 返回的 auth 解包出 parent 对象后取 `.id`。

- **证据**：`backend/domain/catalog/media_auth.py:12-23`：

def authorize_media(request, token: str = "") -> None:
    header = request.headers.get("authorization", "")

    if not auth_token:
        raise UnauthorizedError("未登录")

    admin = db.query(AdminUser).filter(AdminUser.id == int(payload["sub"])).first()

## P0-F4【阻断】押金赔偿金额无校验：负数金额反向增加可用余额，非法字符串直接 500

- **验收可见性**：**验收必撞（若你测负数/乱输入）**——押金赔偿弹窗输入 -100 会真的反向加钱；修复后变 422
- **证据**：`backend/domain/billing/router.py:44-45` + `billing/service.py:164-170`：

```text
# router.py L44-45 — amount 用 str 接收，无任何约束
class DeductRequest(BaseSchema):
    amount: str = Field(..., description="赔偿金额（元）")

# service.py L167-170 — 裸 Decimal() + min 钳制防不住负数
deduct = min(amount, dep.available_amount)
dep.available_amount = (dep.available_amount - deduct).quantize(...)
dep.deducted_amount = (dep.deducted_amount + deduct).quantize(...)
```

- **现象与根因**：① `amount="-100"` → `min(-100, 200)=-100` → `available_amount = 200-(-100)=300`，余额不降反升，台账记负数发生额；押金余额是退会结算退款依据，虚增会**多退真钱**。② `amount="abc"` → `decimal.InvalidOperation` 未捕获 → 500。触发权限仅 `member.manage`（staff 即可）。根因：金额 str 接收 + service 假设 amount≥0 未防御。
- **修复方案**（两层）：

```text
# 第一层 router.py — Pydantic 直接拒（422）
class DeductRequest(BaseSchema):
    amount: Decimal = Field(..., gt=0, max_digits=10, decimal_places=2,
                            description="赔偿金额（元）")
# （Pydantic v2 对 Decimal 支持 gt/max_digits/decimal_places 约束）

# 第二层 service.py deduct_for_compensation 入口防御
    if amount <= 0:
        raise ValidationError("赔偿金额必须大于 0")
```

  同步核对：router 里调用处的 `Decimal(body.amount)` 改为直接 `body.amount`（已是 Decimal）。
  **前端核对**：检查 `admin-web/src/pages/DepositManage.tsx` 提交 amount 的格式（字符串"50.00"或数字均可被 Pydantic 解析；若前端传了非数字字符，修复后将从 500 变 422，前端 catch 显示 detail 即可）。
  **同族排查**（施工时顺带 grep 核对同类写法是否还有）：`rg "amount: str" backend/domain/`——审查时 billing 域其他金额入口未见同款，以此卡为准全量确认一次。
- **测试要求**：`tests/unit/test_wm4_deposit.py` 增用例：
  1. `POST /api/admin/deposits/children/{id}/deduct {"amount": "-1", ...}` 断言 422（**修复前 200 且余额+1，RED**）
  2. `{"amount": "abc"}` 断言 422（修复前 500）
  3. 正常 `"50.00"` 断言 200 且 `available_amount` 减 50、`deducted_amount` 加 50
  4. 边界 `0` 断言 422（gt=0）
- **验证等级**：B 级（billing 域）→ 相关 pytest + ruff
- **施工顺序**：无依赖。修复后用 `python -m pytest tests/unit/test_wm4_deposit.py -q` 验证
