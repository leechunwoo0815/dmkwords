## 〇、统一模板（先读这个，10 张卡同模式）

项目里已有两段教科书级并发模板（审查确认无缺陷，作为修复参照）：

**模板 1：主体行锁**（`circulation/service.py:102`，borrow 锁 Child 串行化同孩子操作）：

```text
child = (
    self.db.query(Child)
    .filter(Child.id == child_id, Child.is_deleted == 0)
    .with_for_update()          # ← 锁定读：后续校验与写入基于当前值，并发方排队
    .first()
)
```

**模板 2：锁内查重**（`activity/service.py:400-434`，报名锁 Activity 行后名额检查零超卖）：
名额/查重/状态校验全部放在拿到行锁**之后**——B 拿锁后读到的是 A 已提交的新快照。

**修复原则**：所有资金状态机的"读→校验→写"，入口读主体行时加 `with_for_update()`
（宪法铁律 5：资金面 = 状态机矩阵 + 行锁 + 幂等 + Decimal）。ORM flush 的 UPDATE
按主键无条件覆盖，**应用层 if 校验挡不住并发**——这是全部 10 张卡的共同根因。

**并发测试基建**（本包新增一次，全部卡复用）：
`tests/unit/conftest.py` 增加双 session fixture：

```text
@pytest.fixture
def session_pair():
    s1 = SessionLocal()
    s2 = SessionLocal()
    try:
        yield s1, s2
    finally:
        s1.rollback(); s2.rollback()
        s1.close(); s2.close()
```

并发用例写法：session A 手动开启事务并锁定主体行（模拟先到者未提交），session B
走被测 service 方法——B 应**阻塞后失败**（或看到 A 提交后的新状态）而非覆盖写。
注意 MySQL REPEATABLE READ 下需 `db.commit()` 或 `db.expire_all()` 刷新快照
（项目已有先例注释：test_wm13_admin_notify.py:487）。

```text
        self.db.query(RefundRequest)
        .filter(RefundRequest.id == request_id, RefundRequest.is_deleted == 0)
        .with_for_update()
        .first()
    )
```

  锁定读后：第二个并发事务阻塞在行锁上，拿到锁时读到 A 已提交的 processing →
  状态校验 `not in (APPROVED, FAILED)` 直接拒绝——防重生效。
