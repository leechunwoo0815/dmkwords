### HC-T1【高】BDD 门禁假绿：96.7% 场景被结构性跳过，资金域 BDD 从未执行

```text

```

`behave.ini:1-3`：`tags = ~@wip ~@future ~@draft`（全局过滤）；`features/` 34 个

withdrawal/transfer 全部在内），仅 audit/config/rbac/smoke 四个无 feature 级 @draft。
- **现象与根因**：gate step3 "behave 通过"的绿灯下 816/844 steps 被跳过；M0.5 的
  "230 个 Gherkin 场景"与实际执行 12 个之间是纯纸面覆盖。跳过是 tag 导致——
  **即使摘掉 tag，资金类 step 也会因无实现直接失败**（双保险锁死，见 HC-T2）。
  根因：behave.ini 全局过滤 + @draft 从未摘除 + steps 从未实现 + gate 无 skip 阈值。
- **修复方案**（解封流水线，按依赖顺序分四批）：
  1. **批 1（资金域先行）**：摘 refund.feature / deposit.feature / withdrawal.feature /
     transfer.feature / order.feature / payment.feature 六个文件的 @draft，
     同时实现 steps（可大量复用 tests/unit 的造数逻辑与既有步骤模式）。
     建议从 refund 开始（对应用户当前验收主战场 WM10）
  2. **批 2**：behavior 清库对齐（HC-T3——先做否则场景互相污染）
  3. **批 3**：其余 @draft 文件逐批解封（catalog/circulation/reading/growth/
     activity 的 feature）
  4. **批 4**：gate.sh 加阈值（HC-T5——最后做）
- **测试要求**：每解封一个 feature 跑 `python -m behave features/<x>.feature --no-capture -q`
  全绿才进下一批；全量 behave 场景数从 12 单调上升
- **验证等级**：C 级（测试基建 + gate）
- **施工顺序**：本包第一卡，但**从批 1 开始**（阈值是最后一步）
- **标注**：【事实】

### HC-T6【高】verify_architecture 只扫 router.py 不扫 miniapp_router.py：31 处宪法违规零发现

- **证据**【事实】：`scripts/verify_architecture.py:47-55`：

```text
def check_router_violations(errors: list[str]) -> None:
    for domain in DOMAINS:
        router = BACKEND / "domain" / domain / "router.py"   # 只查这一个文件名
```

grep 实测 5 个 miniapp_router.py 共 **31 处命中**：`db.query` 28 处（identity 8、
reading 12、billing 3、growth 2、activity 1）、`db.commit()` 1 处
（identity/miniapp_router.py:161 mark_notifications_read）、`try/except` 1 处
（reading/miniapp_router.py:53-55）。管理端 router.py 5 文件零违规（规则被执行了一半）。
- **现象与根因**：宪法 §三"Router 出现 db.query/add/commit、try/except = 违规"
  的机械执法（宪法铁律 2"规则必须可机械判定"）在 miniapp 侧落空。根因：门禁
  glob 未随 miniapp_router 文件命名演进。
- **修复方案**（分两步，陷阱 2）：
  1. **先下沉存量违规**：31 处按域分批挪 service——优先 identity 的
     `mark_notifications_read`（整段 ORM 写+commit 在 Router 层，挪 identity
     service 一个方法）与 reading 的鉴权 try/except（挪 guards/get_current_parent）；
     其余 `db.query` 渲染类逐批下沉
  2. **后扩 glob**：扫描对象改 `(BACKEND / "domain" / domain).glob("*router*.py")`。
     若一次清不完，glob 扩展时带豁免清单（含注释与截止批）——禁止静默豁免
- **测试要求**：扩 glob 后跑 verify_architecture 报出剩余违规数（与豁免清单一致）；
  下沉后违规数单调下降
- **验证等级**：C 级（门禁脚本 + 多域 router）
- **施工顺序**：先 1 后 2；reading/miniapp_router.py 442 行大文件下沉可拆多批
- **标注**：【事实】

### HC-T7【中】反假绿扫描脚本盲区：查不了宽断言/空真断言/skip 比例

- **证据**【事实】：`scripts/check_fake_assertions.py:21-29` 全部规则 = 只匹配
  整行 `assert True` / `assert False`。盲区清单：
  1. `assert True  # 任意注释` 即放行（制度化后门——脚本自述这是"前端交互步骤"
     的合法豁免）
  2. 查不了 `is not None` 型弱断言、空真断言、`status_code in (...)` 宽断言
  3. 查不了 BDD skip 比例（与 HC-T1 叠加：816 skipped 全绿时脚本照样 PASS）
  4. 无 AST 级恒真检查（`x == x`）
- **修复方案**（增强三处）：
  1. `assert True` 的注释豁免要求含关键词（issue 编号/"前端交互"）否则报
  2. 增加 BDD skip 比例检查（与 HC-T5 阈值同源）
  3. AST 恒真检查：`Compare(left=x, ops=[Eq], comparators=[x])`
- **测试要求**：构造一个带注释的 assert True 跑脚本应报（无关键词时）
- **验证等级**：C 级（门禁脚本）
- **标注**：【事实】

### HC-T8【中】无全局 500 兜底 handler：未捕获异常返回纯文本与统一 JSON 结构不一致

- **证据**【事实】：`backend/main.py:42` 仅注册 BusinessException handler；
  无 Exception 级 handler。Starlette 默认（非 debug）返回 `"Internal Server Error"`
  纯文本（无堆栈泄露——安全性合格；uvicorn 记录 traceback 到服务端日志）。
- **现象**：前端拿到的 500 是 text/plain 而非统一 `{detail}` JSON——client.ts 的
  错误分支对非 JSON 响应有兜底但显示质量降级；服务端日志无请求上下文关联。
- **修复方案**：补 Exception 兜底 handler（返回统一 JSON 500
  `"服务器开小差了，请稍后重试"` + logger.exception 带请求路径）。
- **测试要求**：构造必 500 端点（临时）断言响应是 JSON 含 detail
- **验证等级**：C 级（main.py 公共层）
- **标注**：【事实】（结构缺失）；前端行为【推断】
