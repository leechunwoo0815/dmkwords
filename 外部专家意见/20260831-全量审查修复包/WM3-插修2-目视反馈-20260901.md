## F6 client.ts FormData 污染 + \[object Object] 双修（基建级）

- **现象**：传凭证后点确认收款报错 `[object Object]`，凭证实际没传成。

- **证据（两个叠加 bug）**：

  1. `admin-web/src/api/client.ts:31`：`request()` 无条件设
     `Content-Type: application/json`——`apiUploadVoucher`（members.ts:121-123）走
     request 传 FormData，json Content-Type 覆盖浏览器自动生成的
     `multipart/form-data; boundary=...` → 后端 multipart 解析失败 422
  2. FastAPI 422 响应 `detail` 是**数组**（`[{loc, msg, type}]`）——
     client.ts `new ApiError(res.status, body.detail ?? ...)` 把数组当 message →
     Error 构造 String(数组) → `[object Object]`

- **修复**（两处都在 client.ts）：

  1. headers 组装时 `body instanceof FormData` 则不设 Content-Type（让浏览器自动加）
  2. detail 为数组时提取 `msg` 字段拼接（`Array.isArray(body.detail) ?
     body.detail.map((e) => e.msg ?? JSON.stringify(e)).join("; ") : body.detail`），
     兜底文案不变

- **影响面说明**：修 1 会影响所有走 request 的 FormData 调用——grep 确认现存量调用
  （members.ts apiUploadVoucher 等），封面/音频走的是 catalog.ts uploadWithProgress
  （XHR 独立通道）不受影响；简报附调用清单。

- **gate**：tsc。

## F7 孩子守卫口径细化：身份字段锁 / 学籍字段放【用户拍板口径变更】

- **现象**：已创建订单的孩子，英文名和年级无法修改（用户要求可改）。

- **用户口径**：身份字段（姓名/性别/生日）有订单禁改；**学籍动态字段
  （英文名/年级/AR）放开可改**——年级随学年变化、英文名/AR 是教学属性。

- **证据（现状全锁）**：`backend/domain/identity/service.py:222-224`
  update\_profile 入口 `has_orders → 409 一刀切`；前端编辑弹窗各字段
  `disabled={editChild?.has_orders}` 全锁。

- **修复**：

  - 后端 update\_profile：守卫细化——有订单时仅当请求含
    name/gender/birthday 任一非 None 才 409（409 message 指明"身份字段（姓名/性别/
    生日）已创建订单禁止修改，英文名/年级/AR 可改"）；english\_name/grade/ar\_level
    正常放行；AR 只升不降逻辑保留不变。删除守卫不变（有订单禁删）。

  - 前端编辑弹窗：name/gender/birthday 保持 `disabled={has_orders}`；
    english\_name/grade/ar\_level 移除 disabled；顶部警告文案改为
    "该孩子已创建订单：姓名/性别/生日锁定，英文名/年级/AR 仍可修改"

  - 家长守卫不变（家长有订单仍全锁——家长编辑的就是姓名/手机号身份字段）

- **红测试**（先红后绿，3 例）：

  1. 有订单孩子 PATCH 仅 grade → 200 落库
  2. 有订单孩子 PATCH 含 name → 409
  3. 有订单孩子 PATCH english\_name+ar\_level（升级值）→ 200

- **BDD**：既有 WM3-B1 feature 补场景（学籍字段可改）。

- **docs**：docs/03 FEAT-074 口径补充一行变更记录（勿动已定稿，增量追加）。

- **gate**：B（相关 pytest）。
