### R1【P0·#6】box 默认值反转回归：mirrorUrl 对称性修复

**根因链**：[Notifications.tsx:128](file:///Users/litianyu/cc-projects/dmkwords/admin-web/src/pages/Notifications.tsx) `box = searchParams.get("box") === "parent" ? "parent" : "admin"`（T20e 改）+ [L162](file:///Users/litianyu/cc-projects/dmkwords/admin-web/src/pages/Notifications.tsx) `if (next.box !== "parent") params.box = next.box`（旧默认 parent 时省略）→ 点家长 tab → URL 无 box → 读回 admin → 弹回管理待办 → "家长通知无法点击"。

### R2【P0·#1】活动单确认收款与"不联动报名"设计对齐

**根因**：[order_service.py](file:///Users/litianyu/cc-projects/dmkwords/backend/domain/identity/order_service.py) confirm_payment 的 TYPE_ACTIVITY 分支无条件调 `on_activity_order_paid`（无报名则 404）——管理端活动单（R3/FEAT-080）从不创建报名。

**修法（按订单来源分流）**：
```python
if order.order_type == Order.TYPE_ACTIVITY:
    from backend.domain.activity.models import ActivityEnrollment
    has_enrollment = (
        self.db.query(func.count(ActivityEnrollment.id))
        .filter(ActivityEnrollment.order_id == order.id, ActivityEnrollment.is_deleted == 0)
        .scalar()
    ) > 0
    if has_enrollment:
        # 家长端报名链路（报名→订单→收款→报名转正）
        ActivityService(self.db).on_activity_order_paid(order)
    # 管理端直建活动单（FEAT-080：线下收钱，无报名）→ 无联动，纯资金入账
```
注释注明设计边界（FEAT-080 §3.5.2：管理端活动单不联动报名）。

**红测试**：管理端创建活动单（R3 链路）→ confirm_payment → 200 PAID（当前 404 = RED）；家长端报名活动单 → confirm → 报名转 ENROLLED（回归）；免费/收费单各一。

### R3【#5 重设计】staff 待办"查看"的目标页与 403 风暴

**裁定（产品语义，专家提案用户可否决）**：**staff 点"查看"不再跳退款中心**——改跳通知中心管理待办（staff 已可见只读，T20g 已通）的**详情展开**（点击行展开完整内容+超管处理结果，不跨页）。理由：staff 无 audit.view 是 WM13 权限矩阵设计（资金审核域），给 staff 开退款中心只读=扩权限面；而"看到进展"在待办列表内即可满足（展开行显示 content + 已审结状态/处理人）。

**修法**：
1. 前端：staff 视角"查看"按钮 → 触发行展开（expandedRowKeys）而非 navigate；超管保持跳退款中心
2. **403 风暴根治**：退款中心页面加载的 6 个 API 若对 staff 全 403——本卡顺带在 RefundCenter 入口加权限门（`hasPermission(permissions, "audit.view")` 为 false → 渲染"无权访问"提示页，不发任何请求）——从源头杜绝 6 连 toast（即使未来有人直接输 URL）

**验证**：tsc + staff 目视（点查看 → 行展开见详情+处理结果，无 toast 风暴）。
