## 三、最重要的技术修正：E-00 与 B-16 是两个独立缺陷，不能互相替代

**外部专家原文**（B-16 修复提案）："所有 with_for_update 统一追加 populate_existing()；**或在 create_engine() 设置 isolation_level='READ COMMITTED'（一行修复，见 E-00）**"

**复核裁定：该"或"字选项不成立。** 机制分析：

| 缺陷 | 层次 | RC 是否修复 |
|---|---|---|
| E-00：锁后 COUNT/SUM 读 read view 旧快照 | MySQL 快照层 | ✅ 修复（RC 每语句新 read view，聚合查询读最新已提交） |
| B-16：with_for_update 命中 identity map 返回旧实例、属性不刷新 | SQLAlchemy ORM 层 | ❌ **不修复**（RC 下 SELECT FOR UPDATE 仍返回最新行，但 ORM 发现 identity map 已有对象即丢弃新行数据——这与隔离级别无关） |

**修复结论（投喂任务包必须分开写）**：
1. E-00 → `isolation_level="READ COMMITTED"`（1 行）+ 回归
2. B-16 → 12+ 处 `with_for_update` 逐点补 `.populate_existing()`（约 22 处无保护的锁定读）

**E-00 迁移 RC 的三个前置检查**（任务包必须含）：
- binlog_format 必须为 ROW（MySQL 8 默认；生产部署 checklist 项）
- gap lock 消失 → 排查"COUNT 防重 + INSERT"无唯一索引兜底的场景（B11 通知幂等有唯一索引 ✓；预约同书唯一、退款同订单唯一是否有索引兜底**待查**——无兜底者 RC 下有幻读竞态）
- C 级全量 gate 回归（315 基线只增不减）
