## R7【T6 补刀】管理端造单 → 报名待确认通知零发

**根因（活体实锤）**：T6 的通知发送逻辑只写在家长端 `ActivityService.enroll()` 内
（[activity/service.py:535](file:///Users/litianyu/cc-projects/dmkwords/backend/domain/activity/service.py)
`if order is not None` 分支）——而 **T2 新增的管理端造单链**在 `order_service.py`
里直接 `db.add(ActivityEnrollment(...))`，**不走 enroll()** → 通知零发。
专家活体：管理端造单+确认全链成功（order=paid/enrollment=enrolled），但
`admin.activity_enroll_manual` 通知 0 条、`activity_enroll_pending` 计数恒 0。

**语义裁定**：管理端造单**要发**这条通知吗？——**发**。理由：虽然造单的运营自己知道，
但通知是**协作感知层**：造单的馆员 A 和确认收款的馆员 B 可能不是同一人（staff 造单
staff 确认，或超管接手）；且通知的 mark_handled 闭环（确认收款→待办消失）对两链
同样需要。与退款申请双入口（家长端/超管代发起）均进待办是同一口径。

**修法（发送逻辑下沉为共享方法，双链调用）**：
1. 把 enroll() 内的 T6 发送段抽成 `ActivityService._notify_enroll_manual(child, activity, enrollment, fee)`（私有方法，含 dedup_key=enrollment_id 天然幂等）
2. enroll() 调用处替换为该方法
3. **order_service.py T2 造单段**（同生 enrollment 之后）：调
   `ActivityService(self.db)._notify_enroll_manual(child, a, e, a.fee)`——注意该处
   已 import ActivityService（T2 已引）；fee 直接用活动 fee
4. 免费活动管理端造单本来就不该存在（fee=0 的活动管理端造单无意义）——**造单入口
   前端已按 fee 过滤？** dev 核对：若前端活动下拉未过滤免费活动，顺带过滤（免费
   活动无收款单语义，家长端免费报名不发待办——管理端造免费单属误操作，后端可 422
   "免费活动无需创建订单，请走家长端报名"——**选后端 422 硬拦**，防呆优于前端过滤）

**红测试**：
1. 管理端造付费活动单 → `admin.activity_enroll_manual` 通知 1 条（当前 0 = RED）
   + `activity_enroll_pending` 计数 1
2. 确认收款 → 通知 mark_handled + 计数归零（mark_handled 钩子在 confirm 链已挂？
   核对——T6 声称"mark_handled 回写"但那也只在家长端链，管理端造单链同样要验）
3. 管理端造免费活动单 → 422
4. 家长端付费报名回归：通知仍正常发（抽方法不改行为）

**验证等级**：C 级（含 gate）+ 专家活体复验（造单→通知出现→确认→通知消失）。
