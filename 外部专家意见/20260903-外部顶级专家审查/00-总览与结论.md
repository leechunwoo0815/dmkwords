## 三、总体评价

### 做得好的方面（值得保留的设计）

1. **资金域行锁覆盖率高**：24 处 `with_for_update()` 覆盖绝大多数高频并发场景（P1-F1~F9 修复成果扎实）
2. **Decimal 纪律基本严格**：主体资金路径 Numeric(10,2)，零 float 入库（活动域 fee 字段有一处 float 违规见 B-8）
3. **审计日志完整**：`publish_audit` 覆盖所有状态变更，同事务提交，18 个文件使用
4. **alembic 迁移 100% 可逆**：17 个迁移全部有真实 downgrade()，CI 空库验证
5. **媒体鉴权规范**：无 StaticFiles 裸挂载，所有文件经 FileResponse + token 鉴权 + 路径穿越防护
6. **管理端 Router 干净**：8 个 `router.py` 零 try/except、零 HTTPException、零 db.query
7. **密钥隔离**：.env 从未入库，certs/ gitignored，无硬编码生产密钥
8. **CI 门禁完整**：MySQL 服务容器 + uv sync --frozen + alembic upgrade head + gate.sh 全量
9. **备份脚本工程质量高**：single-transaction、gzip 校验、30 天保留、防 .env 注入
10. **admin-web TypeScript strict**：零 `any`/`@ts-ignore`/`dangerouslySetInnerHTML`；openapi-typescript 工具链可用
11. **小程序封装完整**：wx.request 唯一调用点在 request.js，21 个 API 全走封装，401/403 分流正确

### 必须修复的系统性风险

1. **MySQL RR 隔离级别致锁+守卫模式整体失效**（E-00 + B-16）：`create_engine` 未设 `isolation_level`，默认 REPEATABLE READ 下 auth preload 建立 read view → 锁后 COUNT 守卫读旧快照 → P1-F1~F9 行锁批修被系统性架空。**一行修复**（`isolation_level="READ COMMITTED"`）可解决。
2. **退会流程存在死锁路径**（B-13）：结算退款单被 reject/cancel 后 withdrawal 永久卡 refunding，孩子永久 operation_locked，无出口。
3. **门禁覆盖率与宪法宣称严重不符**（A-1）：miniapp_router 占全部 HTTP 入口一半，处于执法真空；"Router 零违规"PASS 是假绿。
4. **资金操作存在旁路端点**（B-15）：`POST /orders/{id}/refund` 直接翻 Order 状态为 REFUNDED，绕过 RefundRequest 七态审核链、R-309 可退金额计算。
5. **活动域资金纪律全面缺失**（B-6/B-8/B-9, E-3/E-5）：cancel 可绕过退款、fee 用 float、退款不走 RefundRequest 台账、review_refund 无锁。
6. **前端 U10"禁假 0"系统性违规**（F-H4/F-M8~M13）：两端在列表 fetch 失败时普遍静默置空，渲染为合法空态或计数 0。项目专门开发了 error-view / loading-skeleton 组件但**从未接入任何页面**（F-M13）。
7. **运维就绪度低**（I-1~I-14）：Dockerfile 损坏、备份未调度、无限流、无 request-id、无外部告警——当前形态不可上线。
8. **安全基线薄弱**（C-1/C-2/C-4/C-5）：种子弱口令+无限流=接管级风险、家长 token 30 天无撤销、JWT 走 URL 全链路留痕。
9. **定时任务与用户操作竞态**（E-6/E-10/E-11/B-17）：cancel_timeout_orders、expire_due_members、overdue_list 全部使用快照读+无条件写，可与并发用户操作互覆。

## 七、结论

项目代码质量在**业务逻辑层面**达到较高水准——状态机设计合理、Decimal 纪律严格、审计日志完整、行锁覆盖率高。但本次深度审计（159 项发现）揭示了六个维度的系统性短板：

1. **MySQL 隔离级别系统性漏洞**（E-00 + B-16）：REPEATABLE READ 下"锁+COUNT 守卫"模式整体失效，P1-F1~F9 行锁批修被静默架空。**一行修复**（`isolation_level="READ COMMITTED"`）是本次审计最高 ROI 动作。
2. **退会流程死锁**（B-13）：结算退款单被拒后退会永久卡 refunding，孩子永久 locked，无出口恢复。
3. **资金操作旁路**（B-15 + B-6 + B-9）：三条路径可绕过 RefundRequest 七态审核链——直接翻 Order 状态、活动 cancel 不检查 fee、活动退款不创建 RefundRequest。
4. **门禁盲区**（A-1）：miniapp_router 处于执法真空，产出"零违规"假绿信号。
5. **前端 U10 系统性违规**（F-H4 + F-M13）：error-view 组件已开发但零接入，列表 fetch 失败普遍伪装为空态或计数 0。
6. **运维断裂**（I 域）：部署链路不存在、备份未常态化、限流未接线。

**当前形态适合继续开发，但不可直接上线。** 建议按 P0 → P1 → P2 顺序修复，预计 17-25 天工作量可达到上线基线。
