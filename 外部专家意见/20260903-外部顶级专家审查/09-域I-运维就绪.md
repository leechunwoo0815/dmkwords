# 域I 运维就绪审计

> 审计范围：部署清单、密钥管理、备份恢复、日志告警、健康检查、限流、CORS、静态文件
> 审计方法：全栈文件扫描 + 脚本验证 + 配置审查

## I-1 【阻断|事实】Dockerfile 已损坏——引用不存在的 requirements.txt

**可见性**：阻断（`docker build` 必然失败）

**证据**：
- `Dockerfile:7-8`：`COPY requirements.txt .` + `pip install -r requirements.txt`
- 项目根目录无 `requirements.txt`；依赖管理为 `pyproject.toml + uv.lock`
- `.github/workflows/ci.yml:10-12` 注释明确写"项目为 pyproject.toml + uv（无 requirements.txt）"
- Dockerfile 停留在 8 月 22 日，从未随依赖体系迁移更新

**修复提案**：改用 `COPY pyproject.toml uv.lock ./` + `uv sync --frozen --no-dev`（或多阶段构建）

**事实/推断**：事实

## I-2 【阻断|事实】docker-compose.yml 只有 MySQL，无 API/前端/nginx

**可见性**：阻断（ADR-001 承诺的生产部署形态实际不存在）

**证据**：
- `docker-compose.yml:4-25` 全部 services 仅 mysql 一项
- 无 api 服务、无 admin-web 服务、无 nginx/反代、无 TLS 配置
- 文件头注释自述用途即"开发环境：macOS 用 OrbStack"
- 小程序生产环境强制 HTTPS 域名，当前无任何落地路径

**修复提案**：新建 `docker-compose.prod.yml`，至少包含 api（depends_on mysql healthcheck）、nginx（TLS 终结 + admin-web 静态资源 + /api 反代）、mysql

**事实/推断**：事实

## I-3 【高|事实】限流中间件已实现但全库零接线

**可见性**：高（管理端/家长登录无限流，暴力破解无防护）

**证据**：
- `backend/middleware/rate_limit.py` 完整实现了内存字典限流
- 全库 grep 仅命中定义本身和 docstring 示例，无任何 `Depends(rate_limit(...))` 实际使用
- 管理员登录（`admin/router.py:42`）、家长登录均无限流、无失败锁定
- 即使接线：内存字典限流是进程级的（多 worker 各自计数），且永不清理空 key（缓慢内存增长）

**修复提案**：
1. 管理端登录接口加 `Depends(rate_limit(max_requests=5, window_seconds=300))`
2. 家长登录/注册接口加限流
3. 生产环境换 Redis 限流（代码注释已建议）

**事实/推断**：事实

## I-5 【高|推断】binlog 增量备份路径与容器化部署不匹配——PITR 实际失效

**可见性**：高（全量+binlog 的 PITR 承诺只有前半截成立）

**证据**：
- `scripts/backup_binlog.sh:45`：`MYSQL_DATA_DIR` 默认 `/opt/homebrew/var/mysql`（Homebrew 宿主路径）
- `docker-compose.yml:20`：MySQL 数据在容器卷 `mysql_data` 内
- 脚本从宿主 Homebrew 目录找 binlog，而真实数据库跑在 OrbStack 容器里 → for 循环静默空转，脚本仍以"备份完成"退出（exit 0）

**修复提案**：改为 `docker exec dmkwords-mysql mysqlbinlog` 流式导出；失败/零文件时非零退出

**事实/推断**：事实（路径不匹配）+ 推断（静默失效）
