### T20a【P0·9a】活动发布 500：aware/naive datetime 撞车

**根因**：前端 antd DatePicker `toISOString()` → `"2026-09-20T15:00:00.000Z"`（带 Z 后缀）→ Pydantic 解析为 aware datetime → 与 naive `datetime.now()` 比较 → TypeError。

**修法（后端统一规约，不逐点打补丁）**：
```python
# activity/schemas.py 或 router 层（推荐 schema 字段 validator）：
from pydantic import field_validator
@field_validator("start_at", "enroll_deadline", mode="after")
@classmethod
def _strip_tz(cls, v: datetime | None):
    """T20a：前端 toISOString 发 aware 时间，服务端全 naive——统一剥时区（本地时区语义）"""
    if v is not None and v.tzinfo is not None:
        return v.astimezone().replace(tzinfo=None)  # 转本地时区后剥 tzinfo
    return v
```
**同族 sweep（完整性枚举）**：全库 rg `toISOString` 找出**所有**发 aware 时间的前端调用点（ActivityManage start_at/enroll_deadline 已知；其他页面逐一核对）；后端 rg 接收 datetime 的 schema 是否有同款比较风险——命中清单进简报，**凡前端发 toISOString 的字段，对应 schema 全部补 validator**（一次收口这个族）。

**红测试**：`start_at="2026-09-20T15:00:00.000Z"` 创建活动 → 200 published（当前 500 = RED）；enroll_deadline 同款；naive 字符串回归不受影响。

**验证等级**：C 级。
