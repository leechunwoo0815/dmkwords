### G-01 【低|事实】无断言测试

`tests/unit/test_wm6_login_guard.py:70-82` `test_validate_production_passes_when_empty` 无任何断言，语义是"不抛异常即通过"。属可接受的负控模式，但若 `validate_production` 未来改为返回 bool 而非 raise，测试将静默失去意义。

### G-02 【低|事实】反假绿门禁可被绕过

`scripts/check_fake_assertions.py:21-29` 只做行级文本匹配：`assert True  # 任意注释` 即可绕过。当前套件经 AST 扫描无实际绕过者，但该门禁对未来退化无防御力。

### G-03 【低|事实】弱断言族

`test_wm1_audit.py:39-40` 与 `features/steps/wm1_steps.py:231-232` 用 `status_code in (404, 405)` 验证"审计日志无写端点"——若整个 audit-logs 路由挂掉返回 404 也照样绿。建议加一条正向锚（如 GET 200）防路由整体消失时的假绿。

### G-04 【低|事实】测试辅助函数静默失败

`test_wm10_transfer_refund.py:28-35` `_pay()`、`test_wm4_deposit.py:12-26` `_paid_child()`、`tests/unit/helpers.py:7-18` `force_book_on()` 中的关键写操作不断言响应码。下游断言通常会连带失败，但会污染失败定位。

### G-09 【中|事实】比例退款公式无精确金额锚定

**修复提案**：补一条：paid_at 回拨 100 天 → 断言 `refundable == round(paid × 265/365, 2)` 精确值。

## 五、测试隔离

### G-12 【中|事实】文件系统副作用零清理

DB 每测试 TRUNCATE，但上传文件写入真实 `uploads/`（`config.py:53`）且从不清理——当前已积累 **311MB / 约 4136 个孤儿文件**（book_audio 2094、cover 1638、observation 177、reports 159、voucher 68）。DB 行已截断而文件永久残留。

`test_wm3_voucher.py:51` 甚至声明了 `tmp_path` fixture 却未使用。

**影响**：磁盘无限增长、文件删除断言依赖真实目录状态、备份/迁移脚本可能把测试垃圾当生产资产。

**修复提案**：测试环境 `UPLOADS_DIR` 指向 tmp 或 conftest 清理。

### G-13 【低|事实】BDD 清理表清单与 conftest 不对齐

`features/environment.py:12-25` `BDD_BIZ_TABLES` 仅 13 表，conftest 为 36 表；缺 refund_requests / withdrawal_requests / transfer_requests / point_ledgers / books / book_copies / activities / notifications 等 23 表。当前活跃 BDD 不写这些表故无症状，但"横切批"解封资金类 feature 时将踩跨场景残留坑。

**DB 隔离**【事实，合格】：`conftest.py:57-75` autouse 前置 TRUNCATE 36 表 + 重播种 + 缓存失效 → 测试间无顺序依赖。
