## 施工顺序：T1 → T2 → T3 → T4 → T5 → T6

### T1【#1·计数同源第 6 案】家长通知 tab 胶囊在 admin 视角下恒 0

**根因**：胶囊绑 `unreadCount` state，该 state 仅 box=parent 时由 loadParent 填充
（[Notifications.tsx:221](file:///Users/litianyu/cc-projects/dmkwords/admin-web/src/pages/Notifications.tsx) `if (box === "admin") void loadInbox(); else void loadParent();`）——默认落 admin → loadParent 不跑 → 胶囊 0（S1 修了显示层没修数据源触发，第 6 案）。

**修法**：mount 时无条件拉一次家长未读数——后端 todo-counts 响应补
`parent_unread` 字段（NotifyAdminService 一条 COUNT，轻量）→ useTodoCounts 透出 →
tab 胶囊改用该全局数（loadParent 拉到后本地覆盖，双源同值）。**从此胶囊数与视角无关**。

**红测试**：todo-counts 响应含 parent_unread（当前无 = RED）；admin 视角下胶囊显示真实未读。

### T2【#2·设计缺陷】管理端活动单必须自动关联报名

**用户裁定（原文）**："线下门店收活动费，创建订单后无论支付与否，都应该自动关联到活动报名"——推翻插修 11 R2 的"无报名则跳过联动"修法。

**修法（管理端活动单 = 报名代客创建）**：
1. R3 创建链（OrderService admin create TYPE_ACTIVITY）补一步：选活动后**同步创建
   ActivityEnrollment**（child_id=订单孩子、activity_id、status=PENDING_PAYMENT、
   生成 ticket_code、占用名额）——管理端造单即占位，与家长端报名殊途同归
2. confirm_payment 的 on_activity_order_paid 联动恢复全量适用（有报名可转正）——
   插修 11 R2 的"无报名跳过"分支保留（防御历史数据），但新单不再走空分支
3. 取消订单（cancel）联动 cancel_enrollment_by_order（已有）释放名额
4. **名额校验前置**：管理端创建活动单时也查满员（当前只查活动存在性）——满员 422

**红测试**：管理端创建活动单 → enrollment 同生（PENDING_PAYMENT + 名额 -1）；确认
收款 → ENROLLED；取消 → 名额回补；满员 → 422。

### T4【#4·枚举错配老毛病】detail 页 wx:else 裸输出英文状态

**根因**：[activity-detail.wxml](file:///Users/litianyu/cc-projects/dmkwords/miniapp/pages/activity-pkg/activity-detail/activity-detail.wxml) 按钮 wx:elif 链只枚举了 enrolled/pending_payment/checked_in——refund_pending 落 `wx:else` 兜底 `状态：{{status}}` 裸输出英文。

**修法**：wx:else 兜底改为**中文映射**（refund_pending→"退款待审中"/refunded→"已退款，
可重新报名"/cancelled→"已取消"）——与 STATUS_TEXT 表对齐；**同族 sweep**：全 miniapp
rg `\{\{.*\.status\}\}` 裸输出点逐一核对有映射（activity-list 已对齐 ✓，其他页面列清单）。

**验证**：真机目视（退款待审中状态显示中文"退款待审中"）。

### T5【#5·UX】取消报名/申请退款双按钮二选一

**根因**：付费活动给两个按钮——取消报名点了弹"请走申请退款"（不执行），申请退款才
是真路径。免费活动反之（取消可用、无退款按钮）。

**修法（按 fee 二分，一屏一主操作）**：
- 付费：只留"申请退款"（按钮文案"取消报名并申请退款"——用户语义原话），refund_pending
  态显示"退款审核中"disabled
- 免费：只留"取消报名"（现状逻辑）
- 后端不变（免费 cancel / 付费 refund 链已有）

**验证**：真机目视（付费活动单按钮、免费单按钮）。

### T6【#6】活动报名进管理待办通知

**根因**：报名成功只发家长通知（SCENE_ACTIVITY_ENROLL→NotificationService）——管理端零感知。按 WM13 六场景模式，**待人工确认收款的报名**（PENDING_PAYMENT）才是待办（已付 ENROLLED 无需处理）。

**修法**：
1. AdminNotification 新场景 `admin.activity_enroll_manual`：报名创建且活动
   fee>0（待收款确认）→ send 管理待办（title"【活动报名待确认】"，content 含
   家长·孩子·活动·金额，ref_type="activity"，ref_id=enrollment_id，跳转活动页）
   ——免费报名不发（无需运营动作）
2. AdminNotifyService 场景表 + WM13 权限矩阵（member.manage 可见——收款确认属
   会员管理域）+ todo-counts 计入（活动域新计数：activity_enroll_pending，进
   admin_total？——**不进**：admin_total 是审核五类口径，活动报名待确认单独字段
   `activity_enroll_pending`，侧边栏活动中心徽标用它，避免污染既有口径）
3. 确认收款后 mark_handled 回写（L2 模式幂等）+ 家长收到确认通知（notify 链已有？核
   对——报名转正时给家长发"报名确认+入场券码"通知，若已有复用）

**红测试**：付费报名 → 管理待办出现该场景通知 + activity_enroll_pending=1；确认收款 →
通知 mark_handled + 计数归零；免费报名 → 无通知；staff（member.manage）可见。
