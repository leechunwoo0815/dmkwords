## 一、HIGH（4 项）

### H-1 【高|事实】退款执行前缺少 R-310 六项复核

**文档**：R-310 要求"退款执行成功前复核 6 项（无借阅中/无逾期/无未处理遗失/无未处理损坏/无待结清赔偿/无进行中转让）"；校验失败 → 退款不能执行，保持 approved。

**代码**：`backend/domain/identity/wm10_service.py:365-480`（`RefundService.execute`）直接 approved/failed→processing→refunded/failed，**无任何复核**。复核只在退会 `review` approve 时跑 `_preconditions`，且 execute 时刻与 review 时刻之间状态可再变化（如新借书）。

**后果**：review approve 时孩子无逾期 → 家长在 approved→execute 窗口又借了一本书 → execute 不检查直接退款 → 孩子带着未还图书进入退会流程。

**修复提案**：execute 在 `processing` 前重跑 `_preconditions`（复用 `wm10_withdrawal_service.py:37-107`），锁内执行。

**交叉引用**：域 B 报告 B-1 补充了结算退款单被 reject/cancel 后无出口的阻断级问题。

**事实/推断**：事实

---

### H-2 【高|事实】"未处理遗失/未处理损坏"未作为独立校验项

**文档**：R-310/R-311（退会 7 项前置）与 R-302（转让条件）均将遗失、损坏单列。

**代码**：
- `wm10_withdrawal_service.py:37-107` `_preconditions`：只查借阅中/逾期/`deposit.unpaid_balance>0`/进行中转让/会员费退款
- `transfer_service.py:35-141` `check_conditions`：同样只查 unpaid_balance

**后果链**【推断】：遗失书尚未定损时 `unpaid_balance=0` → 退会/转让放行 → 押金已退（Deposit 状态 REFUNDED）→ 之后 `billing/service.py:172-219` `deduct_for_compensation` 拒绝对 REFUNDED 押金扣款 → 赔偿无法落地。

**修复提案**：`_preconditions` 和 `check_conditions` 增加 `BorrowRecord.status IN (STATUS_LOST, STATUS_DAMAGED)` 独立检查项。

**事实/推断**：代码事实；后果链推断

### H-3 【高|事实】退会审批崩溃缺陷（UnboundLocalError）

**证据**：`backend/domain/identity/wm10_withdrawal_service.py:375`：

```python
"deposit_amount": str(dep.available_amount) if dep else "0"
```

但 `dep` 仅在 L356 循环内 deposit 分支赋值。当结算清单不含押金项（观察期会员从未缴押金——PRD §3.2 明确允许押金后缴）时，管理员 approve 直接抛 `UnboundLocalError`，流程卡死。

**复现**：① 创建观察期孩子（未缴押金）；② 发起退会；③ 管理员 approve → 500 Internal Server Error。

**修复提案**：在循环前初始化 `dep = None`（一行修复）。

**事实/推断**：事实（可直接复现）

### H-4 【高|事实】通用退款入口绕过 R-309 活动硬校验（双路径）

**文档**：
- R-309：活动费退款"已签到不可申请/开始前 2h 关闭线上/已开始只能线下"
- R-300-6：线上自助操作必须硬校验，不得靠人工兜底
- R-321：已参加/签到不恢复 99 元资格

**代码**：
- `identity/miniapp_router.py:184-189`：家长可对**任意已支付订单**调 `RefundService.apply`
- `wm10_service.py:108-126` `_paid_order`：只拦押金类，**TYPE_ACTIVITY/TYPE_FIRST_ACTIVITY 畅通**，`_refundable_amount` 全额退，无签到/2h/已开始任何检查；L105-106 规则文案自认"审核时核对"（人工兜底）
- `activity/service.py:616-632`：自带另一条 `apply_refund`（矩阵正确），形成两条并行退款路径

**后果**：家长可通过通用退款入口绕过活动域的正确矩阵，退已签到的活动费 + 恢复 99 元资格。同时两条路径的 dup 检查互不感知，存在双重申请窗口。

**修复提案**：
1. `RefundService._paid_order` 增加 `order.order_type == TYPE_ACTIVITY` 拦截，引导至活动域退款
2. 或删除 `activity/service.py` 的独立退款路径，统一走 RefundRequest 但补硬校验

**交叉引用**：域 B 报告 B-3（`POST /orders/{id}/refund` 绕过退款链）、域 E 报告 E-32（活动签到/退款互覆）

**事实/推断**：事实

## 四、INFERENCE 类（3 项）

### I-1 【推断】早续费退款少算

`wm10_service.py:93-96` `_days_used=(now−paid_at).days`，续费单到期日=原到期日+365（前续），但已用天数从付款日起算，原到期日前的间隔天数被计入"已用"，退款偏低。需产品确认口径。

### I-2 【推断】押金补缴回冲 deducted_amount 与 R-312 存在张力

`billing/service.py:74-86` 回冲 `deducted_amount -= order.amount`；R-312 称"deducted 保留历史扣减记录"。补缴公式 `deposit_amount − available_amount` 本身与 R-312 一致。文档语义歧义。

### I-3 【推断】押金再缴路径不一致

`create_deposit_order` 仅拦 `status==PAID`，`partially/fully_deducted` 状态可再次缴押金，confirm 后 available 重置为标准额但 unpaid_balance 不清零——存在不一致状态路径。
