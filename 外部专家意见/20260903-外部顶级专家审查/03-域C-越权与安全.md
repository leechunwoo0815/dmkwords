## C-1 【高|事实】种子账号弱口令入库且无强制改密——生产接管级风险

**可见性**：高（配合 C-2 限流未接线，任何知道仓库内容的人可直接登录超管）

**证据**：
- `backend/seeds/seed_admin.py:16,22`
```python
# admin/dmkwords123 超管、staff01/dmkwords123
```
- 口令硬编码在仓库，幂等 seed 不会重置已存在账号
- 登录无首登强制改密
- 无 C-2 限流兜底（限流中间件全库零接线，见 I-3）
- 叠加效果：生产跑过 seed 后，任何知道仓库内容的人直接 `admin/dmkwords123` 登录 → 超管全权限（含退款审核/执行、员工管理）

**根因**：seed 脚本仅为开发环境初始化，未考虑生产泄露场景

**修复提案**：
1. seed 脚本生成随机口令并打印到 stdout（仅首次）
2. 或：首次登录强制改密
3. 配合 C-2 限流接线

**红测**：用 `admin/dmkwords123` 登录生产环境 → 观察是否成功

**门禁级别**：集成测试

**依赖**：与 I-3（限流零接线）联合修复

**事实/推断**：事实（代码可验证）

## C-3 【中|事实】`/transfers/conditions` IDOR——任意 child_id 的会员/资金状态泄露

**可见性**：中（信息泄露，可枚举全馆孩子的会员与欠款状态）

**证据**：
- `backend/domain/identity/miniapp_router.py:257-266`
- `transfer_service.py:186-190`（`_child` 无 parent 过滤）
- 家长 A 传入家长 B 的 child_id，`check_conditions` 逐项返回布尔结果：「转出方是正式会员」「会员剩余时间>0」「无未结清赔偿款」「没有进行中的申请」等 12 项
- 等于任意孩子的会员/押金/流程状态探针
- 对比：`apply` 路径有归属校验（`transfer_service.py:148`），仅此查询端点漏

**根因**：conditions 查询是只读操作，开发者未加归属校验

**修复提案**：
```python
# _child 方法加 parent_id 过滤
def _child(self, child_id, parent_id=None):
    q = self.db.query(Child).filter(Child.id == child_id, Child.is_deleted == 0)
    if parent_id:
        q = q.filter(Child.parent_id == parent_id)
    return q.first()
```

**红测**：`GET /api/miniapp/transfers/conditions?source_child_id=<其他家长的child_id>&target_child_id=<同>` → 观察是否返回 12 项布尔结果

**门禁级别**：Service 单测

**依赖**：无

**事实/推断**：事实（代码可验证）

## C-4 【中|事实】家长 token 30 天长效且无任何撤销机制

**可见性**：中（泄露后 30 天内不可失效）

**证据**：
- `backend/domain/reading/miniapp_router.py:34-45`（exp=30d，无 `gen`/`jti`）
- `:48-65`（校验只查 `is_deleted`）
- admin token 有 8h 过期 + token_generation 撤销，家长 token 无对等机制
- 泄露后 30 天内不可失效：改手机号/门店纠纷停用均无法吊销（除非软删家长，会同时锁死本人）

**根因**：家长端追求"免登录"体验，牺牲了 token 生命周期管理

**修复提案**：
1. 家长 token 缩至 7 天
2. 增加 token_generation 字段（同 admin 机制）
3. 关键操作（退款/转让申请）要求重新登录

**红测**：抓包取得 token → 家长挂失后仍可用 30 天访问其孩子全部数据

**门禁级别**：集成测试

**依赖**：无

**事实/推断**：事实（代码可验证）

## C-5 【中|事实】JWT 走 URL query 全链路留痕——日志泄露=账号泄露

**可见性**：中（token 进 Nginx access log、CDN/代理日志、浏览器历史、微信转发链接）

**证据**：
- miniapp：`reading/miniapp_router.py:247,267,286-298`、`growth/miniapp_router.py:102`
- admin：`catalog/router.py:92,105,344`、`identity/router.py:293`
- 媒体端点接受 `?token=<完整30天/8h JWT>`
- 该 token 与 API token 同权（非降权的短时媒体票），日志泄露=账号泄露
- 代码注释承认 `<img>`/`<audio>` 无法带头，但未做任何缓解

**根因**：HTML 组件（img/audio）无法携带 Authorization 头

**修复提案**：
1. 媒体 token 独立：短时（5 分钟）、降权（只能访问特定文件）
2. 或：媒体端点走 cookie（SameSite=Strict）

**红测**：家长把带 `?token=` 的音频链接转发到微信群 → 群内任何人拿 token 直接调 `/api/miniapp/orders` 等全部 API

**门禁级别**：集成测试

**依赖**：与 C-4 关联（token 生命周期）

**事实/推断**：事实（代码可验证）

## C-13 【低|事实】音频上传仅验后缀 .mp3，无 MIME/magic bytes 校验

**可见性**：低（有 `_mp3_duration` 二次兜底，非 MP3 数据解析时长为 0 会被拒绝）

**证据**：
- `backend/domain/catalog/service.py:415-416`：
```python
if not filename.lower().endswith(".mp3"):
    raise ValidationError("音频仅支持 MP3 格式")
```
- 仅检查文件名后缀，不检查 MIME type 或文件头 magic bytes
- 二次兜底：`common/file_storage.py:143-147`（`_mp3_duration(data)` 解析时长，为 0 则拒绝）
- 但 `_mp3_duration` 非安全校验——构造的 polyglot 文件可能通过时长解析

**修复提案**：增加 `file.content_type == "audio/mpeg"` 校验；或用 `python-magic` 检查文件头。

**门禁级别**：Router 单测

**事实/推断**：事实
